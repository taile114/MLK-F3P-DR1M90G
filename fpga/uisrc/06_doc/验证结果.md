`tb_timebase` 在真实 100 MHz 时钟下完成 800017 拍逐拍参考模型核对，覆盖 1 ms tick 周期、32 bit 计数与回绕、错相 / 同拍 valid 时间戳、最新值帧锁存、帧间保持、使能与复位。AXI 测试核对 `0x54～0x74` 读回、signed16 符号扩展、RO 写拒绝、跨 tick 背压保持与首尾帧号检测；通道时间戳随帧保持。波形为 `uisrc/out/sim/tb_timebase.vcd`，全量日志为 `uisrc/out/sim/regression.log`。

`tb_sensor_dma` 包含共享 HP1 的长背压边界：AW 受阻时 STOP / ABORT 保持已发出的地址与长度，ABORT 后用已缓冲样本排空当前突发，W 受阻时保持数据；释放背压后事务完整结束，STOP 不再发第二个突发，ABORT 收尾后可重新启动。`tb_npu_hp1_write_mux` 覆盖两个并发写来源、轮转、16 拍突发、6 bit ID、AW/W/B 背压、SLVERR 与复位。统一入口共执行 35 组测试平台配置，全部通过。

`tb_fpga_top` 在采集器输出处注入数据，覆盖三路时间戳、对齐帧、四路特征与本地快照；传感器总线协议由原有独立 TB 覆盖。该测试不替代板级采样精度与 PS 连通验证。

`tb_encoder_top` 直接例化统一 `fpga_top`，通过独立 UART 从机 BFM 完成 FC06 初始化、FC03 采集、CRC 错误及恢复，解码实际 J16 遥测，核对快照、正负 rpm 与原有 LED2 / LED3 / LED4 含义；测试中其他传感器状态由注入提供，不能替代实板四路联测。

`tb_spectrum_window` 覆盖 §4.6 频谱窗口：`0x400+4k` 解码、整窗推送完成才置快照有效位并给出完成脉冲（完成拍索引必为最后一个 bin）、推送过程中读取等待（`ARREADY` 拉低后重取）、结果字与快照同拍发布、推送途中软复位（窗口立即读 0，在途尾字不回填，下一窗自恢复）、每窗恰好一次完成脉冲，`BIN_POWER=(|X|²)>>8` 的定标边界（`|X|²` 接近 2^40 保留高位、0x100 读出 1、`0xFFFFFFFF00` 读出 `0xFFFF_FFFF`、高于 39 位的原始位丢弃），以及 N=256 与 N=512 两种容量；含 4 个变异用例（完成提前、完成早一字、复位不清开窗标志、少推一字），均判 FAIL。

该窗口的 bin RAM 读写口必须同域：采集域整窗结束后逐字读出，经 push/ack 单 bit 翻转沿与随沿稳定的数据、索引总线推到寄存器域写快照。跨时钟访问同一数组时，综合工具可能实现成读写分离的存储而读回恒 0，仿真里两个域访问同一数组看不出差异（实板曾因此读全 0）。

`tb_board_test` 覆盖板测顶层的判定链路：常数、斜坡、单音、方波四组固定向量分别驱动四路时域块与 FFT，按解析期望值与容差逐项比较，并检查 LED 三态（运行 / 全通过 / 失败快闪）与故障注入分支。

`fpga_top` 不含 CWC 或诊断探针；时基 / 对齐帧与特征没有对外读出通路，相关逻辑可能被优化，该行资源与时序不能用于核验这些功能。独立工程保留四路时域、256/512 FFT、完整 AXI / P2F / 特征快照及可观察的 `X_regs/X_timebase`，用于新增数据通路的资源与时序判定。

板测工程 `board_test_top` 只约束系统时钟与四只 LED，STA 覆盖率 100.00%，`check_timing` 无缺失时钟与无效约束，码流为 `uisrc/out/board_test/board_test.bit`。

TD 把 `initial` 数组与 `case` 两种写法的只读表都推断为 ERAM，并把初值写进码流：对同一工程的 ROM 内容做单 bit 变更后重新生成码流，四个变体（初始形式 / 初始形式改值 / `case` 形式 / `case` 形式改值）的码流互不相同，因此 `HDL-5314 WARNING: net ... does not have a driver` 不影响初值，FFT 系数表沿用 `initial` 写法。

`fpga_top` STA 覆盖率 100.00%，`check_timing` 的 no_clock、invalid_constraint、combinational_loop、no_path 均为 0；6 个输入 / 12 个输出仍无外部 I/O delay。基础外设与串口输出使用 10 ns 片内布线预算，RS485 RX 仅豁免引脚至首级同步寄存器，不能据此声明板级建立 / 保持验证完成。`build_td.tcl` 同时检查覆盖率和非负 SWNS/HWNS。厂商 I2C 已改为单时钟使能，不再存在未约束的 `scl_clk`。SoC 候选工程的构建结果单独列在 §3.1，不能与 `fpga_top` 混用。

复现：按 [`README.md`](README.md) 的 TD headless 命令分别运行 `build_td.tcl`、`build_validation.tcl`。时序和资源文件为 `uisrc/out/td/route_timing_summary.rpt` / `route.area`、`uisrc/out/validation/route_timing_summary.rpt` / `route.area`。构建脚本要求报告包含 100 MHz `sys_clk` 且 SWNS/HWNS 非负；`build_td.tcl` 另要求 STA coverage 100%；`build_soc.tcl` 另要求 `check_timing` 的 no_clock、invalid_constraint、combinational_loop 均为 0，STA coverage 作为报告值记录而不设门槛（残差来源与复现见 [`../../../docs/PL-PS接入与上板交付.md`](../../../docs/PL-PS接入与上板交付.md) §2.2）。构建日志为 `uisrc/out/td/build.log` 与 `uisrc/out/validation/build.log`，独立工程不下载。

环形缓冲实板结论：采样流 16 块连续搬运，`jumps=0`、`lost=0`、`elapsed=873.3 ms`，块周期 54.58 ms，数据正确；`--ring --test` 的 ramp 自测在环形绕圈快于 PS 读取时会出现校验不通过（块在读取期间被覆盖），该现象属测试方法限制，不代表搬运错误。块完成中断不可用：驱动 `f2p_irq[3]` 时 `DMA_IRQ[16]` 持续为 1 而 GIC 计数恒为 0；改驱动 `f2p_irq[0]` 后唤醒的是厂商 VDMA 驱动，因其无法清除中断被内核判为 spurious 并禁用该线。厂商设备树只声明 SPI 82/83 且都属 VDMA，SDK 例程只有 `PL_IRQ_NUM0/1`。块完成通知按 `DMA_BLK_SEQ` 轮询实现。

数据源无数据时的总线行为：模块先攒满当前突发的全部拍数再拉高 `AWVALID`，`AW` 握手时 W 数据已就绪，不会出现「AW 已握手、W 等采样」而长期占用 HP1 的情况；数据源无数据时停在采集侧等待，不发起任何 AXI 事务。`tb_sensor_dma` 覆盖该用例：外部流为空的 200 个周期内 `AWVALID` / `WVALID` 保持低、未产生 AXI 事务，`I_stop` 直接回到 `IDLE` 且不置 `DONE` / `ERRCODE`。

### 5.2 完整频谱窗口（实板）

码流 `soc_hdmi.bit` 含 §4.6 频谱窗口。窗口字为 `BIN_POWER[k]=(|X_k|²)>>8`；`|X|²` 最大约 2^39（ADXL345 ±16 g、256 LSB/g），`>>8` 后约 2^31，unsigned32 不溢出。bin RAM 的读写口同在采集时钟域：整窗结束后逐字读出，经 push/ack 单 bit 翻转沿握手推到寄存器域写快照，AXI 只读快照；同一数组不得跨两个时钟域读写（综合可能实现成读写分离的存储，仿真无差异而实板读回恒 0）。

验收命令与要点：

```bash
plctl spectrum --top 8          # 默认按 3200 Hz 折算频率，bin 间隔 12.5 Hz
plctl features | head -8        # 与 FFT_PEAK_BIN / FFT_PEAK_POWER 对照
```

| 检查 | 期望 |
|---|---|
| `sequence` | 每次读取递增；读取期间被新窗覆盖时重读 |
| 触发峰值 | `BIN_POWER[peak_bin]` 与 `FFT_PEAK_POWER >> 8` 一致 |
| 单音频点 | 能量集中在一个 bin，相邻 bin 显著更低 |
| 反例 | 全 0 说明快照未推送；`ERRCODE` / 序列不变说明 FFT 未推进 |

实板读数（v1.0 码流，`BIN_POWER=(|X|²)>>16`，加载后未重烧 SD）：晃动传感器期间逐窗读取，峰值 bin 的窗口字与 `FFT_PEAK_POWER` 对齐。

| `FFT_PEAK_POWER`（Q16） | `FFT_PEAK_BIN` | `BIN_POWER[peak_bin]` |
|---|---|---|
| 480.7264 | 1 | 480 |
| 159.0810 | 1 | 159 |
| 73.5757 | 1 | 73 |
| 41.5416 | 1 | 41 |

`480 << 16 = 480.7264 × 65536`，窗口字是 `FFT_PEAK_POWER` 的整数部分，说明整窗推送、快照写口与 AXI 读出三段一致。bin 1 与 bin 255 读数相同，属实信号正负频率镜像的预期行为；峰值 bin 在静止噪声中跳动、晃动时固定在低频，与频谱形状一致。静止时该定标下窗口字全 0（`peak_power` 仅 0.03～0.09，整数部分为 0），改为 `>>8` 后同一噪声底约读出 8，需在 v1.1 码流复测确认。

首版本（跨时钟读写同一 bin RAM）在实板整窗读 0，峰值寄存器正常：读写分离的存储实现只在综合后出现，仿真无法复现；现结构为同域读出后经 push/ack 翻转握手推送，实板读数与峰值一致。

### 5.3 板测顶层（实板）

板测码流 `board_test.bit` 已随 rootfs 放到 `/lib/firmware/`。该内核的 `fpga_manager` 只有 `name` / `state` / `status` 三个属性，没有 `firmware` 属性，用 device tree overlay 指定 `firmware-name`，由 `of-fpga-region` 从 `/lib/firmware/` 取码流：

```bash
# 主机
nix shell nixpkgs#dtc -c bash platform/flash/load_bit.sh board_test.bit --out /tmp/lb
# 板卡（dtbo 经串口 base64 或 scp 送入）

mkdir -p /sys/kernel/config/device-tree/overlays/pl
cat /tmp/lb/board_test.bit.dtbo > /sys/kernel/config/device-tree/overlays/pl/dtbo
cat /sys/class/fpga_manager/fpga0/state     # 期望 operating
dmesg | tail -3                             # 期望 fpga prog successfully
```

LED 语义：`O_led[3]`（M20）为 done，`O_led[2]`（J15）为特征通过，`O_led[1]`（R19）为 FFT 通过，`O_led[0]`（T19）为状态（运行中慢闪 / 全通过常亮 / 失败快闪）。

实板结果：加载后四只测试 LED 常亮，`O_led[3:0]=4'b1111`，与仿真结论（四组固定向量在容差内、LED 三态与故障注入符合预期）一致。该验收只观察 LED，不读取测试内部中间量；板测顶层不含 AXI 出口。

恢复显示码流：重启，由 FSBL 重新加载 `BOOT.bin` 内的码流；overlay 生效后 `firmware-name` 会残留在 `/soc/base_fpga_region`（内核日志 `memory leak will occur if overlay removed`），不在同一 devicetree 上叠加第二个码流 overlay。

### 5.6 合并镜像：HDMI / 采集 DMA / FF6 混合推理

测试使用 §3.2 / §3.3 的配套 BOOT、内核、设备树与 rootfs。板端固件摘要为 `88733d39eeed32b703dd5b0aad98b3c63a52024b3fe548cb887c8d88deef2657`，与构建产物一致。原始逐窗结果见 [CSV](../../../npu/results/board/combined-soc-ff6-hybrid.csv)，机器可读摘要见 [JSON](../../../npu/results/board/combined-soc-ff6-hybrid.json)。

| 验证项 | 实测结果 |
|---|---|
| 自动启动 | 主机对时服务运行时，板卡 `reboot` 后自动进入 Linux；服务完成登录和对时，epoch 差为 0 s |
| 内核 / 设备 | `6.1.111-rt42`；`/dev/hard_npu`、`/dev/soft_npu`、`/dev/cma_mem`、`/dev/pl_ctrl`、`/dev/fb0` 均存在，软核 probe 成功 |
| PL / 采集 | `ID=0x504c0102`；温度、三轴和计数更新，`faults=0`；转速 `online=true`、`configured=true`、`err_count=0` |
| HDMI / LED | framebuffer 为 `1920,1080`，本地看板和 LED5 已确认恢复 |
| Qt 并行运行 | 看板运行期间 `DMA_CTRL=0x00000108`（RING / BUSY），`DMA_BASE=0x3ef00000`；硬 NPU 中断计数持续增长，观察值 20776；软核计数为 0 |
| 独立混合回放 | 停止 Qt 后执行 `check_engine ... hybrid 2`，退出码 0；两轮各 184 窗，共 368 窗，重复加载的预测逐窗一致 |

FF6 的六个量化分支在硬核执行，软核驱动成功初始化是厂商运行时的前提；本测试不验证软算子的 HP1 读写压力或软核中断触发。长期并行稳定性、全速率记录、传感器参考源精度及实采模型输入适配仍待定。

串口规程：U-Boot 自动启动倒计时期间不发送字符；主机对时脚本只在确认 Linux 会话后发送命令。手动登录前停止主机 `mlk-board-timesync.service`，退出串口后恢复，命令见 [工具说明](../../../tools/README.md#install_board_timesyncsh)。若控制台已停在 U-Boot `=>`，先停止主机对时服务，再执行 `run an_bootcmd`；不修改持久化启动环境。
