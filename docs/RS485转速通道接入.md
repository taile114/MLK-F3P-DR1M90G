# RS485 转速通道接入说明

本文规定 OID-R3808B-12S1S 编码器在 PL 与 PS 两侧的接入：Modbus RTU 采集、转速换算、SoC 采集链路的寄存器与 DMA 通道、以及 PS 本地应用的取数与显示。PL ⇄ PS 边界的字段级契约见 [`PL-PS接口约定.md`](PL-PS接口约定.md) §14，PS 本地应用侧接口见 [`PS本地应用接口约定.md`](PS本地应用接口约定.md)，实板与构建证据见 [`验证结果.md`](../fpga/uisrc/06_doc/验证结果.md) §5.4。

## 1. 工程与接入路径

编码器有两条 PL 路径，共用同一套采集与换算模块：

| 路径 | 顶层 | 用途 |
|---|---|---|
| 独立采集工程 | [`fpga.al`](../fpga/uisrc/fpga.al) 的 `fpga_top` | 温度、振动、电流、转速四路统一采集，转速经 PL USB UART 输出二进制遥测帧，用于无 PS 时的观测与台架调试 |
| SoC 采集链路 | [`fpga.al`](../fpga/uisrc/fpga.al) 的 `soc_top` 与 HDMI 合并工程的 `soc_hdmi_top` | 转速进入 `sensor_soc_axi` 的 AXI 寄存器窗口与传感器 DMA，经 `/dev/pl_ctrl` 到 PS 本地应用 |

两条路径的差别只在出口：独立工程例化 `encoder_telemetry` 驱动 J16 串口；SoC 工程不例化遥测，把同一份事件快照送进 AXI 域。采集、换算与错误恢复逻辑完全相同。

## 2. 硬件与接线

板载 `U21=SP3485EN` 为 3.3 V 半双工收发器，`R120=120 Ω` 为本端终端，`D14/D15=SMBJ6.0CA` 为总线保护，连接器为 `J11`。PL 引脚与厂商 `21_rs485`、`12_uart_loop` 例程一致。

| 信号 | PL 方向 | 球号 | IOSTANDARD | 用途 |
|---|---|---|---|---|
| `I_rs485_rx` | 输入 | N16 | LVCMOS33，上拉 | 收发器 RO |
| `O_rs485_tx` | 输出 | L17 | LVCMOS33 | 收发器 DI |
| `O_rs485_de` | 输出 | N15 | LVCMOS33 | 1=发送，0=接收 |
| `O_uart_tx` | 输出 | J16 | LVCMOS33 | PL USB UART，115200 8N1，仅独立工程例化 |

| 编码器线 | 连接 |
|---|---|
| 红线 | 外部稳压 +5 V |
| 黑线 | J11.4 GND，并与外部电源负极共地 |
| 白线 | J11.5，RS485 A |
| 绿线 | J11.6，RS485 B |
| 黄线 | 悬空并绝缘 |

编码器供电为 5 V，不接 3.3 V 电源。A/B 使用双绞线；长线或不同供电域的隔离、远端终端与抗干扰验证为 TBD。CAN 使用独立的 U22 与 F20/F19，作为 PS 侧备用接口。

温度 UART 仍为 J12.5/T9；PL USB UART 不占用温度 RX 或 PS 控制台。主机实测枚举为 PS=`/dev/ttyACM0`、PL=`/dev/ttyACM1`，重插后须核对端口。

## 3. 通信参数与执行顺序

| 项 | 默认值 |
|---|---|
| 编码器 | OID-R3808B-12S1S，12 bit，4096 计数/圈 |
| 总线 | Modbus RTU，9600 bit/s，8N1，站号 1，查询模式 |
| 测速采样时间 | 100 ms，FC06 写 `0x000A=0x0064` |
| 速度寄存器 | FC03 读取 `0x0020～0x0021`，signed32，高字 / 高字节在前 |
| 上电等待 | 1000 ms，在统一顶层复位释放后计时 |
| 事务间等待 | 100 ms；另加请求、应答与静默时间 |
| 应答 / 静默等待超时 | 100 ms |
| 帧边界 / 帧内间隔 | t3.5；帧内间隔超过 t1.5 判错 |
| DE 提前量 | 发送起始位前 1 bit |
| CRC | CRC16/Modbus，低字节在前 |

1. 复位释放后等待 1000 ms，并确认总线 t3.5 静默；持续占用时不强制发送。
2. 拉高 DE，提前等待 1 bit，发送 FC06 初始化。完整停止位结束后释放 DE；发送期间屏蔽 RX。
3. 校验初始化回显的地址、功能、寄存器、值、长度及 CRC，全部正确才置 `configured`；失败则等待后重试。
4. 等待 100 ms，发送 `01 03 00 20 00 02 C5 C1`，接收 9 字节应答。
5. 校验 UART、帧间隔、地址、功能、字节数、长度和 CRC，正确时发布 `sample_valid`、锁存 `raw_speed` 并增加成功计数。
6. 换算结束时发布 `rpm_valid`，触发一次事件发布；事务错误也发布一次事件。错误时最近有效数值保持，`online` 清零。

初始化只写测速采样时间，不写站号、波特率、零点、方向或自动回传模式。测速采样时间与事务间等待属于不同参数，后者不等于完整采集周期。采集域的 Modbus 主站自由运行，只受硬复位控制；`CTRL.EN=0` 不停止轮询，只冻结寄存器窗口与 DMA 记录的更新，避免一次使能切换被记成超时事件。

## 4. 转速与错误语义

```text
rpm_milli = trunc_toward_zero(raw_speed × 60,000,000 / (4096 × 100))
rpm = rpm_milli / 1000
```

`raw_speed` 是测速采样时间内的 signed32 计数变化，`rpm_milli` 为 signed32、0.001 rpm/LSB。`raw=1000` 对应 `146.484 rpm`，`raw=-4096` 对应 `-600.000 rpm`。中间运算使用 64 bit，越界饱和到 `0x7FFFFFFF` / `0x80000000` 并置 `overflow`。正负号沿用编码器计数方向；机械方向定义与参考转速准确度为 TBD。

| 错误码 | 含义 |
|---|---|
| 0 | 最近事务正常 |
| 1 | 应答超时 / 等待静默超时 |
| 2 | CRC 错误，含截断帧 |
| 3 | 长度、地址、功能、字节数或初始化回显不符 |
| 4 | UART 停止位错误 / BREAK |
| 5 | Modbus 异常，异常码另行输出 |
| 6 | 帧内间隔超过 t1.5 |
| 7 | 应答超过 9 字节接收缓冲区 |

`online` 表示最近一次采集事务成功；成功计数只在正确采集帧上增加，错误计数累计至复位。错误帧里的最近有效速度不得解释成新样本。

## 5. 独立顶层的串口观测

PL USB UART 为 115200 8N1，只发送，无主机控制命令。每帧固定 20 字节，CRC 覆盖字节 0～17。该遥测只在独立采集工程中例化，SoC 与 HDMI 合并工程不驱动 J16。

| 字节偏移 | 字段 | 编码 |
|---|---|---|
| 0～1 | 帧头 | `A5 5A` |
| 2 | 遥测版本 | `01`，独立于 AXI 接口版本 |
| 3 | 标志 | bit0=online，bit1=overflow，bit2=错误事件，其余为 0 |
| 4～7 | 成功样本计数 | unsigned32，大端 |
| 8～11 | 最近有效 raw_speed | signed32，大端 |
| 12～15 | 最近有效 rpm_milli | signed32，大端 |
| 16 | 错误码 | unsigned8 |
| 17 | Modbus 异常码 | unsigned8，非异常事件为 0 |
| 18～19 | CRC | 低字节、高字节 |

发送开始时锁存字段，避免帧内撕裂。UART 忙时的新事件不排队；默认帧发送约 1.74 ms，事务间隔大于发送时间。缩短轮询间隔前须核对吞吐，并按成功计数检查遗漏。该串口帧使用大端整数，不改变 AXI / DMA 的既有小端格式。

在仓库根目录运行，实时读取需要 `pyserial`：

```bash
python3 fpga/uisrc/06_doc/monitor_encoder.py --port /dev/ttyACM1 --csv fpga/uisrc/out/encoder.csv
python3 fpga/uisrc/06_doc/monitor_encoder.py --input fpga/uisrc/out/sim/telemetry.bin
```

普通串口助手的文本显示不能直接解码二进制帧。正常输出形如 `sample=1 raw=1000 rpm=146.484 overflow=0`；错误事件显示错误码。

独立顶层保留 LED1=心跳、LED2=温度在线、LED3=振动 DEVID 自检通过、LED4=电流错误；转速状态由串口输出，不复用上述灯。LED5 接 PS MIO51，不属于 PL 顶层。

## 6. SoC 采集链路

### 6.1 时钟域与例化

`sensor_soc_axi` 在采集时钟域（`I_sysclk`，100 MHz）例化 `encoder_modbus` 与 `encoder_rpm`，复位为采集域同步复位 `S_sensor_rstn`，不受 `CTRL.EN` 门控。AXI 侧保持既有 100 MHz 域与 `sensor_capture` / `sensor_dma` 通路不变。

### 6.2 时间戳与事件发布

`raw_speed` 有效拍锁存当前采样时间戳（`sensor_capture` 的 32 位 `10 ns/LSB` 时基），与 AXI `PL_TS_NOW` 同源。每次事件（成功样本或错误事件）把一条 192 bit 快照送进跨域信箱：

```text
{raw[31:0], rpm_milli[31:0], count[31:0], err_count[31:0],
 ts[31:0], flags[7:0], error_code[7:0], exception_code[7:0], 8'h00}
flags[0]=sample_valid  flags[1]=overflow  flags[2]=online  flags[3]=configured
flags[7:4]=error_code
```

AXI 域收到后整条锁存，不逐字段更新，随后 `SPEED_SEQUENCE` 加一；`CTRL.EN=0` 时丢弃新事件（窗口不更新），重新使能后由下一个事件带回 PL 侧继续累加的计数。

### 6.3 寄存器窗口

接口版本 v1.2，`ID` / `VER` 为 `0x504C0102` / `0x0102`，已有偏移与位域不变。七个转速偏移全部只读，写访问返回 SLVERR（与 §12 的只读约定一致）：

| 偏移 | 名称 | 规格 |
|---|---|---|
| `0xB8` | `SPEED_RAW` | signed32，一个采样周期内的编码器计数变化 |
| `0xBC` | `SPEED_RPM_MILLI` | signed32，0.001 rpm/LSB |
| `0xC0` | `SPEED_STATUS` | bit0 在线；bit1 换算饱和；bit2 本次事件为错误；bit3 FC06 已配置；`[7:4]` 错误码；`[15:8]` 异常码 |
| `0xC4` | `SPEED_COUNT` | unsigned32，成功样本累计数 |
| `0xC8` | `SPEED_TS` | unsigned32，事件时间戳，10 ns/LSB |
| `0xCC` | `SPEED_SEQUENCE` | unsigned32，事件计数（含错误事件） |
| `0xD0` | `SPEED_ERR_COUNT` | unsigned32，错误事件累计数 |

读一致性：先读 `SPEED_SEQUENCE`，再读字段，最后再读 `SPEED_SEQUENCE`；两次相同才接受，否则重读。错误事件只更新 `SPEED_STATUS`、`SPEED_SEQUENCE` 与 `SPEED_ERR_COUNT`，`SPEED_RAW` / `SPEED_RPM_MILLI` / `SPEED_TS` 保持最近一次成功值。

### 6.4 DMA 记录

转速事件同时写入传感器 DMA 环形缓冲，每条记录固定三个 64 bit 字：

| 字 | `[63:32]` | `CH[31:16]` | `[15:0]` |
|---|---|---|---|
| 0 | 事件时间戳，10 ns/LSB | `0x0003` | `SPEED_STATUS[15:0]` |
| 1 | `rpm_milli[31:0]` | `0x0004` | 0 |
| 2 | `raw_speed[31:0]` | `0x0005` | 0 |

三字与振动帧同宽，复用同一套跨块余字与尾字处理。仲裁规则：振动帧优先，转速记录只在振动打包器空闲时起步，起步后独占数据口直到第 3 字发完，两种记录不互相打断。新事件到达时上一条记录未发完，本次事件不写记录并置粘滞丢弃位，该位并入 `DMA_STATUS.overflow`；DMA 未启动时既不记录也不计丢。

CH 是每个 64 bit 字 `[31:16]` 的通道号，不是整条记录的标识；转速记录没有 `0xFFFF` 填充字，PS 侧按 `CH=3` 起始、连续三字成组。

### 6.5 复位与使能语义

- 硬复位：采集域与 AXI 域同时复位，计数器与窗口清零。
- 软复位（`CTRL.RST`）：清寄存器快照与 DMA 打包状态，PL 侧 Modbus 主站与累计计数不重新开始。
- `CTRL.EN=0`：冻结窗口与 DMA 记录更新，不停止编码器轮询；`CTRL.EN=1` 后继续。

## 7. PS 侧接入

### 7.1 内核驱动

`pl_ctrl` 把 `0xB8`～`0xD0` 作为只读窗口暴露，读地址上限从 `0xB4` 扩到 `0xD0`，写白名单不含这些偏移；探测要求 `ID==0x504C0102`，版本不匹配时拒绝加载而不是带旧位图运行。

### 7.2 取数封装

`pl_read_speed()` 按「序号 → 七个字段一次读完 → 序号」读取，两次序号相同且与突发内的序号一致才接受，最多重试 3 次，持续不一致返回 `-EAGAIN`，各字段不可用。`DriverSource` 把寄存器轮询与 DMA 记录合并成一条样本流：

- 成功样本数或序号变化才算新事件；序号变而计数不变是错误事件，不产生样本。
- 两路带同一事件时间戳，按时间戳去重；环形模式下 1 s 内见过记录就优先用记录，不再追加寄存器读到的同一样本。
- 超过 2 s 没有新样本、或状态为离线时发布不可用，附原因（编码器离线 / 未配置 / 无有效数据）；错误事件本身只更新原因，不清空面板。

### 7.3 看板与命令行

看板「转速」面板按安装方向对 PL 符号取反，以 signed32、0.1 rpm 分辨率显示数值和波形，不施加 ±3276.7 rpm 限制；正转显示正值、反转显示负值，停机后 PL 仍每 100 ms 发 `rpm=0` 的样本，读数自然回到零。无有效数据时显示原因，不用 0 rpm 冒充读数。

```bash
plctl speed            # 一行文本：state / raw / rpm_milli / rpm / count / err_count / ts / seq / status
plctl speed --json     # 单行 JSON，离线时 rpm_milli 与 rpm 为 null
```

### 7.4 NPU 接口预留

`mlk_npu_output` 已预留故障检测与故障分级字段，当前推理恒置 0，界面显示 `N/A`，不得据此判定故障；模型产出后由 `npu.cpp` 填充，字段与版本规则见 [`NPU-AI接口约定.md`](NPU-AI接口约定.md)。
