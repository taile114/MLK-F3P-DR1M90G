# 上位机连接与密钥配置

本文规定 ps-local 与 remote-pc 的首次配对、日常连接、自动启动和密钥更换步骤。无线组件与工单接口见 [无线联网与双端协同](无线联网与双端协同.md)。

## 1. 已配置设备的日常使用

当前联调电脑与核心板已保存相互匹配的 ECDH 身份，开启自动发现。电脑侧 remote-pc 由桌面会话中手动执行启动脚本，未安装自动启动服务；核心板由 `S99qtapp` 启动 ps-local。

1. 电脑登录桌面后，在仓库根执行 `host/remote-pc/run_host_app.sh` 启动 remote-pc，无需附加 IP 或监听参数。
2. 核心板上电。已保存的 WiFi 由认证服务自动连接；有线千兆网插入网线后自动获取地址并按需做门户认证。更换网络时，在 ps-local 左上「网络配置」中选择千兆网或 WiFi 页配置。电脑连接同一个局域网。
3. 已配对设备自动发现对端地址并建立 ECDH 会话。一般在取得 IP 后的 15 秒内完成；无需重新生成密钥，也无需手动开启 PC 监听。
4. ps-local 在「网络配置」右侧显示「上位机：加密已连接」；remote-pc 在「展开」右侧显示「加密已连接」。检查四通道与板端资源信息持续更新。

自动发现成功会保存当前地址；DHCP 地址变化或应用重启后重新查找。WiFi 密码、身份密钥与本机配置保存在设备本地，仓库和通用 rootfs 不携带这对设备的私钥。

替换或重新烧录 rootfs 后，应先检查板端「对端公钥」和身份指纹。配置未保留时，按 §2 重新交换公钥；仅接入同一个 WiFi 不能建立对未配对身份的信任。PC 的连接状态变化同时写入启动终端；使用 systemd 用户服务时可通过 `journalctl --user -u mlk-remote-pc.service` 查看。

## 2. 首次配对：ECDH

每端首次启动自动生成独立身份密钥，默认 ECDH；未填写对端公钥时显示「等待配对」，不发送明文应用数据。私钥始终留在本机。首次配对只交换公钥，不依赖固定 IP。更换电脑、换板或主动重新生成身份后，需要重新交换公钥。

| 步骤 | ps-local | remote-pc |
|---|---|---|
| 1 | 点击右上「配置」，输入本机配置密码，初始 `root` | 点击「配置」或 F2，输入 PC 本机配置密码，初始 `root` |
| 2 | 向下滚动至「安全（传输加密）」，确认「身份公钥」与本机指纹存在；为空时点击「生成身份密钥」 | 同左；两端身份公钥应不同 |
| 3 | 点击「导出本机公钥」，保存为 `ps-local.pub` | 点击「导出本机公钥」，保存为 `remote-pc.pub` |
| 4 | 通过 U 盘或其他可信文件传输方式取得 `remote-pc.pub`，点击「导入对端公钥」 | 导入 `ps-local.pub` |
| 5 | 将导入后显示的指纹与 PC 界面的本机指纹核对 | 将导入指纹与 ps-local 的本机指纹核对 |
| 6 | 「模式」选 ECDH；「传输」中勾选「自动发现已配对设备」；监听为 `0.0.0.0:8000`，点击 OK | 同左，并勾选「启动后自动监听并连接」，点击 OK |
| 7 | 接入与 PC 相同的局域网，观察左上连接状态 | 启动监听后主动握手，收到板端有效数据后显示「加密已连接」 |

`.pub` 文件仅含以 64 个十六进制字符表示的本机公钥，不包含私钥。也可直接把一端「身份公钥」的完整内容填入另一端「对端公钥（hex）」。已有公钥时无需再次点击「生成身份密钥」；点击生成产生新身份，必须重新交换公钥并保存。配置窗口内的改动在点击 OK 后生效。

首次生成后导出文件但尚未保存时，应保持窗口开启，完成交换并点击 OK；取消配置不会保存新生成的身份。常规首次启动已自动保存身份，不存在此限制。

## 3. PSK 配对方式

1. 任一端进入「配置」→「安全（传输加密）」，在「PSK（hex）」右侧点击「生成」。
2. 将完整的 64 个十六进制字符 PSK 通过可信方式复制至另一端同名字段。两端不得各自生成不同 PSK。
3. 两端模式均选 PSK，开启自动发现并保存。PC 开启启动自动监听，接入同一局域网后连接。

PSK 为双方共享的通信秘密，不使用 `.pub` 公钥文件传递。ECDH 与 PSK 任选其一，两端模式必须一致。发现与握手不会自动信任未配对的设备。

## 4. 连接范围与手动地址

| 项目 | 规则 |
|---|---|
| 数据传输 | 默认 UDP 8000，可在两端本机配置中修改 |
| 自动发现 | UDP 8001；仅探测当前启用的 WiFi / 以太网私有 IPv4 子网，支持 `/24` 至 `/30`，每轮最多 1024 个地址 |
| 身份校验 | 使用已配置 PSK 或固定对端公钥派生的独立发现密钥，验证挑战响应后更新端点；应用数据仍通过原加密会话传输 |
| 地址缓存 | 「上报目标」是首选地址；同网段自动发现成功后更新缓存 |
| 网络隔离 | 热点需允许至少两台客户端，并关闭客户端隔离；发现与数据端口需双向可达 |
| 较大子网 / IPv6 | 当前不做自动遍历，使用手动地址 |
| 4G 跨网 | 不使用局域网发现；需要预先可达的公网端点或 VPN 地址，运营商 NAT 下不能仅靠搜索找到 PC |

自动发现使用有界单播请求，使严格 PC 防火墙可按主动请求的回包处理；不要求把整个局域网加入信任列表。PC 先向板端 UDP 8000 发起握手 / 查询后，板端持续回传。实际防火墙策略仍需允许这些主动 UDP 会话。

手动连接时关闭自动发现：ps-local「上报目标」填 PC 的 IP / 监听端口；remote-pc「上报目标」填板端 IP / 监听端口。两端监听本机地址，默认 `0.0.0.0:8000`。配置中的监听端口和对端目标端口需对应，接收端只接受所配目标的源 IP / 源端口。

## 5. PC 启动方式

构建完成后，从仓库根执行 [run_host_app.sh](../host/remote-pc/run_host_app.sh) 启动，脚本加载与构建一致的 Qt 环境：

```sh
host/remote-pc/run_host_app.sh
```

PC 应用只运行一个实例；重复启动保留已有窗口。配置内取消「启动后自动监听并连接」后，程序仍可启动，但需手动点击「展开」→「监听」。

需要随桌面会话自动启动时，可安装 systemd 用户服务：

```sh
bash tools/install_remote_pc.sh install
bash tools/install_remote_pc.sh status
```

服务名为 `mlk-remote-pc.service`，随 `graphical-session.target` 启动，`ExecStart` 指向同一脚本。取消自动启动：

```sh
bash tools/install_remote_pc.sh remove
```

核心板无需安装此服务，rootfs 的 `S99qtapp` 已负责启动 ps-local。

## 6. 本机配置与口令

| 项目 | 用途 / 保存位置 |
|---|---|
| ps-local 配置 | `/var/lib/mlk/config/MLK-F3P/mlk_ps_local.conf`，权限 `0600` |
| remote-pc 配置 | Linux 默认 `~/.config/MLK-F3P/mlk_udp_host.conf`，权限 `0600` |
| WiFi 密码 | 认证服务连接热点使用，独立于应用密钥 |
| 配置密码 | 进入本机配置界面；两端各自保存与修改，初始 `root` |
| 记录加密口令 | 加解密本机记录与故障工单；两端各自保存，不要求相同 |
| 通信身份 / PSK | 认证自动发现与加密通信；ECDH 私钥各端独立，对端公钥相互对应；PSK 方式使用同一共享密钥 |

仅恢复本机私钥不能恢复对端对新身份的信任。备份配置文件会包含本机通信秘密和记录口令，应按私密文件保存；通用镜像中不复制已配对配置。

## 7. 连接状态核对

1. WiFi 已连接但上位机未连接时，确认两端应用均运行，自动发现已勾选，安全模式一致，PSK 或对端公钥匹配。
2. 检查是否位于同一受支持子网、热点设备数量是否足够、客户端间 UDP 是否可达。4G / VPN 场景改用可达的手动地址。
3. 「正在握手」持续存在时，核对身份指纹；「连接超时」表示 5 秒未收到有效应用数据，单纯 WiFi 关联成功不能证明链路正常。
4. 自动发现正确端点但仍无数据时，检查 UDP 8000 和配置的监听端口。发现帧不会单独把状态改成「加密已连接」。

联网后的时间优先由 NTP 获取，WiFi / 4G 共用默认路由；串口只在网络校时不可用时回退，见 [时间与延迟](上位机-PS接口约定.md#7-时间与延迟)。
