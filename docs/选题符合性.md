## 3. 工业总线与转速通道

- 板载 **CAN 为 PS 硬核**（`ARM_Processor_System` CAN0/1，I/O 经 PL BANK33 引出，Linux `socketcan` 驱动）；板载 **RS485 为 PL 逻辑**（软 UART + DE 方向控制，`SP3485EN`）。见 [`接口冲突与可用性分析.md`](接口冲突与可用性分析.md)。
- 转速通道使用板载 RS485（PL 自研 UART + DE），已在统一 `fpga_top` 实现 Modbus RTU 初始化、轮询、CRC、超时与错误恢复，可作为「工业总线时序解析」的实现依据；接线、信号与数据格式见 [`PL-PS接口约定.md`](PL-PS接口约定.md) §8 / §9。
- OID-R3808B-12S1S 为 9600 8N1、站号 1、查询模式；测速采样时间与事务间等待均为 100 ms，完整采集周期另含通信时间。实板前 1000 帧无错误事件 / 溢出、成功计数无跳号，范围 −78.955～+80.126 rpm，停止归零；参考转速准确度、长线抗干扰与长时间连续运行已验收。
- CAN 与 CANopen 为备用路线：若传感器只提供 CAN，则放 PS 侧处理，不做 PL 软核 CAN、不做 CANopen 栈。

## 4. 多通道同步采集口径

硬性任务 1 的「多通道同步采集」按**共同时基 + 对齐锁存 + 时间戳**实现，并标注同步等级：温度 GT-M601 为**自主上报**，PL 不能触发；振动（SPI）与电流（I2C）是 PL 主机可控，但内部 ODR / DR 各自独立。

- **全局时间基准**：PL 内建 100 MHz 周期计数 `r_ts`，并分频出 `tick`（1 kHz）。
- **时间戳**：每个通道锁存样本时（振动 / 电流读点、温度收帧）同步锁存 `r_ts`，样本带时间戳；PS 按时间戳对齐各通道。
- **对齐锁存**：`tick` 上升沿锁存振动最新寄存器与电流最新转换，使 PL 可控通道落在同一时间栅格。器件读点触发不采用：ADXL345 与温度不可命令采样，电流改单次会压低 860 SPS 吞吐，收益低、风险高；设计保留 1 kHz 最新值对齐锁存，器件 ODR / DR 与控制器节奏独立，不改变原始特征样本流。
- **同步等级与局限**：温度按「到达即打时间戳」，属**准同步（同一时间基）**，非严格同时；报告按此口径写。
- **同步精度已板测**：对齐帧周期 999.936 us（21 帧，帧计数严格 +1）、振动 320.2 us（约 3123 Hz，DATA_READY / `acc_vld` / 样本计数均为 66，无漏采）、电流约 1160 us（862 Hz）。振动偏差属器件 ODR 容差；电流为 ADS1115 转换节奏。见 [`../fpga/uisrc/06_doc/验证结果.md`](../fpga/uisrc/06_doc/验证结果.md) §5。

> 备选：硬性任务 1 为三选一。转速走 RS485 后，「工业总线时序解析」即可作为 PL 硬性项。

## 5. 交付结论

1. 板载 NPU 混合后端（硬性 4）：合并镜像包含厂商 `Video_NPU` IP，三个 NPU 设备齐备，FF6 混合回放与实采推理通过。
2. DMA 环形长跑与 PL 特征链路实板校验完成（硬性 3 / 1）。
3. 新 SD 冷启动与 2 h 稳定性验收通过（PS 实板运行，本地存储落地）。
4. RS485 转速长时间连续运行与长线抗干扰验收通过（SoC / PS 数据出口接通）。
5. 量化测试报告所需四项指标全部取得实板数据（硬性 6）。
6. 多通道同步采集按 `tick` 对齐锁存 + 时间戳口径交付，同步等级与器件边界已写入报告。
