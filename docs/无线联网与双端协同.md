# 无线联网与双端协同

本文规定 ps-local 与 remote-pc 的有线千兆网、WiFi 与 4G 接入、链路优先级、共享配置、故障工单和验证流程。网络帧以 [上位机-PS 接口约定](上位机-PS接口约定.md) 为准。

密钥生成、公钥文件交换、日常自动连接和 PC 自动启动的操作步骤见 [上位机连接与密钥配置](上位机连接与密钥配置.md)。

## 1. 运行职责

| 项目 | ps-local | remote-pc |
|---|---|---|
| 采集与推理 | 访问 PL、运行板端模型 | 接收采集与推理结果、控制数据集回放 |
| 界面 | 四传感器、模型面板、指标、核心板资源侧栏 | 同一主题与布局；侧栏显示板端资源 |
| 输入 | 虚拟键盘 | 物理键盘 |
| 配置密码 | 本机 QSettings，初始 `root` | 本机 QSettings，初始 `root` |
| 网络配置 | 顶栏「展开」右侧「网络配置」，左列选择千兆网 / 4G / WiFi，右列显示对应配置 | 不提供 |
| 控制权选择 | 配置中选择 ps-local / remote-pc 优先，默认 ps-local；板端修改始终可用，remote-pc 优先时连接后由 PC 快照覆盖 | 读取板端当前控制权 |
| 连接状态 | 顶栏「网络配置」右侧显示核心板网络状态（千兆网 / 4G / WiFi / 未连接）与上位机连接状态 | 左上「展开」右侧显示连接状态 |
| 本地记录 | 默认 `/data/mlk_f3p` | 默认 Qt 应用数据目录下 `records/` |

配置密码、存储目录、记录口令、保留策略、FFT 点数、界面刷新率、网络端点与身份私钥均属于各端本机设置，不通过共享配置同步。两端通信所用 PSK 或固定对端公钥需分别配置。

ps-local 启动脚本固定使用 `/var/lib/mlk/config/MLK-F3P/mlk_ps_local.conf`，避免开机服务与登录会话的 `HOME` 不同而读取不同配置。首次启动可迁移 `/root/.config/MLK-F3P/` 或 `/.config/MLK-F3P/` 的已有配置；`MLK_CONFIG_HOME` 可覆盖配置根目录。板端系统时钟保持 UTC，界面默认 `CST-8`（UTC+8），故障时间在协议和存储中均为 UTC epoch。

两端连接状态仅由所配对端的有效应用帧刷新，5 秒无有效帧显示超时。WiFi 已关联或 ECDH 握手完成不单独计为应用连接成功。

## 2. 以太网、WiFi 与 4G

有线千兆网使用 PS 端网口，WiFi 与 4G 共用 USB HOST 分支，三者不共用引脚。千兆网获得地址并且门户认证通过后，4G 与 WiFi 不参与默认路由；千兆网链路失效后按 4G、WiFi 的顺序回落。

### 2.1 组件

| 组件 | 目标位置 / 行为 |
|---|---|
| 千兆网接口 | PS 端口，设备树仅启用 `eqos0`，配 YT8531 PHY；Linux 接口名以启动枚举为准，应用按 `eth*` / `en*` 识别 |
| 千兆网 DHCP | 有线接口由系统 `dhcpcd` 管理；`/usr/bin/mlk_net_watch` 仅在系统无 `dhcpcd` 且网口无地址时启动 `udhcpc`，pidfile 为 `/var/run/mlk-net/<interface>.dhcp.pid`；界面「启用并获取地址」通过 `dhcpcd -n` 续租 |
| 链路优先级 | `/usr/bin/mlk_net_priority` 输出当前生效链路；`/usr/bin/mlk_net_watch` 由 `S40mlknetwork` 启动，只保留生效链路的默认路由 |
| 门户认证 | ps-local 的 `NetworkSettingsDialog`、`PortalDialog` 与 `host/common/captiveportal.h`：204 探测、跟随重定向取门户页、抓取登录表单并提交 |
| 门户凭据 | `/var/lib/mlk/ethernet.conf`，权限 `0600`，保存门户地址、账号、密码与自动登录开关 |
| PPPoE 拨号 | `/usr/bin/mlk_pppoe` 调用 `pppd` 与 `pppoe.so`；账号、密码与服务名保存在 `/var/lib/mlk/pppoe.conf`（`0600`）；拨号成功后 `ppp0` 按千兆网优先级参与路由 |
| AIC8800 驱动 | `/lib/modules/<release>/extra/aic_load_fw.ko`、`aic8800_fdrv.ko` |
| AIC8800D80 固件 | `/lib/firmware/aic8800D80/`，由厂商配套启动文件导入 |
| WiFi 用户态 | `wpa_supplicant`、`wpa_cli`、`wpa_passphrase`、libnl |
| 网络校时 | `chronyd`、`chronyc`、`S49mlktime`；WiFi / 4G 由链路优先级选择默认路由，网络源健康时优先于串口校时 |
| WiFi 启动 | `/etc/init.d/S40mlknetwork`，等待 USB 枚举后启动认证与 DHCP 监视器 |
| WiFi 配置文件 | `/var/lib/mlk/wpa-<interface>.conf`，权限 `0600` |
| DHCP | `/usr/bin/mlk_wifi_dhcp` 响应连接 / 断开事件；`dhcpcd.conf` 以 `denyinterfaces wlan*` 排除无线接口，避免重复租约与源地址错位 |
| 蜂窝网络驱动 | 内核内建 USB option、QMI WWAN、CDC Ethernet / NCM / MBIM、RNDIS |
| 厂商蜂窝组件 | `/usr/sbin/quectel-CM`、`extra/GobiNet.ko`；GobiNet 为备用驱动，不与已绑定的 QMI 驱动重复加载 |

USB 跳线应位于 HOST 侧；WiFi、4G 与 USB 鼠标共用 HOST 分支，可共存。SLAVE 侧不提供这些设备，详见 [接口冲突分析](接口冲突与可用性分析.md) §1.2。4G 无 SIM 时仅集成组件，不自动拨号。实际 4G 模块型号、USB VID/PID、运营商 APN 与有 SIM 拨号验收为 TBD。

### 2.2 构建

从仓库根执行：

```sh
nix develop ./platform/flash
bash platform/flash/build_kernel_npu.sh
bash platform/flash/stage_ps_local.sh
bash platform/flash/build_rootfs.sh
```

`build_rootfs.sh` 调用 [stage_network.sh](../platform/flash/stage_network.sh)，按 [network.config](../platform/flash/network.config) 构建 WiFi 用户态组件，导入匹配当前内核版本的厂商驱动、固件与蜂窝工具，再应用 rootfs overlay（含 `mlk_net_priority`、`mlk_net_watch` 与 ps-local 应用）。`NETWORK_ASSETS` 可指定配套启动文件目录。缺少组件、内核功能或模块版本不符时构建失败。

[build_wifi_modules.sh](../platform/flash/build_wifi_modules.sh)从厂商资源树的 AIC8800 源码构建两个 WiFi 模块，关闭 `CONFIG_PREALLOC_RX_SKB` 与 `CONFIG_PREALLOC_TXQ`，使用动态缓冲路径；不直接使用带固定接收池的厂商预编译模块。`AIC_SOURCE` 可覆盖源码位置，生成文件保存在 `platform/flash/vendor/network/aic8800/`。仅构建 `Image` 后需刷新内核模块符号表，脚本按需执行内核 `modules` 构建。

内核产物为 `platform/flash/vendor/boards/DR1M/buildroot/images/boot/uImage.lz4`；rootfs 为同级 `images/rootfs/rootfs.tar.gz`。网络驱动配置在内核中，用户态工具与固件在 rootfs 中，更新时需配套部署。`BOOT.bin` 仍只包含 FSBL、PL bitstream 与 U-Boot。

### 2.3 无 SIM 联调顺序

1. 板卡接入 HOST 分支并启动配套内核 / rootfs；通过串口确认无线接口出现、WiFi 服务运行。接口未出现时执行 `/etc/init.d/S40mlknetwork restart` 并检查内核日志。
2. ps-local 点击「网络配置」→「千兆网」：插入网线后网口自动拉起并获取地址；地址出现后自动做一次连通性探测。需要门户登录时填写门户地址（留空时按默认网关探测并跟随重定向）、账号与密码，点击「门户登录…」抓取登录页并提交；勾选自动登录后，后续取得地址时直接使用已保存凭据提交。
   无线接入选择「WiFi」页，搜索 SSID、输入密码并连接。支持开放网络、WPA/WPA2-PSK；企业 EAP、WPA3-only 为受限。
3. 界面显示认证完成及 DHCP 分配的 IP 后，确认 PC 与板卡 IP 可互通。隔离访客网络、AP 客户端隔离与 PC 防火墙需允许所配 UDP 端口。
4. 按连接说明完成一次 PSK 或 ECDH 配对，启用「自动发现已配对设备」。同一受支持子网内无需手动填写 IP；固定地址场景可关闭自动发现，分别填写对端 IP / 接收端口。两端默认监听 `0.0.0.0:8000`。
5. remote-pc 默认启动后自动监听；取消自动监听时在「展开」侧栏手动开启。观察左上「加密已连接」及 ps-local 的上位机状态。发现帧或监听开启不单独计为连接成功。
6. 观察四通道数据、振动三轴与模型状态。remote-pc 点击「记录」保存接收数据；「记录列表」查看本机采集文件与故障工单。采集断流时相应面板显示不可用。
7. 检查共享参数、断网重连、故障时间及工单重发。完成 WiFi 验收后，再进行有 SIM 的 4G 枚举、APN / 拨号与跨网可达性验收。

WiFi 接口通过 [wpa_supplicant 控制接口](https://w1.fi/wpa_supplicant/devel/ctrl_iface_page.html)异步扫描、配置与读取状态。WiFi 密码不写入 shell 命令或进程参数；WPA-PSK 在应用中派生后通过 Unix socket 传给认证服务。认证与 DHCP 成功后才保存网络配置。

### 2.4 链路优先级与门户认证

优先级为 千兆网 > 4G > WiFi，判定口径是链路已获得 IPv4 地址。`mlk_net_priority` 按该顺序输出第一个可用链路，`mlk_net_watch` 每 5 s 执行一次：网线插入且无地址时启动 DHCP 客户端；当前生效链路以外的默认路由被删除并记录其网关，生效链路失效后按保存的网关恢复下一优先级链路的默认路由。WiFi 的 DHCP 事件处理先查询优先级，千兆网或 4G 已获得地址时不参与地址竞争。启用 PPPoE 时该网口不再获取 DHCP 地址，`ppp0` 获得地址后由 `mlk_net_priority` 按千兆网输出。

门户认证针对有线接入的服务端渲染登录页：先请求 `http://connect.rom.miui.com/generate_204`，返回 204 表示已联网；返回 200 或重定向表示被门户接管，门户地址取重定向目标；探测失败时改用默认网关地址再探测一次，以覆盖 DNS 被门户拦截、只放行网关 HTTP 的接入方式。登录页按 `form` / `input` 解析，优先选择含密码输入的表单，密码字段填入门户密码，首个用户名类文本字段填入账号，按表单 method 以 GET 或 POST 提交，随后再次探测确认。

依赖 JavaScript 计算挑战、CHAP 或私有协议的认证页无法在应用内完成。锐捷 SMP / CAS 一类以单页应用承载的校园门户属于此类：探测后界面显示重定向地址，但登录表单由脚本生成并带会话签名，应用不提交。校园网改由 PPPoE 接入：网口页勾选「使用 PPPoE 拨号」，填入账号与密码后点击「PPPoE 连接」；`mlk_pppoe` 渲染 `/etc/ppp/peers/mlk-pppoe` 并启动 `pppd`，`ppp0` 取得地址后按千兆网优先级接管默认路由。该路径已完成脚本、镜像与实板拨号验证：PAP 认证成功，`ppp0` 取得地址后默认路由、DNS 与 HTTP 出网可用。板端异常断电时接入服务器可能保留旧 PPPoE 会话，重新拨号需等待该会话超时，期间 `pppd` 按 `persist` 间隔重试，界面保持「拨号中」；正常断电应先断开 PPPoE。4G 跨公网通常存在运营商 NAT；本协议使用可达 UDP 端点，公网接入、VPN 或中继部署为 TBD。无 SIM 的 WiFi 测试不代表蜂窝公网链路验收通过。

网络时间源配置在 `/etc/chrony.conf`，默认使用阿里云与 Cloudflare NTP。`mlk_time_status` 成功表示已选中近期网络时间源，串口 `mlk_set_time` 此时保留网络时间；网络源失效后可由串口回退。板端应用后台每 10 s 检测网络时间源，链路刚连上时立即检测，可用后执行 `chronyc makestep` 步进；顶栏「时间同步」提供同一动作的手动入口。`mlk_time_status` 不可用时可在配置中手动设置板端时间，可用后该项禁用。初始大偏差允许前三次校时步进，随后由 Chrony 平滑修正。无 RTC 的开机时间种子仅用于避免 1970 日期，不代表校时完成。故障来源应在取得可靠 UTC 时间后提交 `faultTimeUs`，详见 [时间约定](上位机-PS接口约定.md#7-时间与延迟)。

## 3. 共享参数仲裁

共享范围为四通道 `k`、`b`、告警下限、上限与使能。板端保存唯一生效副本及 `sharedRevision`，remote-pc 显示板端确认后的副本。

| 当前控制权 | ps-local | remote-pc |
|---|---|---|
| ps-local（默认） | 可修改共享参数与控制权 | 共享参数只读，写请求被拒绝 |
| remote-pc | 可修改共享参数（上位机连接后以其快照覆盖），可收回控制权 | 本机保存共享值；加密连接后自动提交并覆盖板端 |

板端校验完整字段、数值范围、上下限关系与控制权，成功后升版本并返回快照。remote-pc 优先时不要求 set 的版本与板端一致：板端接受远端完整快照，用其覆盖离线期间的本地修改；电流零点 / 增益由板端归零维护，不随远端快照回退。对同一请求的短期重试使用相同请求 ID；确认超时后重新查询。配置窗口打开期间收到远端修改时，ps-local 保留最新共享值并提示。共享参数与链路 / 密钥 / 本地存储独立，修改本地设置不要求先填写 IP 或密钥。

电流流内单位为 mA，转速为 0.1 rpm/LSB，两个面板按固定物理尺度显示；电流硬件标定 / 归零仍属于板端驱动操作，不能用远端显示系数代替。

## 4. 故障时间与工单 API

分类模型的当前状态、U7 声光输出和心跳由 `reportModelState` 或 `/run/mlk-fault.sock` 接入，字段及客户端见[声光告警与模型故障 API](声光告警与模型故障API.md)。本节 `reportFault` 仅保存工单，不驱动当前告警状态。

板端接口为 [KLocalWindow::reportFault](../host/ps-local/src/klocalwindow.h)：

```cpp
bool reportFault(const QString &id, quint64 faultTimeUs,
                 int faultClass, int grade, const QString &message);
```

此接口为 Qt `Q_INVOKABLE` / slot；应从 GUI 线程调用，其他线程使用排队调用。返回 `true` 表示板端加密工单保存成功，网络确认独立完成。

| 参数 | 约束 |
|---|---|
| `id` | 1–64 个 ASCII 字母、数字、`_`、`-`；重试复用同一 ID；不同事件使用不同 ID |
| `faultTimeUs` | 故障发生时的 Unix UTC epoch 微秒，非 PL 时间戳或模型单调时钟，使用十进制字符串传输 |
| `faultClass` | `1` 轻微故障、`2` 重度故障 |
| `grade` | `0..255`，由故障来源定义 |
| `message` | UTF-8，最多 512 字节 |

板端先写入 `<storageDir>/orders/<id>.mlko`，再通过加密 UDP 发送；每 2 秒重发最早的最多 4 个未确认工单。remote-pc 按 ID 去重，原子保存成功后返回 `stored` ACK。相同 ID 内容不一致、解密失败或保存失败时不确认。板端保留原工单，以 `.mlko.ack` 标记已确认状态；未确认工单不因断线或进程重启而删除。

`.mlko` 为 `MLKO` + 版本字节 `1` + 16 字节盐 + 12 字节 nonce + GCM 载荷；使用 PBKDF2-HMAC-SHA256 100000 轮派生密钥，完整头部作为 AAD。工单始终加密，两端使用各自本机记录口令；修改记录目录或口令前需保存原目录及口令，未发送工单仍需原口令读取。工单不参与配置中的记录删除操作，保留与导出由工单生命周期另行管理。

模型面板在「故障分级」右侧显示「故障时间」，使用实际已记录事件时间；无事件显示 `N/A`。寿命回归模型不产生分类与分级，不依据 RUL 伪造故障事件。采集「记录」按钮控制波形分段保存，与故障事件 API 独立。板端 / PC 时钟同步要求见 [时间约定](上位机-PS接口约定.md) §7。
