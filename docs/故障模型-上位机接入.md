# 故障模型与上位机接入

本文规定将已通过 F3P 离线板测的单主故障模型接入 PS 本地 Qt 和 remote-pc 的实施步骤、运行包格式及验收条件。现有 SD 系统具备 NPU、采集与 HDMI 基础环境；运行包生成器与共享库源码位于 [host/ps-local/fault-inference](../host/ps-local/fault-inference/README.md)。AArch64 共享库、检查程序与 Qt 应用已构建，QEMU CPU 和开发机 Qt 验证见[故障模型接入与评估模式](../host/故障模型接入与评估模式.md)，输入绑定修复库的板端 NPU 两轮 360 窗证据见[板端验收](../host/tests/results/fault/tensor-binding.json)；GUI 操作与实采仍待验收。

## 1. 参数来源与可复用基线

板测参数来自 Python/PyTorch 训练生成的 `npu/fault-diagnosis/model/runs/active_selection_single_v1_seed42/best.pt`，训练入口及配置见[单故障训练与推断](../npu/fault-diagnosis/model/单故障训练与推断.md)。[prepare.py](../npu/fault-diagnosis/deploy/prepare.py) 调用训练侧 `load_checkpoint`、`fused_eval` 导出网络，不重新训练。BN 折叠改变参数存储形式而保持浮点推断语义；CNN 使用 train 1063 窗做 PTQ，valid/test 不参与尺度拟合。

模型固定为 `fault_mtl_f3p_cnn2d_single_v3`，任务 `bench_fault_single_v1`，分类契约 `single_primary_fault_v1`。类别顺序为 `normal / overload / undervoltage / overtemperature / mount_tilt`；正常 0 级，异常只输出所选类别的 1～3 级。机械与温度两条隔离融合路径、四组分级阈值均须保留。

[板测结果](../npu/fault-diagnosis/deploy/BOARD_TEST.md)：360 窗分类 360/360，分类与所选等级同时正确 356/360；NPU 与 FP32 的逐窗类别和所选等级相同。平均网络前向为 CPU 76.186 ms、NPU 混合 3.988 ms，约 19.1 倍；不含原始预处理、加载、解码和 I/O。当前 test 是同批记录内留出，不代替独立现场精度验收。

## 3. 共享库封装

### 3.1 输入与结果

引擎接收已经标准化的 `base6_single_native4s_flat_v1`，batch=1、小端 float32、共 27683 个值。偏移以 float 为单位：

| 分支 | 形状 | 偏移 | 长度 |
|---|---|---:|---:|
| TF | `[8,64,48]` | 0 | 24576 |
| PSD | `[3,769]` | 24576 | 2307 |
| 振动统计 | `[12]` | 26883 | 12 |
| 姿态 | `[8]` | 26895 | 8 |
| 快状态 | `[6,40]` | 26903 | 240 |
| 慢状态 | `[9,60]` | 27143 | 540 |

以 [fault_engine_api.h](../host/common/fault_engine_api.h) 为唯一 ABI 定义，不重新声明不兼容的结构体。实现以下 `extern "C"` 导出，异常必须在库内转换为错误码和有界错误文本：

| 符号 | 实现要求 |
|---|---|
| `mlk_fault_abi()` | 返回 `MLK_FAULT_ENGINE_ABI=1` |
| `mlk_fault_create(root,backend,error,capacity)` | 校验资产、创建单一持久上下文；后端 1 为 FP32 CPU，2 为四卷积 NPU 混合；失败返回空指针 |
| `mlk_fault_predict(context,input,count,result,error,capacity)` | count=27683、输入有限、`struct_size=32`；单窗前向和解码，返回实际后端与耗时，不读取 test 标签或参考结果 |
| `mlk_fault_destroy(context)` | 等待在途调用结束，再释放图、缓冲、运行时与 CMA；允许完整重建下一实例 |

有效结果使用五类索引 0..4 和所选等级；无效结果清 `valid`，类别/等级/置信度为 -1。错误不能返回有效正常。每个上下文在工作线程串行调用；UI 线程不构图、不执行推断、不强制释放在途 NPU。

### 3.2 已验证代码的提取边界

复用 `Weights`、`Cnn`、`NpuGraph`、`head`、`decode` 及配套 CMA/缓存同步逻辑。将 CLI `main` 拆为初始化、单窗前向和销毁；去除 360 窗读取、参考对照、逐窗 CSV、审计捕获和正常路径的图/profile 写盘。诊断功能保留在独立检查程序，不每次由 Qt 拉起 `fault_test` 子进程。

后端 2 固定采用 `hybrid_split`：四个仅允许 Alnpu 的 Conv3×3 图共用一个 runtime/allocator，CMA 输入输出持久复用；每层后的 ReLU/MaxPool、其余分支与解码在 CPU。ReLU 以 UINT8 零点 128 截断；Signed32 bias、空间 padding、权重量化尺度及舍入保持已验证表达。

当前配套库下连续 Conv/ReLU/MaxPool 的融合 ReLU 数值不正确，`hybrid` 已禁用；共享库不能恢复该模式或改用自动 CPU 回退。后端加载失败应上报原因，由面板明确选择 CPU。四卷积计划的 28 组实际输入输出核验最大差 1 LSB，最终 CNN 相对理想量化参考最大差 5 LSB；共享库验收须同时检查原始输出和最终判定。

初始化次序为权重/阈值/尺度 → CMA 会话 → runtime → 四个卷积图；销毁逆序。当前独立程序 CMA 稳态为 360448 字节、退出为 0，共享库必须重新验证重复创建/销毁，不能仅引用 CLI 成绩。

## 4. 预处理资产与运行包

### 4.1 预处理格式转换

运行包生成器应把冻结训练缓存的 `preprocess.json`、`config.yaml` 转为 [FaultPreprocessor::loadAssets](../host/ps-local/src/faultpreprocess.cpp) 接收的格式。离线包内原始训练资产不保证与该格式直接兼容。转换只改变表示，不重新拟合标准化、水平参考或频带。

| 字段 | 必须导出的内容 |
|---|---|
| `schema` / `preprocess` | `mlk.fault.preprocess.v1` / `base6_native_blocks_short_context_v2` |
| `frequencies` | `bands=64, tf=193, psd=769, maxHz=600` |
| `bands.weights` | 训练冻结的 `[64][193]` 频带权重 |
| `norm.tf.mean/std` | 各 512 项，按 8×64 顺序展平 |
| `norm.psd.mean/std` | 各 2307 项，按 3×769 顺序展平 |
| `norm.stats.mean/std` | 各 12 项 |
| `norm.pose.mean/std` | 各 5 项；覆盖率/有效位/年龄不重复缩放 |
| `norm.fast.mean/std` / `norm.slow.mean/std` | 分别各 6 / 9 项，保持无效位及年龄语义 |
| `pose.reference` | 训练冻结的三轴水平重力参考 |
| `quality` | 冻结的 `minBlocks=12,minBlockSamples=64,minVibrationRateHz=1600,tfRatio=0.45,fastRatio=0.75,slowRatio=0.60,poseAgeMs=1500` |

生成时拒绝缺项、非有限数、非正标准差及形状不符；不依赖 C++ 加载器的默认值补齐缺失资产。用原生记录在 Python 和 C++ 两侧构造相同窗口，逐分支对照原始特征、标准化、质量拒绝和最终 27683 个值；只比较离线缓存无法覆盖实时预处理。

## 5. 构建与板端部署顺序

构建所需仓库文件、厂商 SDK、完整命令与交付文件位置见
[故障模型构建与交付](../host/ps-local/fault-inference/BUILD.md)。

1. `host/ps-local/fault-inference/` 已实现引擎、检查程序与运行包生成器：`engine/fault_engine.cpp` 用 `-fPIC -shared` 导出四个 C 符号，`tools/build_runtime.py` 由离线包生成 `mlk.fault.runtime.v1` 目录，`build_arm.sh` 交叉编译共享库与检查程序。CPU 后端复用已验证的源码、权重与解码规则；设置 `ARMNN_ROOT` 时同时编译四卷积 NPU 后端（四个仅允许 Alnpu 的独立图）。
2. 在 Ubuntu 使用与离线板测相同的工具链和配套库；现有环境变量如下，随后由新的共享库构建入口使用：

   ```sh
   export CXX=/home/uisrc/uisrc-lab-anlogic/tools/aarch64-linux/bin/aarch64-linux-gnu-g++
   export ARMNN_ROOT=/home/uisrc/f3p-rul-probe/vendor/armnn
   ```

3. 使用独立检查程序验证共享库全量 test 的 CPU/NPU 输出和至少两轮加载/释放。通过后封装最终 SHA-256 清单；Qt 应用可通过现有 [build_arm_app.sh](../host/ps-local/build_arm_app.sh) 构建，remote-pc 按其 [README](../host/remote-pc/README.md) 构建。
4. 板端先停止诊断和 RUL 回放，再停止 `S99qtapp`。备份现用应用及模型版本，部署新应用与运行包。[stage_ps_local.sh](../platform/flash/stage_ps_local.sh) 在设置 `MLK_FAULT_ROOT` 时调用 [stage_fault.sh](../platform/flash/stage_fault.sh)，核对六项 SHA-256 与 AArch64 架构后按版本暂存，保留 `mlk_fault.previous`；评估集单独部署到 `/data/fault-eval`。
5. 保留当前配套内核、DTB、驱动、码流与 `/opt/armnn_lib/lib`。当前 SD 已通过离线测试，不需要为模型替换重新烧录；只更新用户态应用及模型目录。设备为 `/dev/hard_npu`、`/dev/soft_npu`、`/dev/cma_mem`；使用硬 NPU 时厂商库仍要求软 NPU 设备可打开。采集需 `/dev/pl_ctrl`，HDMI 需 `/dev/fb0`，声光需 PL ID `0x504c0103`。
6. 正式运行包就绪后，可从串口执行以下命令启动应用，环境值由启动脚本继承；实际开始推断仍需点击本地面板的“开始诊断”：

   ```sh
   /etc/init.d/S99qtapp stop
   MLK_INFERENCE_MODE=fault MLK_FAULT_ROOT=/opt/mlk_fault /etc/init.d/S99qtapp start
   ```

   该环境设置只作用于此次启动。开机路径取自 `/etc/default/mlk-inference`，进程显式环境值优先；`MLK_INFERENCE_MODE=fault` 只记录推理模式，不触发自动诊断。数据集回放由面板按钮或远端指令发起。不得同时运行独立测试 CLI 与上位机 NPU 推理。

## 6. 上位机操作与结果流

本地「故障诊断」面板分为两个模式。「实时诊断」填写正式运行包目录，后端默认「CPU+CNN NPU」，可临时切到 CPU 核对数值；「数据集评估」填写运行包目录、评估集目录与后端，回放冻结特征并按真值统计分类与分级准确度、单窗处理速度。工作线程加载预处理与共享库，形成完整四秒且质量合格的窗口后输出结果，之后按两秒步长提交最新窗口。停用或切换模型前点击“停止”并等待释放。

数据路径为 `DriverSource → KLocalWindow stamped Frame → FaultInputAdapter → FaultWorker → FaultPreprocessor → FaultRuntime → libmlk_fault.so → FaultLiveController`。转速经 `onSpeedSample` 独立接入，不能只监听波形入口；XYZ/温度/电流/转速的物理单位、时间、缺块及标度处理见[实现说明](../host/实时故障诊断实现.md)。

界面显示唯一具体故障、所选等级、模型分数、质量原因、实际后端与预处理/推断耗时。无效、过期或引擎错误显示 N/A；不能显示为健康。`confidence` 是 softmax 分数，不能表示已校准的发生概率。四秒采集等待、预处理、网络前向、确认窗口和网络发送分别计时，3.988 ms 不能作为端到端告警延迟。

模型告警采用 0.80 试用门槛：低分异常仅显示候选，清除模型告警与累计确认，不生成工单；完整状态与日志仍保留原始分数。达到门槛后仍须连续两窗同类别、同等级；正常恢复仍为三窗。该门槛需独立实采标定，可能漏掉低分真故障，也不能排除高分误判；冻结数据集准确度不应用该门槛。传感器独立上下限告警保持原有规则。

确认后的故障由控制器写入 `mlk.fault.order.v2` 结构化工单并驱动现有声光。五类结果通过诊断 API 2 和 UDP v6/type8 传递，remote-pc 必须使用支持该消息的构建；RUL v3 和 API v1 仅保留原有语义。两端类别顺序、等级和失效状态以[字段级接口](../host/故障诊断模型接口需求.md)为准，不把五类编号直接写入粗分类 `class`。

## 7. 接入验收与回退

| 顺序 | 检查内容 | 通过条件 |
|---|---|---|
| 1 | 参数与资产身份 | checkpoint、折叠权重、阈值、尺度可追溯；清单完整，缺失和篡改均拒绝加载 |
| 2 | 共享库 CPU | 360 窗原始 9 维输出满足 `1e-4+1e-4×abs(reference)`，分类/分级与冻结 FP32 一致 |
| 3 | 共享库 NPU | 与同板 v2 的原始输出及判定对照；四图 Alnpu、实际 workload、硬 IRQ 和逐层整数证据齐全，不静默 CPU 回退 |
| 4 | 生命周期 | 至少两轮创建/全量推断/释放，CMA 稳态无增长，退出回到基线；中止、重启及加载失败不残留上下文 |
| 5 | 原生预处理 | 相同真实块在 Python/C++ 的分支特征、标准化、质量与最终张量一致，另覆盖缺块、重复块、时间跳变、标度变化 |
| 6 | 双端与告警 | 具体故障/等级、窗口、时效、工单及声光一致；断网、过期、停止、旧 run 晚到结果正确失效 |
| 7 | 共存与性能 | HDMI、采集 DMA 与推理并行，记录丢块、CMA、预处理/总延迟、长时运行；独立现场精度另行验收 |

接入失败先停止任务并等待释放，再切回上一应用和运行包版本，恢复服务。显式选择 CPU 只替换推理后端，不能绕过包身份或输入质量检查。驱动调用未返回时不得并发销毁图或启动另一个模型实例。
