# 采集记录、波形回放与训练接口

本文规定 ps-local / remote-pc 的四传感器记录、加密文件、异常区间标签、故障关联及训练 CSV 导出。文件契约为 MLKC 加密外层 v1、采集载荷 v2（兼容 v1）/ MLKL v1，标签 API 为 v1；实现入口为 [capturestore](../host/common/capturestore.h)、[回放窗口](../host/common/capturedialog.h)和[命令行工具](../host/common/capturetool.cpp)。

## 1. 记录与回放

| 入口 | 行为 |
|---|---|
| 顶栏「记录」 | 保存启用期间各通道收到的全部样本，按配置的 10 / 30 / 60 / 300 s 分段，默认 60 s；停止时保存末段。PS 开始内置故障诊断时同步开启记录，需已设置记录口令 |
| 顶栏「回放」 | 打开独立二级窗口，默认列出与异常标签重叠的记录；可切换全部记录、故障清单、MLKF 兼容记录 |
| 回放窗口记录清单 | 单击条目，或选中后按回车，才解密并加载波形 / 数据；悬停、滚动、方向键浏览和清单刷新不切换记录；重复点击已加载条目复用当前数据 |
| 回放窗口「四传感器波形」 | 同一时间轴显示温度、电流、转速、振动 XYZ；支持播放 / 暂停、位置和显示区间长度 |
| 回放窗口「对齐数据」 | 查看与 CSV 相同的七个物理量、时间戳和有效位；缺失值显示不可用 |
| 回放窗口「标注当前区间」 | 保存当前显示区间的标签、异常标志、标注来源和说明 |
| 回放窗口「解密导出 CSV」 | 导出所选完整记录，间隔由「CSV 间隔」指定，默认 1 ms；输出为明文 |
| remote-pc「记录列表」 | 列出本机记录和故障工单；双击工单打开详情、关联记录选择、波形和数据表 |
| 配置 · 记录管理 | 「清理所有记录」确认后删除当前目录全部 `capture_*.mlkc` / `fault_*.mlkf`；「删除选定记录」在文件选择器中多选后删除。两者都保留工单、标签、寿命记录 |

ps-local 默认目录为 `/data/mlk_f3p`，remote-pc 为 Qt 应用数据目录下的 `records/`，均可在配置修改。两端记录口令及目录独立。采集 MLKC / 标签 MLKL 始终加密；配置中的寿命结果加密开关不关闭采集加密。

现场四传感器回放与模型面板的数据集寿命回放独立。回放读取单独的数据对象，不更改实时看板或模型输入，后台采集与记录继续执行。

打开回放或切换筛选时等待明确选择记录。新分段落盘及「刷新清单」仅更新条目与标签，保留当前记录、播放位置和清单滚动位置；当前条目被清理或不再符合筛选时清空显示，等待再次选择。remote-pc 记录列表中的明确打开操作可直接加载指定工单或记录。

### 1.1 数据完整性与时间

| 项 | 规则 |
|---|---|
| 通道 | 温度、电流、转速、振动 X/Y/Z；逐块保存电流 / 转速 signed32、温度 / 振动 signed16、原生速率、样本数、序号和计数 |
| 记录粒度 | 各通道独立采样节奏，不将整个区间最后一个温度复制到原始记录，不补造离线通道 |
| 温度单位 | 默认 0.1 ℃/LSB，经记录中的 `k/b` 标定 |
| 电流单位 | 数据源已转换为 mA，记录固定 `k=1,b=0`，避免重复标定 |
| 转速单位 | 面板与记录固定 0.1 rpm/LSB、零偏 0；使用 signed32，不施加 ±3276.7 rpm 限制；PS 按安装方向取反，PC 与记录保留同一方向；旧记录保留原有数值 |
| 振动单位 | 默认 0.0039 g/LSB，三轴共用振动标定 `k/b` |
| 首样本 UTC | PS 发布时以读取完成的 UTC 减去 `(n-1)/rate` 估算；单点为发布 UTC；PC 沿用收到的首样本 UTC，分包按样本偏移推进 |
| 块内时间 | `first_sample_us + floor(i × 1000000 / rate_hz)`；PL 事件时间与 Linux 未硬同步，精度不等于微秒级采样同步 |
| 区间 | `startUs=min(记录开始时间, 所收块首样本时间)`，`endUs=max(保存时间, 各块末样本时间+1)`，半开区间；不同分段估算区间可能有重叠 |
| 分段边界 | 按应用收到样本的分组边界保存，Qt 定时器和读数时间可能有抖动；CSV 在所选记录内使用严格固定时间间隔 |
| 全量范围 | PS 保存数据源成功发布的全部样本，包括 DMA 振动；PC 保存成功收到的全部样本；PL 环覆写、设备采集失败及 UDP 丢失的样本不能恢复 |
| 质量核对 | 原生 CSV 保留 `seq/count/rate_hz`；DMA 丢块和网络丢包仍按实时指标核对。有效位仅表示前值保持未过期，不保证区间无丢样 |
| 容量 | 每段最多 2000000 个标量或 100000 个块，到限提前分段；文件上限 64 MiB |
| 保存失败 | 原子提交，失败保留内存段并提示；缓冲达到上限后停止记录；再次开启时先重试待保存段。进程崩溃或断电未提交段不可恢复 |

记录目录、口令或标定改变时先按该段原配置保存，再开始新段。按保留月数、文件数上限与最低剩余空间清理最旧 MLKC；这些清理规则也适用于异常记录，训练数据应及时另存。MLKF / 寿命结果 / 工单各自使用原有策略。

## 2. MLKC / MLKL 加密外层

`capture_<startUs>_<endUs>_<uuid>.mlkc` 保存采集数据；同目录的 `capture_labels.mlkl` 保存标签数组。文件名区间只供索引，解密后元数据为准。算法为 AES-256-GCM，口令经 PBKDF2-HMAC-SHA256 派生 32 字节密钥，100000 次迭代；每次保存生成独立 16 字节 salt、12 字节 nonce。[OpenSSL GCM 接口](https://docs.openssl.org/1.1.1/man3/EVP_EncryptInit/)定义认证标签及附加认证数据处理。

| 偏移 | 长度 / B | 字段 |
|---|---|---|
| 0 | 4 | 采集为 ASCII `MLKC`，标签为 ASCII `MLKL` |
| 4 | 1 | 版本 `1` |
| 5 | 1 | 加密标志 `1` |
| 6 | 16 | PBKDF2 salt |
| 22 | 12 | GCM nonce |
| 34 | 16 | GCM 认证 tag |
| 50 | 剩余 | 密文；长度与明文相同 |

偏移 `[0,34)` 的整个头作为 GCM AAD。口令错误、头或密文被篡改时拒绝读取。采集内容、元数据和标签均加密；文件名暴露区间和随机 ID。文件采用原子替换，权限为本机所有者读写。两端沿用各自配置的记录口令，修改口令不会重加密既有文件；读取既有文件须使用保存时的口令。

### 2.1 MLKC 解密载荷

数值均为小端，`QDataStream::Qt_5_12`；int16 样本直接写入，不使用 Qt 向量序列化头。

| 顺序 | 字段 | 类型 / 长度 | 含义 |
|---|---|---|---|
| 1 | metadata_bytes | uint32 | JSON UTF-8 长度，最多 8192 B |
| 2 | metadata | metadata_bytes | 下表元数据 |
| 3 | block_count | uint32 | 1..100000 |
| 4 | blocks | 重复 block_count 次 | 各块头及原始样本，按应用接收顺序 |

| JSON 字段 | 类型 | 含义 |
|---|---|---|
| schema | string | `mlk.capture.v2`；读取兼容 `mlk.capture.v1` |
| id | string | UUID，无花括号 |
| source | string | `ps-local` / `remote-pc`；显式演示源为 `remote-pc-demo`，源切换时另起分段 |
| startUs / endUs | 十进制字符串 | UTC epoch µs 半开区间，字符串避免 JSON 数值精度丢失 |
| timebase | string | `estimated_utc_first_sample` |
| channels | 4 个对象的数组 | 按温度 / 电流 / 振动 / 转速排列，每个对象含数值 `k,b`，物理量=`raw*k+b` |

| 块头偏移 | 长度 / B | 字段 | 含义 |
|---|---|---|---|
| 0 | 1 | channel | 0 温度、1 电流、2 振动、3 转速 |
| 1 | 1 | axes | 1 或 3；仅振动允许 3 |
| 2 | 2 | rate_hz | uint16，非零 |
| 4 | 4 | seq | uint32，应用块序号 / PC 收到的通道包序号 |
| 8 | 4 | count | uint32，数据源计数；仅作诊断，不作为统一时间轴 |
| 12 | 8 | first_sample_us | uint64，首样本 UTC |
| 20 | 4 | n | uint32，1..65536，每轴点数 |
| 24 | n × axes × width | samples | 载荷 v2：电流 / 转速 width=4、signed32；温度 / 振动 width=2、signed16。载荷 v1 全部 width=2。单轴为 n 点，三轴依次完整 X、完整 Y、完整 Z |

### 2.2 MLKL 解密载荷

UTF-8 JSON 数组，每项为 §4 的标签对象，最多 100000 项。按标签 `id` 更新；写入使用目录锁和原子提交。不能用空标签文件覆盖无法解密的标签库。

MLKF v1 的 4 通道文件缺少通道 schema 与逐样本时间，兼容界面只预览原始 CH0–CH3，最多 10000 行；不能恢复未存入的电流和转速，也不能转换成完整七字段训练数据。

## 3. 解密为 CSV

### 3.1 构建工具

从仓库根执行，主机 Qt 5 / OpenSSL 环境与两端应用相同：

```sh
nix develop ./host
mkdir -p /tmp/mlk-capture-tool
cd /tmp/mlk-capture-tool
qmake /home/lfour/Projects/MLK-F3P-DR1M90G/host/common/capturetool.pro
make -j4
./mlk-capture --help
```

`host/ps-local/build_arm.sh` 同时生成 ARM 工具 `host/ps-local/build-arm/capture-tool/mlk-capture`；`platform/flash/stage_ps_local.sh` 将其暂存到 `/opt/qt_play/mlk-capture`。板端命令前设置 `LD_LIBRARY_PATH=/opt/qt_play/qt_lib/lib`。复制至 PC 的 `.mlkc` / `.mlkl` 可用主机工具和原口令直接读取，无须模型运行包。

### 3.2 命令

在构建目录执行；`record.mlkc` 替换为实际文件，`/tmp/record.pass` 保存对应记录口令。工具从口令文件读取 UTF-8，剥离末尾一次 LF / CRLF，口令不放入命令行参数：

```sh
umask 077
read -r -s -p '记录口令: ' capture_password
printf '\n'
printf '%s' "$capture_password" > /tmp/record.pass
unset capture_password

# 查看解密元数据及六路原生样本计数
./mlk-capture --password-file /tmp/record.pass --input record.mlkc --inspect

# 七字段等间隔 CSV，默认 1000 µs = 1 ms，可显式选择 20000 µs = 20 ms
./mlk-capture --password-file /tmp/record.pass --input record.mlkc \
  --csv training.csv --step-us 1000

# 保留每一个原生采样点及原始码，不进行等间隔重采样
./mlk-capture --password-file /tmp/record.pass --input record.mlkc \
  --native-csv native.csv

# 查看本机记录 / 标签，标签可单独用于训练集划分
./mlk-capture --password-file /tmp/record.pass --directory /path/to/records --list
./mlk-capture --password-file /tmp/record.pass --directory /path/to/records --labels
```

等间隔 CSV 列序固定：

```csv
timestamp_us,temperature_c,current_ma,speed_rpm,vibration_x_g,vibration_y_g,vibration_z_g,vibration_magnitude_g,valid_mask
```

| 字段 | 含义 |
|---|---|
| timestamp_us | UTC epoch 微秒；行间隔为 `--step-us`，允许 1000..1000000 µs |
| temperature_c | 温度 ℃ |
| current_ma | 电流 mA |
| speed_rpm | 有符号转速 rpm |
| vibration_x_g / y / z | 振动三轴 g |
| vibration_magnitude_g | `sqrt(x²+y²+z²)`，三轴全部有效时计算 |
| valid_mask | 十进制位掩码，bit0..6 依次对应七个传感器字段；127 表示七字段均有效 |

对齐规则：各列只使用时间不晚于该行的最近样本，采用前值保持，不使用未来样本回填。温度最长保持 6 s，电流 / 转速 2 s，振动各轴 500 ms；超过时限或通道缺失时，该列留空、对应有效位清零。标签不由数值阈值自动生成。网格与样本之间不做低通或抗混叠；降低 CSV 频率会丢失高频细节，频谱和原生训练宜使用 `--native-csv`。每次等间隔导出最多 1000000 行。

原生 CSV 列为 `timestamp_us,channel,raw_x,raw_y,raw_z,value_x,value_y,value_z,rate_hz,seq,count`。非振动通道仅使用 x 列；缺失 Y/Z 留空。行顺序与存储块顺序一致，跨通道训练前可按时间排序。温度 value 为 ℃、电流为 mA、转速为 rpm、振动为 g。

CSV 是显式解密后的明文文件；工具不改写源记录。七字段导出用于统一时间轴输入，原生导出用于保留采样率和全部原始码，标签通过 `--labels` 另行导出。

## 4. 模型 / 标注 API v1

“异常”由模型发布或人工标签指定，采集程序不内置训练类别。模型只输出 RUL 回归时不产生异常标签。标签的 `abnormal=true` 且区间与记录重叠时，记录自动列入异常回放清单；标签可以先于分段落盘，也可以对已有记录补标。

### 4.1 本地连接与操作

| 项 | 规则 |
|---|---|
| ps-local socket | `/run/mlk-capture.sock`；可用 `MLK_CAPTURE_PS_SOCKET` 覆盖 |
| remote-pc socket | `$XDG_RUNTIME_DIR/mlk-capture-pc.sock`，以 Qt RuntimeLocation 为准；可用 `MLK_CAPTURE_PC_SOCKET` 覆盖 |
| 权限 | 仅应用运行用户访问；一连接一请求，一行 UTF-8 JSON，以 LF 结束 |
| 限制 | 请求不超过 1000 B，2 s 接收超时，最多 8 个连接 |
| 成功 | `{"ok":true,...}` |
| 失败 | `{"ok":false,"error":"..."}`；不修改已有标签 |

| op | 请求字段 | 响应 |
|---|---|---|
| list | `api:1,op:"list"`，可选 `abnormalOnly:bool,offset:int,limit:int`；默认 offset=0、limit=100，limit=1..1000 | `records` 数组与 `total`；每项含 id、startUs、endUs、abnormal、异常 labels |
| labels | `api:1,op:"labels"` | `labels` 完整数组 |
| label | `api:1,op:"label",label:{...}` | 按标签 id 新增或更新，允许把 abnormal 改为 false 复核 |

Socket 仅提供列表及标签操作。CSV 解密通过界面或工具执行；不经本地 API 任意指定明文输出路径。

### 4.4 模型标签来源（v2 工单）

`mlk.fault.order.v2` 工单确认后由上位机写入标签：`label` 为具体故障名与等级，例如 `mount_tilt_grade_2`；`author` 为 `model:bench_fault_single_v1`；`note` 为工单 `message`，按 UTF-8 字符边界截断到 512 字节。有合法诊断窗口时，`startUs/endUs` 取 `diagnosis.startUs/endUs`，`scope=model_window`，另存 `eventUs=faultTimeUs`、`classIndex`、`grade` 和完整 `diagnosis`。窗口标签表示模型对该窗口的判定，不声明各采样时刻均有故障。缺少窗口的工单保留事件点；无 `diagnosis` 的 v1 工单仍生成 `class_<class>_grade_<grade>` 与 `author=model`。

模型标签是预测，不是人工监督真值；训练集划分使用标签时需与人工复核结果区分。标签不改变记录内容，也不按数值阈值自动生成。

### 4.2 标签对象

| 字段 | 类型 | 约束 |
|---|---|---|
| api | integer | 1 |
| id | string | 1..64 字符，`A-Z a-z 0-9 _ -`，稳定标签 ID；同 ID 更新内容 |
| startUs / endUs | 十进制字符串 | UTC epoch µs，startUs>0，endUs>startUs，最大 253402300799999999 |
| abnormal | boolean | true 列入异常清单；false 可保存健康、复核或撤销异常标签 |
| label | string | 非空分类名称，UTF-8 最多 128 B；词汇由训练流程定义 |
| author | string | 标注者 / 模型版本，UTF-8 最多 128 B |
| note | string | 说明，UTF-8 最多 512 B；同时受请求总长度限制 |

示例文件 `/tmp/label.json`：

```json
{"api":1,"id":"bearing-0001","startUs":"1700000000000000","endUs":"1700000060000000","abnormal":true,"label":"bearing_outer_race","author":"model-v1","note":"人工复核区间"}
```

在线提交与查询，从仓库根执行：

```sh
python3 - <<'PY' > /tmp/capture-label-request.json
import json
with open('/tmp/label.json', encoding='utf-8') as f:
    label = json.load(f)
print(json.dumps({'api': 1, 'op': 'label', 'label': label}, ensure_ascii=False))
PY
python3 host/common/capture_api.py --socket /run/mlk-capture.sock < /tmp/capture-label-request.json
printf '%s\n' '{"api":1,"op":"list","abnormalOnly":true}' | \
  python3 host/common/capture_api.py --socket /run/mlk-capture.sock
```

离线操作相同标签库：

```sh
./mlk-capture --directory /path/to/records --password-file /tmp/record.pass \
  --label-json /tmp/label.json
```

模型运行时分类入口仍为[声光告警与模型故障 API](声光告警与模型故障API.md)。产生工单时，应用使用工单 ID 和 `[faultTimeUs,faultTimeUs+1)` 自动写入标签，名称为 `class_<class>_grade_<grade>`，author=`model`；这只表示事件所在分段，不扩张为未经定义的故障前后区间。需要更长区间或自定义训练分类时，通过本节标签 API 发布明确的 startUs / endUs。

### 4.3 双端故障清单

PS 的工单先在本机加密保存，再通过已配对的加密链路发送。PC 保存工单及对应标签后确认。工单选择后，回放窗口列出本机与诊断窗口相交的全部采集分段；无窗口的历史工单按 `startUs <= faultTimeUs < endUs` 关联。选中后显示四传感器波形与数据，模型窗口以阴影及具体故障、等级标出。无关联记录时显示原因并禁用导出，不以当前实时波形代替故障现场。

PS 在确认故障、停止诊断和打开回放前保存当前记录段，因此回看不必等待默认分段定时器。
操作顺序为：配置记录口令 → 开始诊断 → 顶栏「回放」→「故障清单」选择工单，或在默认「异常波形」中选择带标签的记录；跨段窗口通过关联记录下拉框切换。停止诊断后记录保持开启，按需从顶栏单独停止。

### 5.1 诊断记录保留策略

实时诊断的「仅保留异常波形」默认关闭，并保存最近一次启动时的选择。验证模型时保持关闭，
包括被模型误判为正常的真实故障样本在内，全部原始记录均按常规存储保留规则保存。

日常运行启用该选项后，仅登记本次诊断中新提交的 MLKC 分段。完整区间被有效正常窗口覆盖，
且已越过前置上下文保护范围的旧分段才自动清理。异常候选、已确认故障、数据不足、
引擎错误或物理阈值告警窗口保护前后各 10 秒；按整段保留，实际范围可能更长。
历史文件、启用前的手动记录、未完全判定正常的分段及最近的上下文不会据此删除。
人工或模型异常标签覆盖的分段同样保留；标签库无法读取时停止自动清理并提示。
时间基准倒退时保留旧时基文件；该策略不修改工单或标签，也不把不可用判为正常。

验证已有故障的识别可在植入故障后启动诊断；需要故障发生前的波形时，先启动记录和诊断，
取得正常基线后再植入故障。启动前未采集的数据不能由前置上下文策略补回。

两端独立开启记录、保存自己的数据。工单传输不包含完整采集文件；PC 未开启记录、链路中断或记录已清理时，需将 PS 保存的 MLKC 与所需标签库复制后，使用保存时的口令查看 / 导出。不同口令的标签库不能直接覆盖合并。模型 / 人工通过某端标签 API 添加的自定义标签仅保存于该端；模型工单事件标签随工单双端生成。

## 5. 开发机与板端验证

开发机测试见 [测试规程](../host/tests/README.md)。无硬件验证覆盖文件认证、原生采样保存、时间对齐、空值、标签提前发布、双端加密通信、工单关联、独立回放及 CSV 导出。实板完整采集率、磁盘写入压力、长时运行与时间精度为待验证，不以模拟输入代替实采证据。

板端验证按顺序执行：

1. 部署构建的 ps-local、`mlk-capture` 及 PC 应用，保留配置和原记录口令。
2. 确认四传感器有有效读数，PC 加密已连接，两端分别开启记录。
3. 跨越至少两个分段后停止，确认各自 MLKC 数量、时间区间及 `--inspect` 六路样本数。
4. 使用对应的真实记录区间提交自定义标签，两端各自核对异常清单。
5. 模型发布测试工单，PC「记录列表」双击，核对工单详情、关联四传感器波形、数据表；使用无对应区间事件核对缺失提示。
6. 导出等间隔与原生 CSV，核对时间、单位、负转速、振动合成、缺失传感器有效位；使用错误口令核对认证拒绝。
7. 在回放窗口开启期间继续采集，确认实时看板、记录和 DMA 丢块指标；连续记录验证磁盘余量及保留策略。

## 6. 单主故障冻结特征评估集

`mlk.fault.evalset.v1` 供数据集评估使用；输入已经过训练侧预处理与标准化，
不经过 MLKC 解密、原生块适配或实时预处理。生成入口为
[`build_runtime.py --eval-output`](../host/ps-local/fault-inference/tools/build_runtime.py)。

| `evalset.json` 字段 | 定义 |
|---|---|
| `schema` | 固定 `mlk.fault.evalset.v1` |
| `model` / `task` | 与运行包相同模型身份 / `bench_fault_single_v1` |
| `inputs` / `index` | `test_inputs.bin` / `test_index.csv`，包内普通文件名 |
| `samples` / `inputFloats` | 索引样本数 / 固定 27683 |
| `classes` | `normal/overload/undervoltage/overtemperature/mount_tilt`，顺序固定 |
| `inputStage` | 固定 `frozen_normalized_features` |

`test_inputs.bin` 按索引顺序连续保存每窗 27683 个小端 float32，文件长度必须为
`samples×110732`；非有限数拒绝推断。`test_index.csv` 为无引号逗号分列：

| 列 | 定义 |
|---|---|
| `sample` | 从 0 递增的输入行号 |
| `window_id` / `window_end_us` | 来源窗口身份 / UTC 微秒窗口结束时刻 |
| `source_sha256` / `feature_sha256` | 原始来源文件 / 特征缓存的 SHA-256，用于溯源 |
| `class_target` / `grade_target` | 人工/数据集真值：类别 0..4；正常 0 级，异常 1..3 级 |
| `reference_class` / `reference_grade` | FP32 冻结参考判定；检查程序用于一致性校验，Qt 准确率只使用真值 |
| `quantized_class` / `quantized_grade` | 离线量化参考判定；不参与 Qt 准确率判定 |

评估报告 `mlk.fault.eval_report.v1` 包括模型、预处理、实际后端、样本数、分类/联合/故障窗
准确率、5×5 类别矩阵、4×4 等级矩阵、逐类联合正确数，以及调用耗时的均值/中位/P95/峰值
和窗/秒。默认保存于评估集目录 `fault_eval_report.json`。该模式不产生告警、工单、标签或
UDP 诊断结果；不替代实采完整链路与独立现场精度验收。
