# 接口冲突与可用性分析（MLK-F3P-DR1M90G）

> 针对本项目方案：**SD 卡启动自定义 Linux + 以太网供网/上位机 + HDMI 本地显示 + 本地存储 + UART/JTAG 串口 + PL 采集 + 工业总线（RS485 转速；CAN 备用）**，明确哪些设备/功能**互斥或抢引脚**、哪些可共存。
> 依据：《MLK_F3P_CZ02_DR1 开发板硬件使用手册》（下称《硬件手册》）各章节、《Linux 出厂系统测试》《Linux 恢复出厂设置》、`DS1200_DR1_Datasheet`。

---

## 0. 本方案用到的接口

| 功能 | 走哪 | 归属 |
|---|---|---|
| 启动介质 | SD(TF) 卡 | PS |
| 供网 / 上位机 | 千兆以太网（PS eth1，可选 PL eth0） | PS / PL |
| 本地显示 | HDMI 1080p60 | **PL（FPGA 直接驱动）** |
| 串口/JTAG 下载 | UART&JTAG 二合一 Type-C | CH342K(PS+PL UART) + 下载器 |
| 数据采集 | 传感器板 → J12（BANK13 / CEP1） | PL |
| 工业总线 | RS485（转速通道，PL 软 UART + DE）；CAN（备用，PS 硬核，I/O 经 PL BANK33） | PL / PS |
| 本地存储 | SD(TF) 卡 / eMMC | PS |
| 远程/4G（比赛加分，可选） | 4G 模块 + SIM | PS（USB） |

## 1. 硬互斥（二选一）

### 1.1 启动模式：JTAG / QSPI / SD / eMMC 四选一
SW1 决定从哪引导（`0=ON,1=OFF`）：JTAG=ON-ON-ON，QSPI=ON-ON-OFF，SD=ON-OFF-OFF，eMMC=OFF-OFF-OFF。`ON-OFF-OFF` 是 SD 启动位，不是 JTAG 位。
→ **互斥的是"启动介质"四选一**：`MIO3/4/5` 只决定 **BootROM 从哪里取启动镜像**，**并不禁用 JTAG 通道**。JTAG 可独立用于 PL 配置（`Program FPGA`）与 PS 调试；所以 **SD 启动运行 Linux 时，JTAG 仍可用于在线配置 PL，或用于固化 QSPI（`ProgramFlash`）**——但这一步**需在实机上验证一次**（不同厂商对在线配置是否要求特定启动模式有差异）。SD 启动下在线配置 PL 的步骤与限制见 [`PS-PL开发流程.md`](PS-PL开发流程.md) §5.3.1；QSPI 固化仍需 `ON-ON-ON` + `ProgramFlash`。
> 《硬件手册》五、模式开关；《Linux 恢复出厂设置》五、模式开关；《Linux 出厂系统测试》五、模式开关。

### 1.2 USB 分支：HOST 侧（WiFi+4G+2×USB HOST）⟷ OTG Type-C
PS 只有**一路 USB 控制器**（USB3320 PHY，`f8180000.usb`）。它经 **CH442Q** 分到两个方向，用**排针 + 跳线帽**选（**硬件**，非软件）：

| 跳线位置 | 得到 | 同时失去 |
|---|---|---|
| **HOST** | FE1.1S 四路 hub → **板载 WiFi(AIC8800) + 4G 模块 + 2×USB2.0 HOST** | USB2.0 OTG Type-C |
| **SLAVE** | **USB2.0 OTG Type-C**（作 USB device） | WiFi + 4G + 2×USB HOST |

**易误读之处**：

- 互斥的是「**HOST 整条分支**」⟷「**OTG Type-C**」，**不是** "4G ↔ SD"、也不是 "4G ↔ WiFi"。
- **WiFi 与 4G 同属 HOST 侧、可共存**；二者只是形态不同（WiFi = 板载 AIC8800 USB 芯片；4G = 外插模块 + SIM），在"总线归属/冲突关系"上**完全一样**。
- **SD 卡不在这条 USB 上**（走 SDHCI/SDIO），故 **SD 与 WiFi/4G 都不冲突**（见 §1.3、§4）。
- 切换是**物理跳线**，出厂**未接到可控 GPIO** → **不能软件/自动切换**（即"插 OTG 不会自动关 4G"），除非改板 + 内核 role-switch。
- **JTAG 不在这一路**：JTAG 走另一个 **UART&JTAG 二合一 Type-C** → **插 JTAG 不影响 WiFi/4G，无需切换**。

> 《硬件手册》13:USB2.0 接口（"使用排针通过跳线帽切换 CH442Q 的 IN 高低电平来切换 USB 的 HOST&SLAVE"）。

### 1.3 SD / eMMC 与 USB(4G/WiFi) 不冲突
| 设备 | 控制器 | 引脚 |
|---|---|---|
| SD/TF（主槽） | SDHCI `mmc0`（`f8049000.mmc`） | MIO40-45 + MIO47(CD) |
| eMMC | SDHCI `mmc1`（`f804a000.mmc`） | — |
| USB（WiFi/4G/USB口/OTG） | dwc2 `f8180000.usb` | MIO29-39 + MIO46 |

→ 控制器与引脚均不重叠，**SD + 4G/WiFi 可同时使用**（启动日志中 `mmc0/mmc1` 与 `usb1` 即同时在线）。
> 《硬件手册》13:USB2.0 + 14:SD 接口（引脚表）。

### 1.4 AUDIO ⟷ UART&JTAG Type-C（本方案受影响）
音频模块与 UART&JTAG Type-C 共用走线，手册原文：**"使用时下载完程序后需拔出 JTAG&UART 的 TYPE_C 线可实现无噪声，否则会有部分杂音。"**
→ **插着串口/JTAG 线时音频会有杂音**；本方案不用音频，无影响。
> 《硬件手册》21:AUDIO。

### 1.5 预留 TF1 ⟷ eMMC
核心板资料：「1 路 TF 卡接口，一路**预留的 TF1 卡接口（不焊接 EMMC 时可使用）**」。
→ 第二 TF 槽与 eMMC **二选一（不共焊）**。本板已焊 eMMC，TF1 用不了；主 TF 槽与 eMMC 各自控制器，可共存（但**启动仍二选一**）。
> 《硬件手册》主要参数表「SD 卡」行。

## 2. 引脚复用冲突（同一 DR1 PIN 被两个接口占用）

### 2.1 PL 以太网 MDIO/MDC ⟷ KEY1/KEY2
| DR1 PIN | 接口 A | 接口 B |
|---|---|---|
| `K14` | ETHA_MDIO（PL eth0） | KEY1（PL 按键） |
| `J14` | ETHA_MDC（PL eth0） | KEY2（PL 按键） |
→ **用 PL 以太网口，就不能用 KEY1/KEY2**（反之亦然）。本方案若只用 **PS 网口(eth1)**，不涉及；若用 **PL 网口(eth0)** 则牺牲 K1/K2。
> 《硬件手册》12:以太网（PL 侧表）＋ 17:LED&KEY（按键表）；原理图 `P13_LED&KEY`：`B35_L20P_K14→KEY1`、`B35_L20N_J14→KEY2`。
> 核对提示：厂家 `08_框图及pinlist/MLK-F3P/按钮-LED-UART管脚定义表.xlsx` 把 KEY1/KEY2 写成 `K19`/`J19`，与该原理图页和《硬件手册》§17 **矛盾**。**以原理图球号（K14/J14）为准**——写约束前用球号核对，不使用文档里的 BANK/信号名。

### 2.2 PS 以太网复位 ⟷ LED5
| DR1 PIN | 接口 A | 接口 B |
|---|---|---|
| `MIO51` | PS_ETH_RST_B（PS eth1 复位） | LED5（PS 端 LED） |
→ **用 PS 网口就占 MIO51，LED5 不可用**（反之）。本方案用 PS 网口 → LED5 放弃。
> 《硬件手册》12:以太网（PS 侧表）＋ 17:LED&KEY（LED 表）。

> 其余接口（HDMI / CAN / RS485 / AUDIO / CEP1 / FEP / I2C）的引脚表**彼此不重叠**，见 §4。

## 3. PL IO 预算（上限）

DR1M90GEG400 为 **126 单端 IO / 60 对差分**（`DS1200` 选型表）。板上 PL 接口合计远超此数：

| PL 接口 | 大致信号数 |
|---|---|
| FEP | 48 IO / 24 对差分 |
| GPIO/CEP（J12） | 24 IO / 12 对差分 |
| PL 以太网 eth0 | 15 |
| HDMI | 4 对差分 + 5 单端 |
| AUDIO | 9 |
| CAN + RS485 | 2 + 3 |
| LED×4 + KEY×2 | 6 |

→ **不可能全部同时使用**，必须在 PL 设计里取舍。
本方案实际用：**CEP1 采集(24) + RS485(3) + HDMI(14) + （可选）PL eth0(15) ≈ 56** → 够用。
> 《硬件手册》主要参数表、19:FEP、20:GPIO、15:HDMI、18:CAN&RS485。

## 4. 互不冲突、可共存（本方案的核心组合）

| 组合 | 结论 | 依据 |
|---|---|---|
| **HDMI + CAN + RS485 + 采集(CEP1)** | 可共存：引脚表不重叠，可同时 | 硬件手册 §15/§18/§20 引脚表 |
| **PS eth1 + PL eth0** | 可共存：两个独立 PHY（YT8531） | §12 两张引脚表 |
| **PS UART + PL UART + JTAG** | 可共存：同一 Type-C，CH342K 双通道 + 下载器 | §11 |
| **SD 卡 + eMMC 同时在线** | 可共存：各自控制器（mmc0/mmc1），但**启动二选一** | 启动日志 + §五模式开关 |
| **SD 卡 + 4G/WiFi** | 可共存：不同控制器（SDHCI vs USB）、引脚不重叠 | §1.3 / 引脚表 |
| **本地 SD 存储 + 千兆上传 + 4G 远程/OTA** | 可共存：存储走 SD，上传走网口/4G | §12/§13/§14 |
| **插 JTAG 线 + 用 WiFi/4G** | 可共存：JTAG 走 UART&JTAG Type-C，与 USB 分支无关 | §1.2/§11 |
| **EEPROM(24LC02) + RTC(DS1337)** | 可共存：共用 I2C（L15/L14），不掉电丢失 | §16 |
| **HDMI 显示 + 网络 + 采集** | 可共存：无电气冲突（HDMI 走 PL，网络走 PS/PL PHY） | §12/§15 |

## 5. 本方案逐项结论

| 功能 | 可用性 | 备注 |
|---|---|---|
| SD 卡启动 | 可用 | SW1=ON-OFF-OFF；eMMC 保留回退 |
| 以太网供网 + 上位机 | 可用 | 本方案选用 PS 网口（硬件手册标 PS eth1，Linux 侧设备树 `eqos0`，接口名以启动枚举为准），仅放弃 **LED5(MIO51)**；PL eth0 未使用，KEY1/KEY2 保留 |
| HDMI 本地显示 | 可用 | 由 **PL 驱动**，占用 4 对差分 + 5 单端；与 CAN/采集不冲突 |
| UART 串口 | 可用 | 与音频互斥（有串口线则音频有杂音） |
| TD/JTAG 固件下载 | 可用 | **启动介质**四选一；JTAG 通道与"是否运行 Linux"**无硬互斥**——SD 启动下 JTAG 仍可在线配 PL（`Program FPGA`，需实测）；固化 QSPI 时才需 SW1 拨 JTAG 用 `ProgramFlash`。**与 4G/WiFi 不冲突**（不同 Type-C）。PL 码流如何进 PL 见 `PS-PL开发流程.md` §5.3 |
| PL 采集（CEP1/J12） | 可用 | BANK13，3.3V |
| RS485（PL，转速通道） | 可用 | BANK33；软 UART + DE，统一 `fpga_top` 已实板验证；与采集 / HDMI 不抢引脚，转速已并入 `soc_hdmi` 合并码流（寄存器窗口 / DMA / 看板均已实板核对），见 [`RS485转速通道接入.md`](RS485转速通道接入.md) |
| CAN（备用） | 可用 | 控制器在 PS（`ARM_Processor_System`），I/O 经 PL BANK33；本方案转速不用 CAN，若用则在 PS 侧（Linux socketcan）驱动 |
| **本地 SD 卡存储** | 可用 | 与 4G/网口/HDMI/CAN 均不冲突 |
| **WiFi（板载）/ 4G（模块+SIM）/ 2×USB HOST** | 可用 | USB 跳线在 **HOST** 侧即可；与 SD/网口/HDMI/CAN 不冲突 |
| **4G 远程运维 / OTA / 数据加密（比赛"高级"项）** | 可用 | 需 4G 模块 + SIM + 跳线 HOST；与本地 SD 存储、千兆上传可同时 |
| 音频 | 受限 | 与 UART&JTAG Type-C 互斥，本方案不用 |
| USB2.0 OTG Type-C | 有条件 | 跳线拨 **SLAVE** 才可用，代价是失去整条 HOST 分支（WiFi+4G+2×USB HOST）；**与 SD 无关** |
| 第二 TF 槽(TF1) | 不可用 | 与 eMMC 不共焊，本板用不了 |

## 6. 设计要点

- **PL 引脚固定**：HDMI、CAN、RS485、AUDIO、LED、KEY、PL eth 的引脚在板上固定，PL 设计里不把这些引脚再分配给采集/其它功能；采集用 **CEP1(J12, BANK13)** 独立引脚。
- **BANK33 含 ADC 引脚**：《硬件手册》§9 提示 BANK33 部分 IO 为 ADC，做高速 IO 需避让；分配 PL 引脚前核对 §8 pinlist / 原理图。
- **电压域**：FEP 与 BANK32 支持跳线改电压（VADJ1）；本方案各接口多为 **LVCMOS33**，确保 VCCO 一致。§22 电源管理。
- **时钟/等长**：两路千兆以太网收发总线与时钟严格等长（§12），PCB 已处理，逻辑侧按 RGMII 时序约束即可。

## 7. 比赛网络 / 远程 / 存储需求可行性

| 评分项 | 硬件需求 | 可用性 |
|---|---|---|
| 中级：本地 SD 卡存储 + 千兆网数据上传 | SD 卡 + 网口 | 可行 |
| 高级：4G 远程监控 + OTA 固件升级 + 数据加密 | 4G 模块 + SIM（USB，跳线 HOST） | 可行，与 SD 不冲突 |
| 领域 5 高级：4G 推送运维工单 | 同上 | 可行，与 SD 不冲突 |

**唯一约束**：用 4G 时 USB 跳线必须在 **HOST** 侧 → 不能用 USB2.0 OTG Type-C（物理互斥，见 §1.2）。比赛未要求 OTG，故无影响。

**要点**：
- JTAG/UART Type-C 可自由插拔，**不影响 4G/WiFi**；
- USB 跳线留 **HOST** → 提供 WiFi + 4G + 2×USB HOST；
- 使用 **OTG** 时跳线拨到 SLAVE，将失去 WiFi + 4G + 2×USB HOST；
- **SD、网口、HDMI、CAN/RS485 不受这条 USB 影响。**
