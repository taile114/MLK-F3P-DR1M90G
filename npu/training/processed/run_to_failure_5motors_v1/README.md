# 五台电机寿命预测数据集

本数据集将 Motor2、Motor3、Motor5、Motor6、Motor7 的稳态 CSV 整理为现有 FKP-DVGT 训练入口可直接加载的输入。文件边界、质量隔离、观测周期、归一化参数和样本来源均有独立清单。原始 ZIP、解压后的 CSV 和 `fkp_dvgt/` 原模型源码保持不变。

特征版本为 `motor_stable23_v1`。频域特征经过数值修正，需要使用本数据重新训练；不能与原 `full_fft_23_features` 的模型权重混用，也不据此声称严格复现论文全部数据处理细节。

## 数据与划分

| 集合 | 电机 | 有效片段 | 模型样本 | 保存形状 |
|---|---|---:|---:|---|
| 训练 | Motor2、Motor3、Motor5 | 570 | 543 | `[543,10,11,23]` |
| 验证 | Motor6 | 193 | 184 | `[184,10,11,23]` |
| 测试 | Motor7 | 174 | 165 | `[165,10,11,23]` |

共解压 537 个稳态 CSV，合计 10,738,200 行原始采样数据。名义 1,074 个片段中保留 937 个，隔离 137 个：136 个受处理记录标注的传感器异常影响，1 个不足 10,000 点。

隔离按整个片段进行，原始 CSV 不删除、不覆写。Motor6_20110822135510.csv 实际有 18,200 行，只保留其完整的前 10,000 点片段，剩余 8,200 点不补零、不形成样本。其余选中 CSV 均为 20,000 行。没有对实际保留片段执行缺失值填补。

电机不跨集合，原始片段不跨电机。验证集和测试集未参与归一化拟合。

## 周期与寿命标签

| 电机 | CSV 数量 | 观测测试批次 | 标签终点约定 |
|---|---:|---:|---|
| Motor2 | 108 | 28 | 第 28 批为零 |
| Motor3 | 103 | 26 | 第 26 批为零 |
| Motor5 | 110 | 28 | 第 28 批为零 |
| Motor6 | 109 | 27 | 第 27 批为零 |
| Motor7 | 107 | 27 | 第 27 批为零 |

`RUL = 最后观测测试批次编号 - 当前批次编号`。单位为剩余观测老化测试批次，模型样本的标签取输入历史最后一个片段所属批次。原始 CSV 没有逐样本 RUL 列或精确失效时间戳，标签是根据运行至失效记录构造的监督目标。最后记录批次置零是数据处理的端点约定，不代表已知精确失效时刻。

这五台电机的文件数量与 [原始研究第 9 页表 1](https://papers.phmsociety.org/index.php/ijphm/article/download/2285/1267) 中的运行至失效样本一致。周期重建使用本地文件时间和处理说明，不能用文件数量除以四替代。

- Motor2 实际存在 28 个日期分组，两批各只有两份记录；本地汇总中的 27 与文件目录不一致，采用 28 个已观测批次。
- Motor6 在 2011-08-22 有五份记录，均属于同一批。
- Motor7 最后一批文件名日期是 2012-06-08，上一批为 2011-12-19。保留原日期，不改名、不把日期间隔换算成额外老化周期。
- 质量隔离后不重新编号周期，不把最后有效片段重新标成零。Motor2 末批的电流片段被原处理说明标注，隔离后该电机有效输入没有 RUL=0 的片段。

## 输入与时间历史

通道顺序固定为：Current 1、Current 2、Current 3、Voltage 1、Voltage 2、Voltage 3、Accelerometer 1、Accelerometer 2、Microphone、Tachometer、Temperature。空格与点两种 CSV 列名统一识别。行号、X_Value、Output Current、Output Voltage、Comment 不进入特征。

采样率为 10,240 Hz，各 CSV 的时间轴通过单调性和总体采样率检查。每个 CSV 内部独立分为不重叠的 10,000 点片段，每段约 0.9766 秒。原始波形不跨 CSV 边界。

每个片段生成 `[11,23]` 特征矩阵。每台电机按观测先后取最近十个有效片段组成 `[10,11,23]`，窗口步长为一个有效片段。十个时间步表示十次有效观测，不表示连续十秒。已知被隔离片段允许形成观测缺口，缺口数量及完整片段编号记录在 `sample_index.csv`；没有合成填补缺失的波形或测试批次。

## 质量隔离规则

`document_quality_masks.json` 保存处理说明中各替换语句的左侧异常区间及原文。每个 CSV 按两个名义 10,000 点槽位与按时间排序的记录对应，异常区间转换为片段隔离规则。没有执行其右侧使用邻近或未来记录替换信号的语句。该映射作为可核查的处理假设保留，不作为原始数据新增的事实。

额外缺失规则：单通道最多十个缺失采样点，且连续缺失不超过三点，使用片段内过去值前向填补；首点缺失、长缺失和超过限额的片段隔离。该版本保留片段没有触发填补。

近恒定通道通过 `峰峰值 <= 1e-10 * max(1,最大绝对值)` 判断，未定义的偏度、峰度及频域特征采用稳定零值。所有保留特征、归一化输入和标签均通过有限性检查。

## 特征定义

先以 float64 提取特征和归一化，再转 float32。设原始片段为 x，去均值片段为 u，点数为 N；单边谱功率 P 为 `abs(rfft(u))²/N²`，内部频点乘二，直流项置零；频率 f 使用 Hz。记加权平均为对 `P/sum(P)` 求和。

| 编号 | 特征 | 定义 |
|---|---|---|
| 1 | 均值 | mean(x) |
| 2 | 样本标准差 | sqrt(sum(u²)/(N-1)) |
| 3 | 方根幅值 | mean(sqrt(abs(x)))² |
| 4 | 均方根 | sqrt(mean(x²)) |
| 5 | 绝对峰值 | max(abs(x)) |
| 6 | 偏度 | sum(u³)/((N-1)·标准差³) |
| 7 | 峰度 | sum(u⁴)/((N-1)·标准差⁴) |
| 8 | 峰值因子 | 绝对峰值/均方根 |
| 9 | 裕度因子 | 绝对峰值/方根幅值 |
| 10 | 波形因子 | 均方根/mean(abs(x)) |
| 11 | 脉冲因子 | 绝对峰值/mean(abs(x)) |
| 12 | 平均谱功率 | mean(P) |
| 13 | 谱功率方差 | mean((P-mean(P))²) |
| 14 | 谱功率偏度 | 三阶中心矩/谱功率方差^(3/2) |
| 15 | 谱功率峰度 | 四阶中心矩/谱功率方差² |
| 16 | 频率重心 | 加权平均(f) |
| 17 | 频率标准差 | sqrt(加权平均((f-频率重心)²)) |
| 18 | 均方根频率 | sqrt(加权平均(f²)) |
| 19 | 频率形状量 | sqrt(加权平均(f⁴)/加权平均(f²)) |
| 20 | 频率比值 | 加权平均(f²)/sqrt(加权平均(f⁴)) |
| 21 | 频率变异系数 | 频率标准差/频率重心 |
| 22 | 频率偏度 | 加权三阶中心矩/频率标准差³ |
| 23 | 频率峰度 | 加权四阶中心矩/频率标准差⁴ |

与恢复版源码的差异包括单边去直流功率谱、谱功率峰度的方差归一化、频率中心矩的总功率归一化，以及退化信号的稳定处理。信号单位沿用 CSV；时间频率特征使用 Hz。详细阈值与顺序见 `preprocessing.json` 和处理工具。

## 归一化与分布

逐传感器、逐特征，仅使用训练电机有效片段的最小值和最大值拟合。验证集和测试集不重新拟合、不强制裁剪到 `[0,1]`。归一化参数保存在 `normalization.npz`，与该特征版本、训练权重配套使用。

验证集约 0.665% 的输入元素超出训练范围，输入范围约为 `[-73.45,4.63]`；测试集约 0.573% 超出训练范围，范围约为 `[-0.178,1.610]`。验证集极小值对应加速度通道均值的分布偏移，作为观测保留。正式训练需要评估跨电机泛化；NPU 量化时应检查输入饱和情况，不能直接假设所有输入都在 `[0,1]`。

## 可训练性验证

原模型源码未修改。使用 CPU PyTorch 2.8.0 验证原 `load_dataset`、模型前向、反向传播、优化器更新、原 `train` 的三轮训练、`best.pt` 重载和测试预测。

- 训练 MSE 三轮依次为 112.503、53.833、52.981。
- 验证 RMSE 三轮依次为 7.221、6.968、6.478 个批次。
- 八个不同寿命标签样本的容量检查在五十次更新后，MSE 从 236.986 降至约 0.00397。仅该诊断关闭 Dropout。
- 板端二进制与原加载器输出逐元素一致；三个集合的追溯抽查、有限性和电机隔离检查通过。

这些结果只证明数据能驱动原模型训练、保存和预测，不代表最终训练精度或跨设备泛化性能。正式模型尚需完整训练和独立评估。检查中确认原源码的 `linear_t` 与 `fusion` 未参与前向；它们没有梯度不作为本次数据验证失败的条件。

## 使用与复现

在模型根目录，使用安装了 PyTorch 和 NumPy 的 Python 环境，将三个 NPZ 直接交给现有训练入口：

```powershell
.\.venv\Scripts\python.exe main.py train --train processed/run_to_failure_5motors_v1/train.npz --val processed/run_to_failure_5motors_v1/val.npz --output outputs/motor_stable23_v1_train --device cuda
```

现有默认训练为 150 轮；该命令应使用尚不存在的输出目录。项目训练环境为 `.venv`，使用 Python 3.12 和 GPU 版 PyTorch 2.8.0+cu126。原数据可训练性验证使用的 CPU 环境信息保留在 `processing_environment.json`，当前 GPU 配置及命令见 [Windows CUDA 训练环境](../../TRAINING_ENV.md)。

复现预处理需要 Python、NumPy 和 pandas，运行 `tools/prepare_motor_dataset.py` 并指定原始 ZIP 所在的 data-root、独立 raw-root 和一个全新的 output 目录。复现训练检查使用 `tools/validate_motor_dataset.py`。处理工具不会覆盖已完成的数据集；原通用 `main.py prepare` 不适用于这里的批次标签。
