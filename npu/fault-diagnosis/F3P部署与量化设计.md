# 单故障模型的 F3P 部署与量化规划

本文规定当前单主故障分类分级模型的 F3P 移植路径、运行包、CPU/NPU 分工及后续实施门槛。[独立离线测试包](deploy/README.md)已完成训练集校准、AArch64 构建与 360 窗 test 板端回放；[实机结果](deploy/BOARD_TEST.md)确认四个卷积使用硬 NPU，类别与所选等级判定与 FP32 一致，平均网络前向加速约 19.1 倍。上位机预处理、ABI 与控制器源码已有；正式共享库、运行包及实时联调按[故障模型接入规程](../../docs/故障模型-上位机接入.md)实施。

## 1. 部署对象与实施顺序

部署对象以[单故障训练与推断](model/单故障训练与推断.md)为准；[设计方案](设计方案.md)中的多标签 v2 结构仅作对照，不能混用权重、输出解码或连续波形预处理。

| 项目 | 规划基线 |
|---|---|
| 架构 | `fault_mtl_f3p_cnn2d_single_v3` |
| 任务 / 分类契约 | `bench_fault_single_v1` / `single_primary_fault_v1` |
| 输入 / 预处理 | `base6` / `base6_native_blocks_short_context_v2` |
| 分类模式 | `single_label`，正常、过载、欠压、过热、电机倾斜，共五类 |
| 最终层 | Linear 128→9：五个分类 logits、四个故障等级分数 |
| 分级 | 正常为 0；异常仅输出所选类别的 1～3 级；输入无效为不可用 |
| 温度隔离 | `temperature_isolation=true`，机械和温度两条 CPU 融合路径 |
| 当前候选 | 本地 `model/runs/active_selection_single_v1_seed42/best.pt`，非最终训练权重 |
| 当前数据边界 | 26 段同批记录内时间划分；训练 / 验证 / 测试 1063 / 360 / 360 窗 |
| 在线时间范围 | 过去四秒真实观测，默认每两秒生成一个新窗口 |

推荐交付顺序：冻结当前预处理与权重身份 → 实现 AArch64 CPU 浮点版本 → 接入本地实时采集 → 实施 CNN 算子与量化检查 → 形成可选 CPU/NPU 运行包。实时诊断的首个交付不以 CNN 的 NPU 兼容性为前提。F3P 上不部署电脑端 PyTorch 训练环境。

当前 `fault_mtl.export` 命令明确拒绝 `exploratory_native_blocks` checkpoint。离线包通过独立的 `deploy/prepare.py` 核对 checkpoint/config/preprocess/标签身份、BN 折叠及温度隔离语义，冻结已标准化 test 特征；没有删除该检查。该包不包含板端原生预处理和实时共享库，不能直接装入 RUL 上位机。电脑端及仿真准确率不作为 NPU 实机数值、实时性或独立实验精度的证据。

## 2. 资料与证据边界

### 2.1 RUL 移植过程的复用范围

| 现有来源 | 已有事实 | 本模型的使用方式 |
|---|---|---|
| [RUL 移植说明](../docs/porting.md) | 完整图受配套解析器限制，采用原生运行时和 CPU/NPU 分区 | 先实现 CPU 基准；必要时用原生 Arm NN 图构建 CNN，不将 ONNX 作为唯一入口 |
| [RUL 分配说明](../docs/cpu-npu-allocation.md) | 六个 UINT8 FC 在同一个硬 NPU 顺序执行，其他计算留 CPU | 复用分区、持久缓冲、量化与缓存同步的方法；不复用六个 FC 的图、尺度或张量 |
| [FC 补齐证据](../docs/npu-fc-padding-validation.md) | 特定补齐 FC 路径有实板证据，未补齐表达出现过超时 | 8 通道补齐作为保守设计起点；不是任意 Conv 或 Pool 尺寸兼容的证明 |
| [其他分支证据](../docs/additional-offload-validation.md) | 特定 1×1 Conv 表达可执行，小算子迁移未必加速 | 本模型四个 3×3 Conv 已独立板测；当前连续图融合 ReLU 受限，采用 CPU ReLU/MaxPool |
| [上位机接入说明](../../docs/寿命模型-上位机接入.md) | 独立共享库、C ABI、工作线程、清单校验、初始化后复用、退出释放 | 复用封装流程；新建故障模型 ABI、运行包和实时控制器 |
| [RUL 运行时生成入口](../../host/ps-local/inference/README.md) | `prepare_runtime.py`、交叉构建和封装均绑定 RUL 的权重与输入 | 参考其生成、封包、完整性检查和暂存方式，不将该脚本直接用于新模型 |

RUL 固定输入为 2530 个 float32，即 `[1,23,110]`；输出为寿命值。当前 `npu_*`、`libmlk_rul.so`、UDP v3 寿命帧和回放控制不能装入本模型。RUL FF6 约 43 ms/窗的既有结果仅属于该回放模型，不用作新 CNN 的性能估计。六分支也不表示六个物理 NPU。

### 2.2 工具链与硬件前提

配套 RUL 环境记录的 Arm NN 为 32.1.0、ONNX Parser 为 24.6。实施时以实际固定的头文件、动态库、后端插件、驱动和码流组合为准，记录版本及 SHA-256。模型导出、图解析、后端接收和硬件实际正确执行是不同门槛。

硬件能力依据现有 RUL 文档及本地 [DR1 产品说明](../../../ref/F3P/02_hardware/hardware_MLK_F3P_CZ02_DR1_20250526/06_芯片手册/01_DR1/UG1214_安路科技DR1系列FPSoC产品说明书.pdf)与 [NPU 开发教程](../../../ref/F3P/01_start/02_start_Linux/05_application_demo/05-5_NPU演示/05-5_米联客-安路F3P-CZ02开发板NPU开发.pdf)。Soft NPU 是 PL 逻辑；Pool 等算子是否存在、类型和连接是否匹配取决于实际 bitstream，不能由通用算子列表推定。当前配套后端只采用已通过逐卷积整数核验的四卷积执行计划；连续融合表达的限制见 §4.1。

## 3. 预处理与输入冻结

### 3.1 平坦输入契约草案

拟定义 `base6_single_native4s_flat_v1`，batch 固定为 1，float32、小端、C 连续布局；各张量按下表拼接，长度共 27683 个 float，即 110732 字节。偏移单位为 float。

| 分支 | 不含 batch 的形状 | 起始偏移 | 长度 | 展平顺序 |
|---|---|---:|---:|---|
| `time_frequency` | `[8,64,48]` | 0 | 24576 | C / 频带 / 时间 |
| `spectrum` | `[3,769]` | 24576 | 2307 | XYZ / 频点 |
| `vibration_stats` | `[12]` | 26883 | 12 | X、Y、Z 各自的 RMS、峰峰值、峰值因子、峭度 |
| `mount_pose` | `[8]` | 26895 | 8 | gx、gy、gz、相对倾角、模长、覆盖率、有效位、年龄 |
| `fast_state` | `[6,40]` | 26903 | 240 | I、n、valid_I、valid_n、age_I、age_n |
| `slow_state` | `[9,60]` | 27143 | 540 | T、I、n、valid_T、valid_I、valid_n、age_T、age_I、age_n |

该 ABI 的输入已完成训练侧固定标准化，引擎不能重复标准化。CPU 预处理入口另行接收物理单位、块元数据和时间；运行包必须同时携带该实现所需的固定资产。

### 3.2 短上下文算法的移植要求

权威实现为本地 `model/fault_mtl/exploratory.py` 的 `NativeBlocks`、`gap_aware_state`，及 `preprocessing.py` 的 `FeatureNormalizer`。实现时固定下列行为，完整参数来自候选缓存中的 `preprocess.json` 和 `config.yaml`。

| 部分 | 必须保持的行为 |
|---|---|
| 时间 | 输入窗口 `[t-4s,t)`；仅采用完整落入窗口的原生块，不跨保存暂停拼接波形，不补造未来或缺失采样 |
| 原生块 | XYZ、至少 64 点、记录采样率不低于 1600 Hz；按实际块采样率，块内时间间隔误差门槛 2 μs；幅值合理性门槛沿用 16 g 开发配置 |
| 原生频谱 | 每块逐轴去均值、对称 Hann 窗；NFFT=max(512,nextpow2(N))；单边 PSD 密度，内部频点乘二，按块时长加权汇总 |
| PSD | 只在频率轴插值到 0～600 Hz 的 769 个网格点，取 log10(power+1e-10)；网格细化不代表恢复短块的频率分辨率 |
| TF | 块频谱插值到 193 个频点，经冻结 64 频带权重汇总；块中心分配到四秒内 47 个实际时间格，按块时长加权；标准化后缺格为零，再补第 48 列及五个空通道 |
| 统计量 | 汇总块内去均值振动的二阶/四阶矩和极值；保留物理幅值，不逐窗除 RMS |
| 姿态 | 使用块均值的逐轴中位数及冻结水平参考求相对倾角；覆盖率按真实时间区间并集计算，重叠块不重复增加覆盖率 |
| 快状态 | 四秒内 40 个 100 ms 网格，严格取网格以前的 I/n，最大年龄 0.5 s；不读取未来点 |
| 慢状态 | 保持 `[9,60]`；前 56 格物理值和有效位为零、年龄为 1，仅最后四格读取短历史；T 用过去观测、最大年龄 6 s；I/n 的一秒格要求至少两点、跨度至少 0.2 s、末点年龄不超过 0.5 s |
| 标准化 | 只用训练阶段固定参数；TF 按轴/频带、PSD 按轴/频点、统计量逐项缩放；姿态前五项缩放，覆盖率/有效位/年龄保留；状态先缩放物理值，再将无效值置零 |
| 质量门槛 | 至少 12 块、TF 有效格比例≥0.45、快状态两量最低有效比例≥0.75、慢状态最后四格三量最低有效比例≥0.60、姿态年龄≤1.5 s；重力模长异常等原因同样拒绝 |

配置中即使保留 1600 Hz、连续 IIR 或 60 s 的其他字段，当前 native-block 分支也不执行连续重采样、连续高通或完整慢历史。C++ 不得根据这些闲置字段另建一条预处理路径。先匹配 float64 中间计算、最后转 float32 的参考语义，再考虑优化。

水平参考来自训练侧正常、水平暖机的前 30 秒块均值中位数，随运行包冻结；这是本台架的经验参考，不是分别测得的三轴零偏和增益。在线启动无需再采 60 秒或自动归零。传感器安装方向、标度或位置变化时，应建立新配置及适配流程；不能用当前窗口重学水平参考而消除倾斜信号。

## 4. CPU/NPU 分工

### 4.1 离线执行计划与连续图限制

当前 `hybrid_split` 计划将下表四个 Conv3×3 分别构建为仅允许 Alnpu 的图，全部在硬 NPU 执行；ReLU 与 MaxPool 在 CPU 执行。CNN 输入 NCHW `[1,8,64,48]`，输出 `[1,64,4,3]`；每组为 Conv3×3、padding=1、stride=1，ReLU，MaxPool2×2、stride=2。

| 组 | Conv 输入 | Conv 输出 | Pool 输出 |
|---|---|---|---|
| 1 | `[1,8,64,48]` | `[1,16,64,48]` | `[1,16,32,24]` |
| 2 | `[1,16,32,24]` | `[1,32,32,24]` | `[1,32,16,12]` |
| 3 | `[1,32,16,12]` | `[1,64,16,12]` | `[1,64,8,6]` |
| 4 | `[1,64,8,6]` | `[1,64,8,6]` | `[1,64,4,3]` |

CPU 保留 ReLU、MaxPool、TF 768→64、PSD 2307→32、统计 12→16、姿态 8→16、快状态 240→32、慢状态 540→64、Concat、融合 224→128、输出 128→9 和解码。CNN 只执行一次；不将每个小 FC 独立迁移以增加同步边界。实时接入时的 FFT、PSD、姿态、质量判断和标准化也安排在 CPU，当前离线包直接读取冻结特征。

当前 UINT8、zero-point=128 连续 Conv/ReLU/MaxPool 图虽被优化为四个硬 NPU 节点，实际输出含低于 ReLU 零点 128 的值，不能保持参考语义；`hybrid` 融合模式已禁用。`hybrid_split` 拒绝卷积的 CPU 回退，逐层使用实际输入和冻结尺度进行 int64 核验，28 组卷积最大差 1 LSB。四层传播后的最终 CNN 相对理想量化参考最大差 5 LSB；全部 360 窗类别和所选等级与 FP32 一致。完整数值、IRQ、profiling 和 CMA 证据见[板测报告](deploy/BOARD_TEST.md)。

### 4.2 温度隔离和唯一结果

共同的五个编码为 TF、PSD、统计、姿态、快状态，只算一次。慢状态编码、融合和 head 按已训练结构执行两次：

1. 机械路径将慢状态通道 0/3/6（温度、温度有效位、温度年龄）全部置零，其余不变，拼接共同编码。
2. 温度路径只保留慢状态 0/3/6，其他慢状态通道和全部共同编码置零。
3. 分类 logits 的正常/过载/欠压/倾斜取机械路径，过热取温度路径；等级分数中过载/欠压/倾斜取机械路径，过热取温度路径。
4. 五个 logits 做稳定 softmax，取最大项为唯一类别；并列时取最小索引。分数用于显示，不另设四个分类阈值。
5. 对所选异常的等级分数 s，用冻结的两个有序阈值 θ1/θ2 解码：`grade=1+sum(sigmoid(s-θj)>=0.5)`。阈值由训练参数 `a` 和 `a+softplus(b)+1e-4` 冻结。正常 grade=0，无效 grade 不可用。

机械原始 logits 和等级分数不直接读取温度，但五类 softmax 的竞争仍允许高温时过热胜出。移植时不能把两个融合路径合成一次，也不能对四个等级头取最大等级。

## 5. 导出、运行库与运行包草案

### 5.1 导出与数值形式

固定 checkpoint/config/preprocess/类别表的身份与 SHA-256，记录 `final_training=false, acceptance_verified=false` 的当前用途。后续候选权重替换要形成新包标识。先 `eval()` 并使用冻结 BN 统计；折叠公式为：

```text
alpha = gamma / sqrt(running_var + eps)
W_fold = alpha * W
b_fold = beta + alpha * (b - running_mean)
```

原卷积无 bias，代入 b=0；第一层五个补齐通道权重持续为零。训练 Dropout 在推断时关闭。输出仍为浮点 logits 与等级分数；CPU 负责 softmax 和所选分级。完整 ONNX 可作为对照或交换产物，解析受限时使用本地原生 C++ CPU 实现和原生 Arm NN CNN 构图。

### 5.2 独立 C ABI 草案

现有 [host/common/fault_engine_api.h](../../host/common/fault_engine_api.h) 定义 ABI `MLK_FAULT_ENGINE_ABI=1`；拟新增 `host/ps-local/fault-inference/` 与 `libmlk_fault.so` 实现。该 ABI 与现有模型告警 API v1 分属不同接口，具体封装与清单以[接入规程](../../docs/故障模型-上位机接入.md)为准。

引擎 32 字节结果布局、上位机原生块、诊断 API 2、结构化工单及双端摘要的字段级草案统一见 [host 模型接口需求](../../host/故障诊断模型接口需求.md)；上位机代码改动位置见 [host 改造清单](../../host/故障诊断上位机改造清单.md)。完整故障类型通过新版接口传递，v1 粗分类仅保留兼容用途。

| 拟新增函数 | 契约 |
|---|---|
| `mlk_fault_abi()` | 返回运行库 ABI 版本 |
| `mlk_fault_create(root,backend,error,capacity)` | 校验包与任务身份，加载一次权重/图/缓冲，返回独立上下文；backend=1 CPU，2 CPU+CNN NPU |
| `mlk_fault_predict(context,input,count,result,error,capacity)` | count 固定 27683；同步处理一个已标准化窗口；返回执行码及结果结构 |
| `mlk_fault_destroy(context)` | 等待调用结束后释放图、权重与 CMA，最后卸载运行库 |

结果结构草案包含 `struct_size`、`valid`、`class_index`、`grade`、`confidence`、`backend`、`infer_us`，调试时另取五个 logits/四个等级分数。采用固定宽度字段和显式结构版本/大小检查，不以 C++ 对象跨共享库边界传递。输入时间、质量、预处理耗时和过期判定由实时控制器保存；执行失败不返回有效正常结果。每个上下文单线程调用，不采用 `npu_*` 的全局 RUL 状态。

### 5.3 拟部署目录

```text
/opt/mlk_fault/                 # 拟新增，独立于 /opt/mlk_rul
  model.json                   # 包身份、ABI、执行计划、资产 SHA-256
  libmlk_fault.so              # little-endian AArch64 ELF
  weights.bin
  weights.tsv                  # 层名、布局、偏移、形状、类型
  preprocess.json              # 固定标准化、频带权重、短历史参数、水平参考
  decode.json                  # 五类顺序、四个等级分数顺序、冻结有序阈值
  qparams_cnn.tsv              # 仅 hybrid 包需要；逐边界量化参数
```

`model.json` 草案需包含：`schema=mlk.fault.runtime.v1`、包 ID、架构/任务/分类契约、预处理版本与哈希、`classification_mode=single_label`、`temperature_isolation=true`、输入布局/长度、输出定义、参考 ID、运行库 ABI、CPU/CNN 执行计划、后端/驱动/码流兼容标识、文件哈希及候选用途。CPU 包不伪造量化参数。全部推断必要资产均列入清单；不能原样沿用 RUL 的“五个文件、2530 输入、六分支”的检查器。

实时运行包不包含训练集、标签 CSV、Python 源码、训练环境和测试集。离线对照向量位于[独立测试包](deploy/README.md)，不作为实时启动输入。实时运行库的 fault 生成/封包/暂存入口另行实现；现有 `stage_rul.sh` 保留 RUL 语义，可参考其方式新增 `stage_fault.sh`。

## 6. 量化和训练

首先采用 CNN PTQ，CPU 其余部分保持 FP32。校准只用 train 的代表性真实窗口，覆盖正常、四故障、各档位、两次采集背景、缺格及幅值范围；valid 用于方案选择，test 保持既有开发留出的限定，不用于校准拟合。

| 项目 | 规划规则 |
|---|---|
| BN | 浮点冻结后折叠，再统计实际 CNN 的激活与权重 |
| 类型 | 离线包采用 QAsymmU8、zero-point=128、逐张量尺度；四个独立卷积已通过实机检查，连续融合 ReLU 禁用 |
| 量化 | `q=clip(round(x/scale)+zero_point,0,255)`，舍入、饱和、ReLU 和 Pool 的域必须与后端一致 |
| 零与 padding | 实数零编码为该张量 zero-point，包含补齐通道、末列、空间 padding；不能统一填 UINT8 的 0 |
| 偏置 | BN 折叠产生非零 bias；离线包使用 Signed32，尺度为输入尺度×权重尺度 |
| 跨边界 | CPU 标准化 TF → 一次量化 → 完整 CNN → 一次反量化 → CPU 编码/融合；图内尺度变换由冻结图显式定义 |
| 误差 | 同时保留 CNN 特征误差、五类 logit/argmax 变化、所选等级阈值翻转、温度隔离和无效样本行为 |
| QAT | 仅在 PTQ 误差不满足后续准入条件时启用；匹配目标量化规则，不更换任务或暗中重算标准化 |

RUL 的零偏置 FC 证据不能覆盖本网络的非零 INT32 bias、3×3 padding 或 Pool。先确定这些路径可实施，再投入 QAT；不能用软件 fake-quant 的结果替代硬件执行证据。

## 7. 编译、内存与资源规划

离线包已沿用 RUL AArch64 工具链与配套 Arm NN/Alnpu 库完成构建、封包和板测，入口见 [deploy](deploy/README.md)。实时共享库生成与 Qt 程序构建分离；Qt 侧通过动态加载只依赖新 C ABI，不引入训练框架头文件，其构建和暂存入口在实时接入时实现。

运行时规划如下：

- 创建时完成权重、四组 CNN 图、输入输出和工作区分配；逐窗只更新输入、同步缓存、执行、取结果。
- 固定权重和 CPU 临时区复用；NPU 输入 24576 字节、最终 CNN 输出 768 字节仅指 UINT8 张量数据，不含各层中间输出、对齐、图工作区和驱动开销；当前离线计划 CMA 恒定为 360448 字节，退出后为 0。
- FP32 全输入 110732 字节；参数量 257137 仅作模型规模参考，实际冻结权重文件大小由折叠及打包布局决定。另留原生块频谱缓存、状态环与 UI 队列内存。
- 首版 RUL 与故障推理采用应用级模式互斥，包括自动启动及外部发布者所有权。仅有一套 NPU/CMA 运行库在用；停止当前任务并完成释放后才启动另一任务。
- 混合后端加载失败显示原因；手动切换 CPU。后续若实现自动回退，应明确上报实际后端及降级原因，不以 CPU 成功冒充 NPU 执行。
- NPU/传感器/HDMI 共存继续使用配套码流与内存图。传感器 DMA 的 `0x3EF00000`、1 MiB 保留区不得与 NPU CMA 重叠；板端告警要求见实时接入方案。
- 非返回的驱动调用不能通过强制销毁工作线程安全恢复；不得在调用未退出时卸载库、释放 CMA 或启动第二上下文，后续由受控服务重启策略处理。

## 8. 后续实施阶段与交付门槛

下表为完整实时部署的工作范围。独立离线包已覆盖权重与缓存资产冻结、浮点/整数参考、交叉构建、四卷积硬 NPU 实测及释放检查；原生预处理、共享库、上位机与现场运行仍按各阶段条件实施。

| 阶段 | 实施内容与产物 | 进入下一阶段的条件 |
|---|---|---|
| A：冻结 | 当前权重、预处理、类别/等级顺序、水平参考与版本清单；解除短上下文导出限制所需的正式入口 | 资产完整、用途明确，不再依赖训练缓存隐式字段 |
| B：CPU | 原生块预处理、标准化、完整浮点网络、唯一类别/等级解码、AArch64 CPU 共享库 | 与冻结参考的特征和输出对照满足预先确定容差；有效/不可用一致 |
| C：实时接入 | 本地四传感器流、工作线程、窗口调度、显示/告警/工单适配 | 明确窗口时间、数据缺口、过期和模式所有权；完成 CPU 诊断链路 |
| D：算子 | 精确 Conv/ReLU/Pool 形状、非零 bias、padding、四组连续图 | 后端接收、实际执行、整数参考及资源释放均有证据；否则保留 CPU |
| E：PTQ | train 校准、冻结量化计划、完整混合输出；必要时 QAT | 分类/等级变化和错误样本符合独立规定的候选接受界限 |
| F：运行包 | 独立 fault ABI/清单/构建暂存、可回退版本目录 | 版本匹配与失败行为明确，CPU 和混合后端可区分 |
| G：现场交付 | 实时性、保存缺口、模式切换、故障恢复、声光/工单/双端同步及长期资源 | 端到端延迟、覆盖率、丢块和资源上限有记录；与最终精度验收分开 |

性能先以每两秒一次窗口、无历史积压为目标，分开记录采集等待、预处理、推断和 UI 发布耗时，具体数值门槛为 TBD。比较 CPU 与混合执行的完整窗口耗时，而不是仅比较 CNN 内核。单故障五分类 ≥90%、故障类别与所选分级同时正确 ≥85%作为后续目标，不能将同批开发成绩扩展为跨设备或独立现场结论。

上位机的数据入口、故障 API 适配、拟新增界面及操作顺序见[F3P 实时故障诊断接入方案](F3P实时故障诊断接入方案.md)。
