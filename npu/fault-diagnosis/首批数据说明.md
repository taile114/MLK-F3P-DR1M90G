# 首批自然升温记录与温度分段

本文说明本地 SD 卡导出数据、三个温度区间的原生切片、标签依据及当前数据质量。模拟规则为 `case_temp_35_40_45_v1`，六路输入为振动 XYZ、电流、转速和电机外壳温度。

拼接、插值、慢状态缺失掩码以及较短振动间隙的检查见[缺口处理方案](缺口处理方案.md)。本次切片保持原生数据，没有生成波形插值修复版。

每个 NPZ 有同名 JSON，包含区间、物理单位、标签、原生数组切片范围和 NPZ 哈希。集中索引为 [segments.csv](data/segments/session_001/segments.csv)，训练区间描述为 [episodes.jsonl](data/segments/session_001/episodes.jsonl)。

每段另有同前缀的 `_overview_1s.csv`，可在 Windows 查看温度、电流、转速和振动统计；正式振动输入仍使用 NPZ 原生数组。完整导出与切片逐数组复核结果见 [verification.json](data/processed/verification.json)。

温度标签分别是健康侧 0、轻度 1、中度 2；其他三类依据操作者“未植入、设置未动”的说明标为 0，并明确 `label_basis=operator_no_injection`。这些负例不能解释为已独立测得实际制动力矩、实际母线电压或螺栓预紧力。负载热漂移与测量质量仍按下述问题保留。

上述派生切片与标签属于 `bench_fault_sim_v1`，第四类为 `mount_looseness`。操作者已确认本次全程正常工作，电机水平放置；[当前 v2 设计](设计方案.md#66-安装倾斜异常与三级候选规则)的独立派生清单据此把 `mount_tilt` 标为正常侧 0，使用 `label_basis=operator_confirmed_horizontal`，不是由松动负例自动推断。本次没有数值参考角度、误差或独立静态校准，不填写虚构测量或自动建立重力基准，也没有倾斜正例。温度继续按项目模拟规则用于子任务；原始文件、NPZ、既有 v1 JSON/JSONL 及哈希保持不变。

v2 标签位于 [session_001_v2/episodes.v2.jsonl](data/segments/session_001_v2/episodes.v2.jsonl)，来源、哈希及确认范围见 [adaptation.json](data/segments/session_001_v2/adaptation.json)。水平确认支持第四类正常标签，数值姿态输入仍按校准与真实采样质量分别判定。

没有将原始记录改写为三个加密文件；原件完整保留，NPZ 是对真实原生样本的派生切片，不经等间隔降频、填零或插值。停机背景、启动过渡、阈值往返与未选区间仍保留在完整原生记录及 [temperature_intervals.csv](data/processed/temperature_intervals.csv) 中。

## 3. 原生数据与检查曲线

完整解码数据为 [native_recording.npz](data/processed/native_recording.npz)，来源与逐块标定信息为 [native_metadata.json](data/processed/native_metadata.json)。单个 NPZ 的字段按四个通道分组：

| 字段后缀 | 内容 |
|---|---|
| `_t_us` | int64 估算 UTC 微秒时间戳，各通道独立；振动的相同时间戳样本全部保留 |
| `_raw` | 原始 signed16 或 signed32 码；振动为 `[N,3]` 的 XYZ |
| `_value` | 物理量：温度 ℃、电流 A、转速 rpm、振动 g；仅应用文件标定与 mA→A 单位转换 |
| `_block` | 对应完整 `native_metadata.json` 中的全局块 ID，供源文件与块内样本追溯 |
| `metadata_json` | 切片 NPZ 内的 JSON 字符串元数据；使用 `allow_pickle=False` 读取 |

通道前缀为 `temperature/current/speed/vibration`。时间排序采用稳定排序，没有仅按相同时间戳去重，也未删除非重复块。v2 保存路径、原始数组和每文件标定均已保留。

检查曲线为 [recording_overview.png](data/processed/recording_overview.png)，概览数值为 [overview_1s.csv](data/processed/overview_1s.csv)。概览中的状态量采用不读取未来样本的前值保持；过期值留空，振动仅按每秒统计去均值 RMS 和样本数。该表不能替代 kHz 振动原生数据用于频谱训练。

## 4. 数据质量与使用边界

1. 四路均观察到 40 次超过 0.5 秒的共同记录间隙，约每 60 秒一次。振动间隙为 0.632～0.862 秒，电流为 0.682～0.875 秒，转速为 0.695～0.972 秒，温度为 0.687～0.878 秒。首批间隙与相邻文件分段边界对齐；这支持排查分段保存时的采集/发布阻塞，但不能仅凭记录确认具体代码原因。详见 [acquisition_gaps.csv](data/processed/acquisition_gaps.csv)。
2. 振动累计 6672431 个三轴样本，块内名义速率约 3034～3188 Hz，不能据此认定全程无丢失。估算时间重建存在 5549 对相同振动时间戳；这些样本及源块 ID 均保留，不擅自去重或跨缺口插值。
3. 温度记录有 47204 个发布点，但块头 `rate_hz=1`，记录点的发布间隔中位数约 40 ms。发布次数不等于传感器独立更新次数；不得把它宣称为约 20 Hz 的独立温度测量。
4. 电流 98628 点、转速 18858 点，发布速率和名义 50/10 Hz 不完全相同。物理值范围分别约 -0.073～6.971 A、0～1780.2 rpm；起始近零电流和零转速属于停机背景，启动电流峰值不作为过载真值。
5. 三段共有 2191 个温度同级的候选 60 秒窗口。按方案当前“电流/转速 60 秒历史内不得出现 >0.5 秒间隙”的保守筛查，987/499/705 个窗口分别全部受影响，通过数为 0。详见 [window_quality.csv](data/segments/session_001/window_quality.csv)。筛查结果不是模型精度测试，也不等于温度分段或全部原始数据无用。
6. 现有切片可用于数据检查、温度规则基线与初步方法研究；不能直接标为完整六路正式训练已合格。应先排查周期缺口，再补采连续记录，或经独立验证后另行冻结缺失处理规格；不在本次导出中悄然放宽 0.5 秒门限。
7. 中度区间的电流下降与转速升高已保留在记录中，不能据此补标其他故障。完整记录只有一次自然升温，没有独立重复、冷却循环或重度样本；三段和 41 个源文件必须属于同一个划分组 `session_001`，不能随机拆到训练与测试两边。
8. 细化检查显示，估算振动时间轴中还有 4897 处超过 20 ms 的间隔，三段的所有候选 4 秒窗都与其中至少一处相交。应用 `seq` 连续不证明 DMA 无丢块，诊断 `count` 存在跳变；需核对实板 v2 的时间重建及计数语义。不能把避开 >0.5 秒大缺口后的 2024 个候选终点直接称为完整合格波形样本。

本次记录的第 15 分钟附近壳温约 32.4～33.2 ℃，与此前口述的约 28±2 ℃参考并不相同。后续参考统计应使用实际文件、运行起点和工作点定义，不把口述值覆盖到本次数据。

## 5. 处理工具与复核

- [prepare_capture.py](tools/prepare_capture.py)：核对导出清单与认证载荷哈希，按 v1/v2 对应字宽解析，保留原生码、物理量、时间戳、源块与质量统计。
- [segment_capture.py](tools/segment_capture.py)：按实测温度区间提取三类 NPZ，排除初始停机/启动，生成标签、窗口间隙筛查与概览曲线；`--operator-no-injection` 仅在操作者已确认未植入故障时使用。

原始数据与派生数据均位于本地忽略目录 `data/`，不随普通 Git 提交加入仓库。读取 NPZ 的示例：

```python
import numpy as np

with np.load("data/segments/session_001/overtemperature_g1.npz", allow_pickle=False) as data:
    vibration_g = data["vibration_value"]
    vibration_t_us = data["vibration_t_us"]
    temperature_c = data["temperature_value"]
```

工具依赖 NumPy；绘图另需 Matplotlib。SD 卡源文件未修改，解密仅针对已复制或经认证的本地派生文件；口令不写入切片、报告或工具命令行参数。
