# F3P 本地上位机实时故障诊断接入方案

本文说明单主故障模型接入 PS 本地 Qt、remote-pc、声光与工单的结构及实施边界。参数来源、共享库提取、正式运行包、部署命令和验收步骤统一见[故障模型与上位机接入](../../docs/故障模型-上位机接入.md)。

## 1. 当前基线

| 部分 | 状态 | 权威入口 |
|---|---|---|
| Python 训练与冻结权重 | 已生成当前开发候选 `best.pt`，部署未重新训练 | [单故障训练与推断](model/单故障训练与推断.md) |
| 独立 CPU/NPU 测试包 | 四卷积硬 NPU、360 窗 test、整数核验及释放已板测 | [板测报告](deploy/BOARD_TEST.md) |
| 本地/远端诊断链路源码 | 原生块入口、C++ 预处理、线程、ABI 加载、界面、API 2 与消息已有；应用级构建和运行验收待完成 | [实时故障诊断实现](../../host/实时故障诊断实现.md) |
| 正式故障模型运行包 | `libmlk_fault.so`、预处理格式转换、生成/封包/暂存入口待实现 | [接入规程](../../docs/故障模型-上位机接入.md) |

现有上位机 SD 系统可支持独立模型测试，无需为模型重新烧录。离线测试目录不能直接作为 Qt 运行包；其 schema、程序入口和预处理资产格式与正式加载器不同。当前板测不代表实时特征或新共享库已经验收。

## 2. 数据与线程

```text
DriverSource → KLocalWindow 已加时间戳的完整物理块
                    ├→ 看板 / MLKC 记录 / UDP 波形
                    └→ FaultInputAdapter → 有界输入队列
                                               ↓
                                  FaultWorker 工作线程
                                  四秒切窗 / 两秒步长
                                  FaultPreprocessor → FaultRuntime
                                               ↓
                                        libmlk_fault.so
                                               ↓
                                  FaultLiveController / 主线程
                                  ├→ 唯一故障 / 等级 / 质量与时效
                                  ├→ 确认事件 → 声光 / 工单 / 标签
                                  └→ UDP v6/type8 → remote-pc
```

输入必须是与训练一致的原生块；转速通过 `onSpeedSample` 独立接入。禁止从绘图、UDP 分片、四路最后值或 PL 频谱拼装六分支特征。四秒窗口、时间戳、单位、缺块、质量和标准化要求见[模型接口需求](../../host/故障诊断模型接口需求.md)。

CPU/NPU 引擎均在工作线程初始化、调用和销毁；每个上下文串行执行。RUL 与故障任务互斥，切换前等待释放。默认 NPU 计划为四个独立 Conv3×3，ReLU/MaxPool 和其余分支留 CPU；连续融合 ReLU 模式禁用。

## 3. 实施顺序

1. 固定已板测权重、阈值和量化尺度，按现有 `fault_engine_api.h` 提取共享库，不改变解码或温度隔离。
2. 转换冻结预处理资产为 `FaultPreprocessor::loadAssets` 的格式，并逐分支与 Python 原生记录对照。
3. 形成 `mlk.fault.runtime.v1` 清单、共享库和完整资产哈希，验证全量 test 与重复创建/释放。
4. 构建本地与远端应用，在现有系统部署用户态应用及正式模型包。
5. 依次验证 CPU 实时输入、四卷积 NPU、双端具体故障、告警/工单、缺口/过期及长时资源。

## 4. 上位机操作规程

正式运行包验收通过后，在“实时故障诊断”面板选择包目录和 CPU 或 CPU+CNN NPU，点击“开始诊断”。RUL 释放后工作线程加载，收集完整四秒且质量合格的数据后输出唯一类别和所选等级。切换包、后端、标度或任务前先停止并等待资源释放。

故障模式下不可用或过期结果显示 N/A，不作为正常；模式、运行身份和窗口序号共同防止晚到结果重新生效。新端通过 API 2 和 UDP v6/type8 表达五类结果；API v1 仅承载兼容粗摘要，不能直接填入五类索引。

启动变量、板端命令、失败处理和逐项验收均以[接入规程](../../docs/故障模型-上位机接入.md)为准；字段以[模型接口需求](../../host/故障诊断模型接口需求.md)为准，文件职责见[实现说明](../../host/实时故障诊断实现.md)。
