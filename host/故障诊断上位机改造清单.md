# 实时故障诊断上位机改造清单

本文列出满足[模型接口需求](故障诊断模型接口需求.md)的本地上位机、共享组件、远端和构建部署改动。两后端共享库、检查程序和本地 Qt 已交叉编译，CPU 360 窗与开发机 Qt 集成验证通过；输入绑定修复库已更新至板端并通过两轮 NPU 360 窗，双端及实采验收待定。实现见 [fault-inference](ps-local/fault-inference/README.md)，参数、部署与操作见[故障模型与上位机接入](../docs/故障模型-上位机接入.md)，模式与验证范围见[故障模型接入与评估模式](故障模型接入与评估模式.md)。

## 1. 差距与改动优先级

| 编号 | 现有接口限制 | 要求的改动 | 优先级 |
|---|---|---|---|
| H01 | RUL 固定 2530 输入，结果只有寿命 | 独立故障共享库 ABI，27683 输入，唯一五类+所选等级 | P0 |
| H02 | 图表/记录有实时流，但模型没有完整原生块入口；转速单独处理 | stamped 原生物理块接口及独立转速接入，不读图表或网络分片 | P0 |
| H03 | 现有 ReplayController 是数据集调度 | 新建四秒缓存、预处理和两秒窗口调度的 FaultWorker/Controller | P0 |
| H04 | 模型 API v1 和 UI 类别只有正常/轻微/重度 | 新增 API 2，classIndex=0..4，故障类型和等级独立 | P0 |
| H05 | `reportModelState` 将工单重建为旧字段，具体故障只在消息中无法结构化读取 | 新增确认事件持久化路径和 `diagnosis` 工单快照 | P0 |
| H06 | RUL 自动回放、旧诊断输入和 Socket 可能各自更新分类状态 | 统一模式/发布者所有权，所有入口检查 run 与任务归属 | P0 |
| H07 | 原始结果与告警状态、不可用与健康缺少独立诊断状态 | 增加原始结果/确认告警/历史事件分离，过期立即无效 | P0 |
| H08 | UDP v3 是 RUL；v1/v2 cls 不是具体故障类型 | 独立 UDP v6/type8 状态消息和新端解析 | P1 |
| H09 | 运行包暂存和启动变量只覆盖 RUL | 故障运行包加载、CPU 默认、任务启动配置和版本回退 | P0 |
| H10 | 四卷积硬 NPU 独立程序已板测，应用共享库已封装与交叉编译 | 验收共享库板端数值、图归属与 CMA 生命周期 | P2 |

P0 为本地 CPU 实时诊断必需，P1 为远端完整故障显示，P2 为后续 NPU 加速。仅把现有 `cls` 的上限从 2 放宽到 4，不能解决标签含义、预处理、时效或工单结构问题。

## 2. PS 本地代码修改位置

表中不存在的文件和函数均标为新增；名称为建议命名，不表示已存在。

| 位置 | 现有入口 / 拟新增入口 | 需要实施的修改 |
|---|---|---|
| [src/klocalwindow.cpp](ps-local/src/klocalwindow.cpp) / [.h](ps-local/src/klocalwindow.h) | `onFrame`、`handleWaveform` | 在同一个 `timestampWaveform` 结果上生成物理块；模型分支位于同步记录和网络分片之前。不要对同一帧重复换算时间/物理单位 |
| 同上 | `onSpeedSample`、`onSpeedAvailability` | 将已去重的 0.1 rpm 转速样本单独送模型；离线/错误通知进入质量状态，不能遗漏转速或重复追加寄存器与 DMA 同一事件 |
| [src/datasource.cpp](ps-local/src/datasource.cpp) / [.h](ps-local/src/datasource.h) | `DriverSource::pollRing`、`speedChanged`、数据源可用性通知 | 提供源运行身份、缺块/重启/饱和元数据；可扩展内部信号保存完整 DMA 序号。保留当前块采样率及时间语义，无需先改 PL 或驱动 ABI |
| 新增 `ps-local/src/faultinputadapter.*` | `acceptStampedFrame`、`acceptSpeed` | 集中转换 g/℃/A/rpm，附加 scale_id、source_run、block_id；禁止各显示分支分别决定模型单位 |
| 新增 `ps-local/src/faultlivecontroller.*` | `start`、`stop`、`acceptResult` | 模式、运行身份、固定四秒/两秒调度、状态与时效；拒绝旧 run/旧窗口、管理停止后的晚到结果 |
| 新增 `ps-local/src/faultworker.*` | 工作线程与有界输入缓冲 | 原生块/状态环、冻结预处理、标准化、推断、分开计时；一任务在途、一最新窗口待处理，禁止无限排队 |
| 新增 `ps-local/src/faultruntime.*` | 引擎动态加载封装 | 加载 `/opt/mlk_fault/model.json` 和 `libmlk_fault.so`，校验 ABI/任务/资产；初始化/调用/释放均在工作线程 |
| 新增 `ps-local/fault-inference/` | CPU 引擎、运行包生成与封装 | 按冻结短历史实现浮点网络；解决当前导出准入和资产完整性，不复用 RUL 的 2530 输入检查器 |
| [src/klocalwindow.cpp](ps-local/src/klocalwindow.cpp) | 新增 `reportDiagnosisResult`、`applyConfirmedDiagnosis` | 接受 API 2 原始结果；确认后生成结构化工单、更新 AlarmController 和兼容 v1 摘要。不能直接调用只接收粗类的旧 reportModelState 丢失类型 |
| 同上 | `handleDiagnosis`、`reportModelState` | 保留 v1/RUL 兼容，但分类入口都检查发布者所有权；旧注入帧不得覆盖内置实时模型 |
| [src/modelfaultserver.cpp](ps-local/src/modelfaultserver.cpp) / [.h](ps-local/src/modelfaultserver.h) | 请求分发、读取缓冲 | 新增 api=2 分发和每实例长度上限；模型 v2 上限 4096 B，v1/采集 API 保留既有上限；响应区分接收失败与存储失败 |
| [src/alarmcontroller.cpp](ps-local/src/alarmcontroller.cpp) / [.h](ps-local/src/alarmcontroller.h) | `modelGrade` | 保留 0..3 和现有 PL 时序；由新控制器直接传确认后的等级，解除对粗分类字段的依赖 |
| [src/klocalwindow.cpp](ps-local/src/klocalwindow.cpp) | 构造函数的 RUL `singleShot`、自动回退、回放控制连接 | 统一模式检查，故障模式禁止 RUL 自动启动和自动回退另开引擎；仅隐藏回放按钮不满足要求 |
| 同上 | 构造函数的 `modelTimer`、`m_modelSeen` 超时处理 | 旧十秒 watchdog 仅处理 v1 发布者；API 2 使用新控制器的窗口时效，禁止旧计时器在新模式中清除有效告警 |
| 同上 | `applyConfig`、电流归零、源重连、退出路径 | 模型相关标度变更时停止/清上下文；归零不得作为普通运行操作静默污染窗口；先撤销模型有效和告警，再等待释放 |

现有 `npu.*`、`replaycontroller.*` 保持 RUL 含义；故障实现使用独立上下文和文件名。初版两类模型模式互斥，当前 CPU 或 NPU 调用尚未结束时不得启动另一上下文。

| 新增故障诊断日志模块 | 每窗结果与模型/预处理/质量/耗时单独记录，沿用加密和保留策略；不得每窗新增工单或把预测自动当监督真值 |
| [common/mlk_fault_client.c](common/mlk_fault_client.c) / [.h](common/mlk_fault_client.h)、[mlk-fault.c](ps-local/tools/mlk-fault.c) | 如需外部发布 v2，增加限长 4095 B 请求正文的 v2 客户端入口和 CLI 选项，保留旧函数 999 B 正文上限，响应仍需判断 ok；内置工作线程不在 UI 中同步访问自己的 Socket |

确认状态与原始推断分别保存。事件 ID、故障时间和首次快照在确认时冻结，重复结果不重新持久化；类别/等级确认变更才建立新事件。过期、错误、停止都立即撤销当前模型告警，历史事件继续保留。

## 6. 实施顺序与完成条件

1. 统一五类/分级/无效枚举、API 2、原生物理块与引擎 ABI；登记包身份和预处理资产，明确类型和单位。
2. 实现 CPU 引擎、短上下文预处理和原生数据适配，单线程持久加载；本地 UI 能启动/停止并显示唯一具体故障。
3. 实现模式互斥、过期/停止处理、告警确认与结构化工单，保留 v1 兼容而不让其覆盖 v2 状态。
4. 实现远端专用消息与工单显示，更新打包、启动和操作说明。
5. 在上述接口不变的条件下增加 CNN NPU 后端及包执行计划。

完成标准为输入来自当前真实六路历史、结果完整表达一个具体类别及所选等级、不可用不伪装正常、工单保留结构化类型、模式/时效归属明确。构建、CPU 数值与 Qt 离线结果见[验证状态](故障模型接入与评估模式.md#8-验证状态)；实采数值、缺口、时钟跳变、双端断网与板端资源释放仍须按[剩余事项](故障模型接入待完成事项.md)验收。
