## 2. 产物与复现入口

从新检出仓库复现时，先按[构建与交付](ps-local/fault-inference/BUILD.md)准备厂商 SDK、
工具链、OpenSSL 和冻结资产；该文档列出仓库文件、外部依赖及各产物的部署位置。

工作区产物目录为 `../../out/mlk-fault/`：

| 路径 | 内容 |
|---|---|
| `runtime/` | `mlk.fault.runtime.v1`，含 AArch64 `libmlk_fault.so` |
| `evalset/` | `mlk.fault.evalset.v1` 与 360 窗冻结特征，独立于运行包 |
| `bin/` | `fault_check` 与 `mlk_ps_local` |
| `config/` | `run_arm_app.sh` 与 `mlk-inference` |
| `mlk-fault-aarch64.tar.gz` | 上述用户态产物与校验清单；不含内核、驱动或 Qt/Arm NN 运行库 |
| `consttensor-fix/fault-consttensor-fix.tar.gz` | 库与清单增量包；校验现有模型资产、保留上一版本后切换，已用于板端更新 |

Ubuntu 构建工作区为 `/home/uisrc/mlk-fault-integration`。共享库重编：

```sh

OUT="$PWD/build-aarch64" sh host/ps-local/fault-inference/build_arm.sh
```

Qt 交叉构建使用虚拟机现有的 SDK 与 ARM OpenSSL：

```sh
export PATH="/home/uisrc/mlk-host-ff6/build-tools/usr/bin:$PATH"
QT_SDK_ROOT=/home/uisrc/mlk-host-ff6/qt-sdk \
QT_TOOLCHAIN_BIN=/home/uisrc/uisrc-lab-anlogic/tools/aarch64-linux/bin \
```

再执行 `verify_runtime.py <运行包> --aarch64`。不得把纯 CPU 库声明为 NPU 后端。

## 3. 板端最小验收顺序

前提：使用与独立模型板测相同的内核、驱动、码流和 `/opt/armnn_lib/lib`；
`/dev/hard_npu`、`/dev/soft_npu`、`/dev/cma_mem` 可用。停止上位机后才运行检查程序。

```sh
/etc/init.d/S99qtapp stop
export LD_LIBRARY_PATH=/opt/armnn_lib/lib
# 运行包放 /opt/mlk_fault，评估集放 /data/fault-eval
fault_check /opt/mlk_fault --backend cpu --data /data/fault-eval \
  --report /data/fault-eval/cpu-report.json --predictions /data/fault-eval/cpu.csv
fault_check /opt/mlk_fault --backend npu --data /data/fault-eval \
  --report /data/fault-eval/npu-report.json --predictions /data/fault-eval/npu.csv
```

| 顺序 | 操作 | 通过条件 |
|---|---|---|
| 1 | CPU 360 窗 | 分类 360/360、联合 356/360、reference_mismatch=0、backend=1 |
| 2 | NPU 小样本后全量 | 同上，backend=2；四图均为硬 NPU 卷积，实际 IRQ 增长，无 CPU 回退 |
| 3 | 原始输出对照 | 共享库的 9 维输出、各卷积输入/输出与独立程序对照；CLI 当前只公开最终判定，原始输出证据仍需补充 |
| 4 | 两轮创建/释放 | 结果一致；CMA 退出回到基线、稳态无持续增长；记录平均/中位/P95/峰值 |
| 5 | Qt 本地实时诊断 | 至少一个真实质量合格窗口；五类、等级、分数、后端与耗时可读 |
| 6 | Qt 数据集评估 | NPU 跑完 360 窗，导出报告，滚动查看逐类表与两个矩阵 |
| 7 | 异常与双端 | 停止/重启、加载失败、6 s 过期、旧窗口、断网、本地显示、远端 N/A 与告警撤销正确 |
| 8 | 共存 | HDMI、采集 DMA、存储与推理并行；记录丢块和长期资源变化 |

## 4. 实采预处理数值验收

使用同一批真实 `.mlkc` 记录，分别经训练侧 Python 与 C++ `FaultPreprocessor`
生成 27683 输入，比较 TF 64×47 能量、PSD 769 点、统计 12、姿态 8、
快状态 6×40、慢状态 9×60；年龄通道归一化至 [0,1]，不可用为 1。

覆盖缺块、重复块、时间跳变、标度变化、电流归零及源重连。记录质量门限在真实数据
上的分布，确认 12 块、TF 0.45、快状态 0.75、慢状态 0.60、姿态年龄 1500 ms、
重力偏差 0.25 g 的现场适用性。冻结特征评估不覆盖本项。

## 5. 暂存与版本切换

```sh
MLK_FAULT_ROOT=/path/to/runtime \
ARMNN_RUNTIME_ROOT=/home/uisrc/f3p-rul-probe/vendor/armnn \
bash platform/flash/stage_fault.sh
```

脚本只写 rootfs overlay；版本目录为 `/opt/mlk_fault-packages/<model>-<manifest-hash>`，
`/opt/mlk_fault` 指向当前版本，`/opt/mlk_fault.previous` 保留上一版本。
重复暂存相同版本不覆盖上一版本链接；校验失败不切换当前包。
评估集单独部署到 `/data/fault-eval`。

启动配置见 `platform/flash/rootfs-overlay/etc/default/mlk-inference`，显式进程环境优先；
`MLK_INFERENCE_MODE` 只记录意图，不自动加载模型。板端回退前停止诊断、评估与寿命回放，
等待释放并停止服务，再切换模型链接与应用备份；不得在设备调用尚未返回时并行加载另一模型。
