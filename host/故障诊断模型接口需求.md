# 实时故障诊断模型接口需求

本文定义单主故障模型要求的数据输入、引擎 ABI、结果发布、工单及双端消息接口。上位机源码已按本文实现，未重新构建，也未运行验证；实施改动位置与顺序见[上位机改造清单](故障诊断上位机改造清单.md)。

## 1. 模型基线与接口职责

| 项目 | 要求 |
|---|---|
| 架构 / 任务 | `fault_mtl_f3p_cnn2d_single_v3` / `bench_fault_single_v1` |
| 分类契约 / 输入 | `single_primary_fault_v1` / `base6` |
| 预处理 | `base6_native_blocks_short_context_v2`，四秒历史、两秒步长 |
| 结果 | 正常及四故障中唯一最高 logit；仅所选异常的等级 1～3，正常为 0 |
| 物理输入 | XYZ（g）、电流（A）、转速（rpm）、外壳温度（℃） |
| 运行方式 | PS 工作线程执行；CPU 首先实现，CPU+CNN NPU 为后续可选后端 |

当前 RUL 的 `[1,23,110]` 输入、`npu_result_t`、故障 API v1 的粗分类、旧诊断帧和工单字段不能完整表达该模型。应新增独立五类诊断接口；兼容旧端时才派生“轻微/重度”摘要。具体故障类型是正式结构化字段，不依赖消息文本解析。

| 接口 | 生产方 → 消费方 | 拟定版本 |
|---|---|---|
| 原生物理块 | 本地采集适配器 → 实时预处理 | `fault.sample.v1` |
| 标准化张量 | 预处理 → 共享库引擎 | `base6_single_native4s_flat_v1`，引擎 ABI 1 |
| 诊断结果 | 模型工作线程/外部模型进程 → 上位机控制器 | 模型诊断 API 2，schema `mlk.fault.result.v2` |
| 确认事件 | 上位机控制器 → 加密工单/标签 | `mlk.fault.order.v2` |
| 状态摘要 | PS → remote-pc | UDP v6/type8，schema `mlk.fault.status.v1` |

这些版本已按本文在上位机源码中实现，未重新构建，也未运行验证；新旧端并存时按 `api` 与 `schema` 分派，旧接口继续以 [NPU-AI 接口](../docs/NPU-AI接口约定.md)、[PS 本地接口](../docs/PS本地应用接口约定.md)、[网络接口](../docs/上位机-PS接口约定.md)和[告警 API](../docs/声光告警与模型故障API.md)为准。

## 2. 上位机提供给模型的数据

### 2.1 原生块对象 `fault.sample.v1`

这是同进程数据结构需求，不新增 UDP 原始数据协议。适配器在本地完整 Frame 加时间戳后生成对象，按值或受控共享内存移交，不能保留 DMA 映射的临时裸指针。

| 字段 | 类型 | 规则 |
|---|---|---|
| `source_run` | UUID 字符串 | 数据源本次运行身份；驱动重连、DMA 重启或时基重置后更换 |
| `block_id` | uint64 | 本地完整块唯一 ID，不使用网络分包序号或 16 位 `cnt` 直接替代 |
| `channel` | uint32 | 0 温度、1 电流、2 振动、3 转速，沿用现有通道编号 |
| `t0_us` | uint64 | 估算 UTC 首样本时刻，复用 `timestampWaveform` 后的记录时间语义 |
| `rate_hz` | uint32 | 块内实际记录采样率；单点状态保留通道名义率；不能用于断言块间连续 |
| `count` / `axes` | uint32 | 每轴样本数；振动 axes=3，其余=1；振动 XYZ 数量必须相等 |
| `values` | float32 数组 | `[count,axes]` 按样本、轴顺序排列，使用物理单位；不先做模型标准化 |
| `scale_id` | 有界字符串 | 生成物理值使用的标度快照身份；与模型运行配置匹配 |
| `data_valid` | bool | 实际新观测；旧寄存器重复读、离线/错误事件不得伪造有效样本 |
| `gap_before` / `saturated` | bool | 缺块与量程饱和信息；记录实际情况，不补造样本 |
| `dma_seq` | 可空 uint32 | 若源层提供则保留完整 DMA 块序号，用于质量追踪，不代替应用唯一块 ID |

单位转换必须匹配当前训练侧：温度/XYZ 先按记录的 `k×raw+b` 转换；电流 Frame 已是 mA，模型入口除以 1000 得到 A，不再次应用 ADC 增益；转速使用现有 0.1 rpm 整数量化后的 rpm，不直接换用高精度 `rpmMilli`。饱和信息单独展示；改变饱和样本处理或改用高精度输入须形成新预处理适配版本。

温度、电流、XYZ 从 `KLocalWindow::onFrame` 的 stamped Frame 接入；转速从 `onSpeedSample` 构造的 speed Frame 单独接入并沿用 PL 事件去重。模型入口位于记录落盘和 `sendWaveform` 分成 128 点网络包之前。无需修改 PL 采样协议或增加电压传感器。

### 2.2 切窗与质量

预处理由 PS 模型工作线程完成，上位机操作不需要预切文件。使用 `[end_us-4s,end_us)`，仅包含完整落入区间的原生振动块；逐块去均值、Hann/PSD 后汇总，禁止跨保存间隙拼成连续波形。状态通道按过去观测对齐，不能使用未来样本。

TF 频带功率按时长汇总后取 `log10(power+1e-10)`，再应用冻结标准化；缺格在标准化后置零。
RMS、峰峰值、峰值因子和峭度均基于逐块去均值后的振动，不把重力与块间均值漂移计入动态幅值。
快状态格位于窗口起点至结束前 100 ms，只允许严格早于格位的观测；缺失值为零、有效位为零、年龄为 1。

保留慢状态 `[9,60]` 的外形，前 56 格无效，仅最后四格读取实际短历史；输入资产、标准化、频带权重和水平参考随包冻结。启动不重新拟合水平，不将当前姿态自动视为正常。质量条件沿用固定配置：至少 12 个可用振动块、TF 有效比例≥0.45、快状态最低有效率≥0.75、慢状态最后四格最低有效率≥0.60、姿态年龄≤1.5 s，以及块内采样、重力等检查。

保存造成的缺口触发有效位和质量判定；不满足条件时输出不可用。工作线程仅一个推断任务在途，另保留一个最新待处理窗口；输入队列和原生缓存有容量上限。时基跳变、标度变化或 source_run 改变时清上下文并重新等待四秒。

振动原生块独立计算，不跨缺口拼接或补造采样。`gap_before` 计入 `quality.gapBlocks`，
不单独作为整窗拒绝条件；是否可推断按运行包冻结的块数、TF/快慢状态有效率、姿态年龄及重力条件判断。
本地 DMA 读取按序回收环中仍保留的完成块，排除当前写入槽；复制并复查生产序号后才交给解析器。
已被覆盖或复制期间可能被覆盖的块不发布，真实缺失仍保留在时间轴及质量信息中。

上位机实现从运行包 `preprocess.json`（schema `mlk.fault.preprocess.v1`）读取冻结参数：`frequencies{bands,tf,psd,maxHz}`、`bands.weights[64][193]`、`norm.{tf,psd,stats,pose,fast,slow}.{mean,std}`、`pose.reference[3]` 与 `quality{minBlocks,minBlockSamples,minVibrationRateHz,tfRatio,fastRatio,slowRatio,poseAgeMs}`。缺项、长度不符或版本不符即报错并把状态置为 error，不用默认值继续推断。标准化参数长度按 TF `[8][64]`、PSD `[3][769]`、统计 `[12]`、姿态 `[5]`、快状态 `[6]`、慢状态 `[9]` 校验。

## 3. 引擎输入输出 ABI 草案

### 3.1 输入布局

batch=1，float32、小端、C 连续；`count=27683`，共 110732 字节，调用前已用固定训练参数标准化。共享库不得重复缩放或自行切窗。

| 分支 | 形状 | float 偏移 | float 数量 |
|---|---|---:|---:|
| time_frequency | `[8,64,48]` | 0 | 24576 |
| spectrum | `[3,769]` | 24576 | 2307 |
| vibration_stats | `[12]` | 26883 | 12 |
| mount_pose | `[8]` | 26895 | 8 |
| fast_state | `[6,40]` | 26903 | 240 |
| slow_state | `[9,60]` | 27143 | 540 |

分支内部顺序、原生块频谱和温度隔离以[部署与量化规划](../npu/fault-diagnosis/F3P部署与量化设计.md)为准。引擎检查输入长度、有限值、包身份和姿态有效位；上游另负责完整窗口质量。CPU 和混合后端使用同一输出解码，返回唯一类别及等级，不返回四个独立“是否故障”布尔值。

### 3.2 函数与结果结构

拟新增 `common/fault_engine_api.h`，动态库 `libmlk_fault.so`，`MLK_FAULT_ENGINE_ABI=1`。符号如下，具体 C 声明在实施时按此需求落地：

| 符号 | 参数与返回 |
|---|---|
| `mlk_fault_abi` | 无参数，返回 int ABI=1 |
| `mlk_fault_create` | root、backend、错误缓冲及容量；成功返回上下文指针，失败返回空 |
| `mlk_fault_predict` | 上下文、const float 输入、size_t 元素数、结果指针、错误缓冲及容量；0 成功，负数失败 |
| `mlk_fault_predict_masked` | ABI 1 可选扩展：在 count 后增加 uint32 类别排除位图；bit i 屏蔽类别 i，其他参数不变；未知位或屏蔽全部五类时失败 |
| `mlk_fault_destroy` | 上下文，无返回值；仅在在途调用结束后销毁 |

建议结果结构固定 32 字节，IEEE float32、字段按下表偏移排列，静态断言检查布局；不含指针或 Qt 类型。调用方先填写 `struct_size=32`，错误返回时仍清有效位。

| 字节偏移 | 字段 | 类型 | 含义 |
|---:|---|---|---|
| 0 | struct_size | uint32 | 固定 32；不匹配即拒绝调用 |
| 4 | valid | uint32 | 0 不可用、1 有效 |
| 8 | class_index | int32 | 有效 0..4；无效 -1 |
| 12 | grade | int32 | 正常 0，故障 1..3；无效 -1 |
| 16 | confidence | float32 | 有效 0..1；无效 -1，JSON 序列化改为 null |
| 20 | backend | uint32 | 1 CPU，2 CPU+CNN NPU，不沿用 FF6 文案 |
| 24 | infer_us | uint32 | 本次引擎调用耗时，不含预处理/等待时间 |
| 28 | reserved | uint32 | 0 |

加载时校验任务、架构、预处理及哈希、输入布局、分类顺序、温度隔离和有序分级阈值；不允许加载多标签权重并按五类解释。
构建与运行包生成见 [BUILD.md](ps-local/fault-inference/BUILD.md)。

内置实时诊断要求 masked 扩展。最近有效窗口温度不超过 35℃ 时仅排除过热类别，
从其余真实 logits 重新选择主类并输出该类等级；超过 35℃ 后恢复五类竞争。
温度缺失或过期时按窗口质量规则输出不可用。`quality.temperatureC` 记录策略所用温度，
`quality.overtemperatureMasked` 记录排除状态。原始数据集评估不应用此规则，模型权重和阈值保持。

## 4. 模型诊断 API 2

### 4.1 原始结果字段

同进程推荐排队信号连接至拟新增 `reportDiagnosisResult`，外部模型可使用 `/run/mlk-fault.sock` 的 api=2 分支。两者复用同一个校验器与所有权判定，不能分别维护两份当前状态。

| 字段 | 类型/上限 | 要求 |
|---|---|---|
| api / schema | int / string | 固定 2 / `mlk.fault.result.v2` |
| task | string | 固定 `bench_fault_single_v1` |
| model / preprocess | string，各≤64 ASCII 字节 | 包 ID / 冻结预处理版本，与已选运行配置匹配 |
| run | UUID string | 本次模型运行身份；启动/换包后更换 |
| seq | uint32 | 新窗口严格递增，从 1 开始；尚无窗口为 0；重发不增加 |
| startUs / endUs | 十进制 string | 窗口 UTC 微秒；有窗口时 end-start=4000000；无窗口均为 `"0"` |
| state | string | `stopped/loading/waiting/running/data_insufficient/stale/error/stopping` |
| valid | bool | 仅当前质量合格且未过期的结果为 true |
| classIndex / fault | int / string | 按下表固定对应，拒绝不一致组合 |
| grade | int | 正常 0，异常 1..3，无效 -1 |
| confidence | number 或 null | 有效时有限数 0..1；无效必须 null |
| backend | string | `cpu` / `cpu_cnn_npu`；加载前未知可为 `unknown` |
| preprocessUs / inferUs | uint32 | 分别记录预处理和引擎调用耗时，未知为 0 |
| reason | string，≤64 ASCII 字节 | 有效为空；无效为有界原因代码，如 `waiting_context`、`missing_speed`、`tf_coverage`、`engine_error` |
| quality | object，可选 | 本地诊断详情，含块数/有效率/丢块等；不作为新的模型物理输入 |

| classIndex | fault | 含义 | grade |
|---:|---|---|---|
| 0 | normal | 正常 | 0 |
| 1 | overload | 过载 | 1/2/3 |
| 2 | undervoltage | 欠压 | 1/2/3 |
| 3 | overtemperature | 过热 | 1/2/3 |
| 4 | mount_tilt | 电机倾斜 | 1/2/3 |
| -1 | unavailable | 不可用 | -1 |

有效结果示意，空白仅用于排版：

```json
{
  "api": 2, "schema": "mlk.fault.result.v2", "task": "bench_fault_single_v1",
  "model": "fault-single-candidate", "preprocess": "base6_native_blocks_short_context_v2",
  "run": "9b428b90-fc6a-4ee9-b6d3-83d4c7e44cf0", "seq": 12,
  "startUs": "1793400000000000", "endUs": "1793400004000000",
  "state": "running", "valid": true, "classIndex": 4, "fault": "mount_tilt",
  "grade": 2, "confidence": 0.96, "backend": "cpu",
  "preprocessUs": 0, "inferUs": 0, "reason": ""
}
```

有效结果的 state 必须为 running，seq 至少为 1。停止、缺数据或错误时保持 run/最后窗口身份用于追踪，但 `valid=false,classIndex=-1,fault=unavailable,grade=-1,confidence=null`；尚无窗口的 seq 为 0。零耗时是示例占位，不代表实际执行成绩。

### 4.2 生命周期、时效与响应

1. 本地模式由控制器创建并持有 run；外部模式经显式选择后接纳一个发布者 run。内置实时模式运行时拒绝 Socket、旧诊断注入等其他分类发布者，返回 `publisher_busy`。
2. 状态心跳可每秒重发；同一 run/seq 的分类、等级、分数和窗口时间不可改变，改变返回 `window_conflict`。同一窗口允许转为停止/过期等不可用状态，但不能据此重新变为有效。
3. 重发只续链路活跃时间，不更新最后新窗口的单调时钟年龄。不同 run 的晚到结果与倒序窗口拒绝；新 run 只能由模式管理器或新的外部会话接纳。
4. 初始结果最大年龄 6000 ms（REF），同时约束窗口结束时间与本地单调时钟。无效、过期、停止立即撤销当前模型告警；“N/A”不等于正常。系统时基跳变需新建运行上下文。
5. 原始分类立即显示；故障/恢复确认由上位机控制器统一执行，不更改原始 argmax。异常分数至少 0.80 且相同类别与等级连续两窗确认，恢复正常连续三窗（REF）。低于 0.80 仅显示低置信度候选，清除模型告警与累计确认，不生成故障工单，不解释为正常；完整状态和日志保留原始预测。0.80 是待实采标定的试用门槛，可能漏掉低分真故障，不能排除高分误判；数据集评估不应用该门槛。在途调用停止后晚到的结果按 run 失效处理。

Socket 沿用 Unix Stream、单连接单行 UTF-8 JSON+LF、最多八客户端、两秒超时。api=2 每行含 LF 上限拟为 4096 字节；api=1 保持 1000 字节。现有 `ModelFaultServer` 也服务采集 API，实施应增加每实例长度参数，不能把采集接口一并无条件放宽。`mlk-fault` CLI 与 C 客户端如需发布 v2，须同步其请求缓冲和错误处理。

api=2 响应建议为 `{"ok":true,"error":"","acceptedSeq":12}`，只表示原始状态已接收，不表示已确认故障或工单已落盘。拒绝返回 `ok=false` 和明确代码：`unsupported_api`、`invalid_result`、`identity_mismatch`、`publisher_busy`、`stale_result`、`window_conflict`。持久化状态独立显示，不复用一个 bool 混合表达模型有效性和存储成功。

## 5. 结构化工单与声光接口

### 5.1 新工单内容

拟在现有加密 MLKO 容器内增加 JSON schema `mlk.fault.order.v2`，继续使用 v4/type5 工单及 type6 ACK。保留已有顶层 `id/faultTimeUs/class/grade/message`，增加 `schema` 和结构化 `diagnosis`；未带 schema 的旧工单按 v1 读取。

| 字段 | 要求 |
|---|---|
| schema | 固定 `mlk.fault.order.v2` |
| id / faultTimeUs | 事件 UUID / 首次确认序列首窗结束 UTC；同事件保持不变 |
| diagnosis | 固定快照：`classIndex/fault/model/preprocess/run/seq/startUs/endUs/confidence`；只允许一个具体异常 |
| grade | 所选异常等级 1..3 |
| class | 兼容粗分类：grade=1→1，grade=2/3→2；新端不以此字段推断具体故障 |
| message | 可读具体类型与等级，v2 建议≤128 UTF-8 字节；不能以该文本作为机器类型来源 |

完整 JSON 保持≤1000 字节、顶层与 diagnosis 的类型/等级一致，不改变现有容器与传输尺寸边界。首次确认时冻结快照；置信度和后续窗口变化不重写同 ID。类别/等级确认变更生成新 ID，心跳不新增工单；加密保存或标签关联失败保留原事件重试。

现有 `reportModelState` 会重建只含五个旧字段的工单，不能承担 v2 事件保存。拟新增完整对象持久化入口，保存结构化 diagnosis，再驱动声光并更新兼容摘要。旧端可继续显示粗分类和 message，新端从 diagnosis 读取具体故障名；旧端不声明具备五分类显示能力。

`faultCaptureLabel` 识别新 schema，生成例如 `mount_tilt_grade_2`，author 为模型身份。
存在合法 `diagnosis.startUs/endUs` 时，标签区间取诊断窗口并设置 `scope=model_window`，
另存 `eventUs=faultTimeUs`、`classIndex`、`grade` 和完整 `diagnosis`；缺少窗口的历史工单保持事件点标签。
模型窗口表示该窗口的预测，不声明窗口内每一时刻均有故障，也不作为人工监督真值。

开始内置实时诊断时同步开启原始采集记录，记录口令为空时拒绝启动并提示配置。
诊断确认、停止诊断、打开波形回看时提交当前记录段；停止诊断保留记录开关的开启状态。
故障回看按诊断窗口与采集文件的时间交集关联所有分段，显示具体故障、等级和模型窗口标记。

### 5.2 声光

声光只需要确认后的 `valid`、是否正常和等级，无需知道故障类型。新的控制器可直接通过 `AlarmController::modelGrade(0..3)` 更新现有硬件路径：无效/正常→0，所选故障→1/2/3。保留现有 3/6/9 秒及抢占规则，不因新增四类而变更 PL 告警位域。

API v1 的 `class` 0/1/2 和 10 秒发布者超时仅保留兼容用途，不限制 v2 的 classIndex。PL v1.3、驱动及声光可用性仍按[声光告警接口](../docs/声光告警与模型故障API.md)执行。工单保存失败和物理告警有效必须分别展示。

## 6. 网络状态接口草案

UDP v6/type8 专用于完整故障状态；沿用现有加密会话、对端限制与抗重放。版本/类型拟分配值待接口确认后登记，不能只提高 `type` 上限而放开任意版本组合。

| 公共头偏移 | 字段 | 拟定值 |
|---:|---|---|
| 0 / 2 / 3 | magic:uint16 / version:uint8 / type:uint8 | `0x4B4D` / 6 / 8，小端 |
| 4 | seq:uint32 | 每个状态包的传输序号，可随心跳增加；不是模型窗口 seq |
| 8 / 12 / 14 | cnt:uint32 / rate:uint16 / n:uint16 | 保留为 0 |
| 16 | tsUs:uint64 | 最后已处理窗口的 endUs，无窗口为 0；心跳不改成当前墙钟 |
| 24 | reserved[4] | 全 0 |
| 28 | UTF-8 JSON | 诊断摘要，整帧≤1200 字节 |

载荷 schema 固定 `mlk.fault.status.v1`，使用 API 2 中的 `model/preprocess/run/seq/startUs/endUs/state/valid/classIndex/fault/grade/confidence/backend/preprocessUs/inferUs/reason`；task 为固定任务身份。省略本地 API 的 `api/schema/quality` 后，改用本消息 schema，并增加 `ageMs`、`alarmConfirmed`。无结果的年龄为 null；心跳重复结果时年龄继续增长。模型窗口 seq 和包传输序号分开，避免“同一窗口转为停止/过期”被误当重复包丢弃。

接收端只把新 run/新窗口作为新推断；心跳用于链路状态，停止/错误等状态更新可立即使同窗口无效。超过五秒未收状态，或结果 age 超过配置门槛则 N/A。使用板端报告的 age 加 PC 单调时钟经过时间，避免把 PC/板端 UTC 差当作结果新鲜度。

原有 BoardStatus v4/type7 中 `modelFault` 继续发 v1 粗摘要，仅兼容旧端；新端完整故障区域只由新消息控制，不受 RUL v3 帧或粗摘要覆盖。新增摘要单独发包，避免挤占已有 BoardStatus 的 1200 字节预算。首版远端只读，不传模型目录、不控制本地推断启动。

## 7. 控制与交付要求

拟新增本地 `FaultLiveController::start(root,backend)`、`stop()` 和状态通知；UI 发起异步请求，以“加载中/停止中”至最终状态完成，不在按钮回调中阻塞推断。开始前停止 RUL 并等待资源释放；关闭故障模式后不再接受旧 run 的结果。CPU/NPU 后端、包目录和标准化资产作为一个配置整体，运行中不能单独替换。

实现交付需同时提供原生块适配、引擎 ABI、API 2 校验、确认事件、完整类型显示及错误/过期语义；旧粗分类桥接不能作为完整接入完成条件。远端和 NPU 加速可分阶段交付，本地 CPU 实时链路先完成。本次不执行任何上述交付检查。
