# 故障模型接入与评估模式

本文说明单主故障分类分级模型在 PS 本地 Qt 应用中的接入方式，包括运行包生成、
共享库实现、两个工作模式的分工，以及寿命模型启动方式的调整。字段级接口以
[故障诊断模型接口需求](故障诊断模型接口需求.md)与
[故障模型与上位机接入](../docs/故障模型-上位机接入.md)为准；模块划分与线程模型见
[实时故障诊断实现](实时故障诊断实现.md)。

当前状态：引擎（CPU 与 CPU+CNN NPU 两个后端）、运行包生成器、检查程序与上位机
源码已实现，已使用 Linaro GCC 7.5.0、Arm NN 32.1.0 与 Qt 5.13.2 完成 AArch64
构建。共享库 CPU 后端通过 x86-64 与 QEMU 360 窗回放；Qt 开发机评估、取消、异常与
模式切换通过，证据见 [验证结果](tests/results/fault/summary.json)。输入绑定修复库的板端
NPU 两轮 360 窗通过，见[板端证据](tests/results/fault/tensor-binding.json)；界面操作与实采仍待验收。

类别顺序 `normal / overload / undervoltage / overtemperature / mount_tilt`，正常 0 级，
异常只输出所选类别的 1～3 级。

## 2. 运行包

### 2.1 目录内容

| 文件 | 必需 | 内容 |
|---|---|---|
| `model.json` | 是 | `mlk.fault.runtime.v1` 清单，含类别、输入、运行库与 `files` 哈希 |
| `preprocess.json` | 是 | `mlk.fault.preprocess.v1`，频带权重、六分支标准化参数、水平参考与质量门限 |
| `weights.bin` | 是 | BN 折叠后的 FP32 权重，连续区段存储 |
| `weights.tsv` | 是 | 每行 `名称 秩 dim... 元素数 偏移` |
| `thresholds.bin` | 是 | 8 个 float32，四类故障各两个分级阈值 |
| `qparams.tsv` | 是 | 四层 UINT8 尺度，CPU 后端不读取 |
| `libmlk_fault.so` | 是 | 共享库，名称取自 `model.json.runtime.library` |

### 2.2 model.json

```json
{
  "schema": "mlk.fault.runtime.v1",
  "model": "f3p-fault-single-v1",
  "task": "bench_fault_single_v1",
  "contract": "single_primary_fault_v1",
  "preprocess": "base6_native_blocks_short_context_v2",
  "input": {"layout": "base6_single_native4s_flat_v1", "floats": 27683},
  "classes": ["normal", "overload", "undervoltage", "overtemperature", "mount_tilt"],
  "runtime": {"abi": 1, "library": "libmlk_fault.so", "backends": ["cpu", "cpu_cnn_npu"]},
  "execution_plan": "four_hard_npu_conv3x3_cpu_relu_pool",
  "checkpoint_sha256": "727801db…95226",
  "files": {"libmlk_fault.so": "…", "weights.bin": "…", "preprocess.json": "…"}
}
```

`backends` 默认声明 `cpu` 与 `cpu_cnn_npu`，两个模式默认都选 `CPU+CNN NPU`，与
离线测试包板测使用的 `hybrid_split` 计划一致；CPU 后端保留用于数值对照与 NPU
不可用时的显式选择。共享库只有在设置 `ARMNN_ROOT` 构建时才有 NPU 实现，此时
`create` 返回 `cpu_cnn_npu backend is not available in this library`，不静默回退
CPU。`--backends cpu` 可生成只声明 CPU 的清单，用于仅编译 CPU 后端的环境。

生成包的权重与尺度可直接追溯：`weights.bin` 的 SHA-256 为
`0e4cf734d67a6e0babb79c76f32d7a7912787aec928e9f30ddd95a19269300af`，
`qparams.tsv` 为 `64c4211d098f78c8358120ae014c6c2bd63a2a2f94b95a34342f40b7b7b17e26`，
与[故障模型与上位机接入](../docs/故障模型-上位机接入.md)记录的板测资产一致；
`build_runtime.py` 只搬运这两个文件，不重新导出权重。

### 2.3 preprocess.json 的字段来源

训练侧 `preprocess.json` 的参数名与布局和加载器不同，生成器按下表转换；只改变
表示，不重新拟合。

| 加载器字段 | 训练侧来源 | 长度与处理 |
|---|---|---|
| `bands.weights` | `band_weights` | 64×193，原样 |
| `norm.tf.mean/std` | `parameters.time_frequency` | 3×64 → 8×64；通道 0～2 为三轴，3～7 取 0/1（固定布局占位） |
| `norm.psd.mean/std` | `parameters.spectrum` | 3×769，原样 |
| `norm.stats.mean/std` | `parameters.vibration_stats` | 12，原样 |
| `norm.pose.mean/std` | `parameters.mount_pose` | 5，原样 |
| `norm.fast.mean/std` | `parameters.fast_state` | 2 → 6；电流/转速两量参与标准化，有效位与年龄不缩放 |
| `norm.slow.mean/std` | `parameters.slow_state` | 3 → 9；温度/电流/转速三量参与标准化 |
| `pose.reference` | `dsp.level_reference.reference_vector_g` | 3，水平重力参考 |
| `quality.*` | `dsp.min_blocks_per_window` 等 | 12 块、64 点、1600 Hz、0.45 / 0.75 / 0.60、1500 ms |

生成后自检：`schema`/`preprocess` 身份、频带权重 64×193、六组 mean/std 长度、
水平参考长度、质量项齐全、`files` 逐项哈希与实际文件一致、运行库存在。

## 3. 共享库

### 3.1 ABI

四个 `extern "C"` 符号与 [fault_engine_api.h](common/fault_engine_api.h) 一致：
`mlk_fault_abi`、`mlk_fault_create`、`mlk_fault_predict`、`mlk_fault_destroy`。
结果固定 32 字节；调用方先写 `struct_size=32`，不符即拒绝；无效结果清
`valid/class_index/grade/confidence`，不返回“正常”。

### 3.2 CPU 后端实现

前向与独立测试程序的 `cpu` 模式逐项一致：

1. 输入前 24576 个 float 作为 `[8,64,48]` 卷积输入；
2. 四层 3×3 卷积（补一圈零），每层后接 ReLU 与 2×2 MaxPool；通道数 8→16→32→64→64，末层输出 64×4×3=768；
3. 六分支编码：TF 768→64、频谱 2307→32、统计 12→16、姿态 8→16、快状态 240→32，拼成 160 维公共向量；
4. 慢状态按机械/温度两组各 540→64，与公共向量拼成 224 维后融合 128 维，输出 9 维；
5. 温度隔离：过热类别（索引 3）与其分级（索引 7）取自温度路径，其余取机械路径；
6. 解码：前 5 维取最大为类别，`softmax` 最大项为分数；故障等级按
   `1 + [score >= t0] + [score >= t1]` 映射到 1～3 级。

上下文在工作线程创建并串行调用，内部互斥保护；`create` 阶段解析全部张量，
缺名称或维度不符即失败，不在逐窗推断中才暴露。`destroy` 等在途调用结束后释放。

### 3.3 CPU+CNN NPU 后端

定义 `MLK_FAULT_HAVE_ARMNN` 时编译（`build_arm.sh` 设置 `ARMNN_ROOT` 即启用），
计划与离线测试包的 `hybrid_split` 相同：

1. 用 `qparams.tsv` 的四组尺度量化卷积权重与偏置，尺度必须逐层衔接（`sy[i] == sx[i+1]`）；
2. 四个卷积各自成为只允许 `Alnpu` 的独立图，加载后解析图属性，要求计算节点全部为
   `ALHardNPU` / `ALSoftNPU` 且至少一个硬核节点，出现其他后端即失败；
3. 每层输入输出用持久 CMA 缓冲，`EnqueueWorkload` 前后做设备与 CPU 的缓存同步；
4. 层间 ReLU 以 UINT8 零点 128 截断，再在 CPU 做 2×2 MaxPool；末层输出按
   `(u8 - 128) × sy` 反量化后进入 CPU 融合头与解码；
5. 初始化顺序为量化尺度 → CMA 会话 → runtime → 四个图；销毁逆序解除图、释放
   CMA、销毁 runtime，允许完整重建下一实例。

运行库、驱动与码流须与板测一致（`libarmnn.so.32.1`、`/dev/hard_npu`、
`/dev/soft_npu`、`/dev/cma_mem`）。未启用该宏时 `mlk_fault_create` 对后端 2 返回
`cpu_cnn_npu backend is not available in this library`，不做静默 CPU 回退。

## 4. 上位机两个模式

「故障诊断」面板用两个页签承载，互相独立，同一时间只运行一个。两个模式的后端
选择都默认 `CPU+CNN NPU`，与离线测试包的板测计划一致；`CPU` 保留用于数值对照，
或用于 NPU 设备不可用的环境。

### 4.1 实时诊断

沿用既有链路：`DriverSource → onFrame/onSpeedSample → FaultInputAdapter →
FaultLiveController.enqueue → FaultWorker → FaultPreprocessor → FaultRuntime →
libmlk_fault.so → FaultLiveController`。

- 输入是当前真实采集的原生块，按四秒窗口、两秒步长调度，质量不合格时给出原因码；
- 结果经确认状态机后驱动物理告警、`mlk.fault.order.v2` 工单与 UDP v6/type8 摘要；
- 包目录、后端、开始/停止与结果详情与既有实现一致；启动前会等待寿命回放释放引擎，避免两者同时占用 NPU 与 CMA。

### 4.2 数据集评估

按已有数据集统计分类与分级准确度，不产生告警、工单或网络包。

评估集目录：

```text
<评估集目录>/
  evalset.json       # mlk.fault.evalset.v1
  test_inputs.bin    # 逐窗 27683 个 float32，小端
  test_index.csv     # 每窗真值：class_target / grade_target
```

`evalset.json` 字段：`schema`、`model`、`task`、`inputs`、`index`、`samples`、
`inputFloats`、`classes`、`inputStage`。加载时校验四项：身份与输入长度、索引列、
输入文件长度与窗口数一致、真值范围 0～4 / 0～3；任一不满足即拒绝，不使用默认值补齐。

流程：`FaultDataset::load` 读清单与索引 → 评估线程按窗读取 27683 个 float →
`FaultRuntime::predict` 逐窗调用共享库 → 与真值比对累计。后端可选 `CPU+CNN NPU`
（默认）与 `CPU`；NPU 需要硬 NPU、软 NPU 与 CMA 设备，加载失败时评估直接报错，
不换后端重试，避免把两种后端的数字混在一份报告里。

统计项：

| 指标 | 定义 |
|---|---|
| 类别准确率 | 预测类别等于 `class_target` 的窗占比 |
| 联合准确率 | 类别与等级同时等于 `class_target`/`grade_target` 的窗占比 |
| 故障窗联合准确率 | 仅在 `class_target != 0` 的窗上计算联合准确率 |
| 类别混淆矩阵 | 5×5，行为真值、列为预测 |
| 分级混淆矩阵 | 4×4，等级 0～3 |
| 逐类联合 | 每类「类别+等级」同时正确的窗数与占该类样本的比例 |
| 处理速度 | 单窗引擎调用时间的平均、中位、P95、峰值与换算的窗/秒；不含读盘与界面刷新 |

界面以滚动区域显示进度、汇总行、处理速度行、逐类表格与两个混淆矩阵，适配 1080p；「导出报告」把
`mlk.fault.eval_report.v1` 写入评估集目录的 `fault_eval_report.json`，报告含所用
后端、准确率、混淆矩阵与耗时统计。

评估集由运行包生成器的 `--eval-output` 生成，取离线包的 `data/test_inputs.bin`
与 `data/test_index.csv`。这些是训练侧已标准化的冻结特征，因此该模式评估模型的
分类与分级能力，不覆盖采集、预处理与时间对齐。

## 5. 配置与启动

| 键 / 变量 | 含义 | 默认 |
|---|---|---|
| `fault/modelDirectory` | 运行包目录（两个模式共用缺省值） | `/opt/mlk_fault` |
| `fault/backend` | 实时诊断后端：1 CPU、2 CPU+CNN NPU | 2 |
| `fault/evalBackend` | 数据集评估后端 | 2 |
| `fault/evalDirectory` | 数据集评估目录 | 空 |
| `inference/mode` | `off`、`fault`、`fault-external` | `off` |
| `MLK_FAULT_ROOT` | 覆盖运行包目录 | — |
| `MLK_FAULT_EVAL_ROOT` | 覆盖评估集目录 | — |
| `MLK_FAULT_SOCKET` | 模型 API Socket 路径 | `/run/mlk-fault.sock` |

启动后不自动加载故障模型，也不自动开始诊断或评估；面板按钮与远端指令是唯一入口。
模式互斥：实时诊断进行中启动评估会被拒绝，评估进行中启动实时诊断会先取消评估并
等待引擎释放；寿命回放完成后仍须卸载上下文。等待超过 8 s 只报告超时，不启动新模型。
停止可取消尚未启动的请求，评估停止后可重新启动。同一 run/seq 的重复发布不累计确认窗口。

## 6. 寿命模型启动方式

数据集回放改为纯手动：

- 删除构造函数的开机自动回放分支、自动续播与自动后端回退，`m_autoBackend`、
  `m_loopPending` 一并移除；
- 启动入口只有本地面板「开始/继续」与远端 `kTypeReplayControl` 指令；
- `MLK_RUL_AUTOSTART` 与 `MLK_RUL_LOOP` 不再被读取，保留在测试脚本中无副作用；
- `/opt/mlk_rul/model.json` 只作为模型目录缺省值，不触发加载。

后端仍由面板选择：`CPU/NPU` 需要 `/dev/hard_npu`、`/dev/soft_npu`、`/dev/cma_mem`，
选择失败时显示错误，不自动切换到融合 CPU。

## 7. 预处理数值一致性

实时预处理的年龄通道按训练侧语义归一化，与本仓库此前写入毫秒原值的实现不同：

| 通道 | 训练侧语义 | 当前实现 |
|---|---|---|
| 姿态年龄 | `age_s / pose_max_age_s`，截断到 [0,1] | 与之一致 |
| 快状态年龄（电流/转速） | `age_s / state_gap_s`，不可用为 1 | 与之一致 |
| 慢状态年龄（温度） | `age_s / temperature_max_age_s`，不可用为 1 | 与之一致 |
| 慢状态年龄（电流/转速） | `age_s / state_gap_s`，不可用为 1 | 与之一致 |

依据是训练侧 `preprocessing.py` 的 `past_values`（归一化年龄，无效时取 1.0）与
`mount_pose.py`（`clip(age_s / max_age_s, 0, 1)`）。此前实现写入毫秒原值，慢状态
不可用格写 `-1`，与训练分布不一致，会让年龄通道偏离模型见过的取值范围。该修正
只改数值语义，不改变字段名、质量门限或阈值。
