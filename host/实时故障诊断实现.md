# 实时故障诊断实现

本文说明 ps-local 与 remote-pc 中实时故障诊断链路的模块划分、数据流向、接口边界、配置项与验证状态。字段级接口以[故障诊断模型接口需求](故障诊断模型接口需求.md)为准，改动位置与优先级见[上位机改造清单](故障诊断上位机改造清单.md)，模型部署与预处理算法见[部署与量化规划](../npu/fault-diagnosis/F3P部署与量化设计.md)。

当前状态：故障共享库、检查程序与 Qt 应用已完成 AArch64 构建；CPU 共享库通过 x86-64 与 QEMU 360 窗回放，开发机 Qt 评估、停止、过期、乱序与模式切换通过。证据见 [results/fault](tests/results/fault/summary.json)。输入绑定修复库已完成板端 NPU 两轮 360 窗，见[板端证据](tests/results/fault/tensor-binding.json)；HDMI 界面操作、双端与实采预处理验收待定。

模型独立程序已完成四卷积硬 NPU 的 360 窗 test 板测，结果见[板测报告](../npu/fault-diagnosis/deploy/BOARD_TEST.md)。该结果不替代本应用的预处理与共享库验收；参数来源、正式运行包生成和部署步骤见[故障模型与上位机接入](../docs/故障模型-上位机接入.md)。

## 2. 数据流

1. `DriverSource` 发出波形帧；`KLocalWindow::onFrame` 先按既有路径打时间戳，供显示、记录与网络分片使用。
2. 同一 stamped Frame 交给 `FaultInputAdapter::acceptFrame`，生成原生物理块；转速在 `onSpeedSample` 中去重后由 `acceptSpeed` 生成独立块。
3. 块经 `FaultLiveController::enqueue` 进入 `FaultWorker` 的有界队列；UI 线程只做入队。
4. 工作线程按两秒步长取 `[end-4s, end)` 窗口，只使用完整落入窗口的块；积压时丢弃旧窗口，只处理最新一个。
5. `FaultPreprocessor::build` 生成 27683 个已标准化 float；质量不满足时返回原因码，不调用引擎。
6. `FaultRuntime::predict` 调用 `mlk_fault_predict`，返回唯一类别、所选等级、分数与计时。
7. 工作线程发布原始结果；控制器校验 run/窗口归属，执行确认与时效判定，向界面、摘要发包与工单链路发布。
8. 界面更新「实时故障诊断」区块；控制器确认事件触发 v2 工单落盘与标签写入；摘要以 UDP v6/type8 发给 remote-pc。

DMA 振动帧的首样本时间由 PL 100 MHz 时间戳锚定 UTC 后计算，32 位回绕按差值展开；
相邻块不按 Qt 收到帧的时刻拼接，避免轮询抖动产生伪缺口。UTC 跳变时重新锚定；
采集时间倒退或超过四秒的中断会清空旧上下文，重新等待四秒。真实采样缺口仍按质量门限拒绝。
转速每个有效事件仅包含一个观测，`SPEED_COUNT` 为累计成功次数，不是块内样本数。

内置诊断启动时开启加密原始记录；停止诊断、确认故障和打开回看时提交当前段。
记录口令须先在配置中设置，记录可在停止诊断后单独关闭。波形回看和标签关联见
[采集记录接口](../docs/采集记录-回放与训练接口.md)。

「仅保留异常波形」默认关闭，适用于先植入故障再启动诊断的验证流程，保留误判分析所需数据。
日常运行可开启，只有本次诊断中已被有效正常窗口完整覆盖的旧分段才清理；
故障候选、质量不足、引擎错误及传感器告警窗口保护前后各 10 秒。策略实现为
[`faultrecordpolicy.h`](ps-local/src/faultrecordpolicy.h)，历史记录和未判明的数据保持。

## 3. 单位与时间

| 通道 | 输入单位 | 模型单位 | 说明 |
|---|---|---|---|
| 温度 | signed16 × 0.1 ℃（按 `k×raw+b` 换算） | ℃ | 使用记录中的标定快照 |
| 电流 | 数据源已换算为 mA | A | 模型入口除以 1000，不重复应用 ADC 增益 |
| 振动 | signed16 × 0.0039 g，三轴 | g | 三轴数量必须相等 |
| 转速 | signed32 × 0.1 rpm | rpm | 不在模型入口改用 `rpm_milli` 高精度值 |

块时间 `t0` 为估算 UTC 首样本时刻，块结束时间为 `t0 + (count-1)/rate`。首个窗口从第一个振动块开始积累四秒，随后每两秒形成新窗口；`startUs`/`endUs` 之差固定为 4000000 µs。同一 Frame 不重复换算时间或物理单位。

## 4. 窗口、预处理与质量

预处理读取运行包 `preprocess.json`（schema `mlk.fault.preprocess.v1`）：`frequencies{bands,tf,psd,maxHz}`、`bands.weights[64][193]`、`norm.{tf,psd,stats,pose,fast,slow}.{mean,std}`、`pose.reference[3]`、`quality{minBlocks,minBlockSamples,minVibrationRateHz,tfRatio,fastRatio,slowRatio,poseAgeMs}`。缺项或长度不符即报错，不使用默认值继续推断；默认阈值为 12 块、64 点、1600 Hz、0.45 / 0.75 / 0.60、1500 ms。

| 原因码 | 触发条件 |
|---|---|
| `waiting_context` | 尚无完整四秒历史，或窗口内没有可用振动块 |
| `gap` | 窗口内部存在缺块 |
| `tf_coverage` | TF 有效格比例低于门槛 |
| `missing_state` | 快状态两量最低有效比例低于门槛 |
| `slow_state` | 慢状态末四格三量最低有效比例低于门槛 |
| `pose_age` | 姿态年龄超过门槛 |
| `gravity` | 重力模长偏离 1 g 超过 0.25 g |
| `engine_error` | 引擎调用失败或运行库未就绪 |
| `engine_invalid` | 引擎返回不可用结果 |
| `result_timeout` | 有效结果超过 6000 ms 未更新 |
| `loading` / `stopping` / `stopped` | 任务加载、停止过程与停止后状态 |

窗口内首个块之前的缺口属于窗口外上下文，不据此判废。时基跳变、标度变化或数据源重连后创建新的 `source_run`，工作线程清空缓存并重新等待四秒。

## 5. 引擎 ABI 与运行包

| 项目 | 约定 |
|---|---|
| 符号 | `mlk_fault_abi`、`mlk_fault_create`、`mlk_fault_predict`、`mlk_fault_destroy` |
| ABI | `MLK_FAULT_ENGINE_ABI=1` |
| 输入 | `count=27683`，float32、小端、C 连续，调用前已标准化 |
| 结果 | 固定 32 字节；调用方先写 `struct_size=32`，不匹配拒绝调用 |
| 后端 | 1 CPU、2 CPU+CNN NPU；加载失败不回退 |

加载顺序：`model.json` 存在性 → `schema=mlk.fault.runtime.v1` → 任务与分类契约 → 预处理版本 → 输入布局与 27683 → 类别顺序 → ABI 与后端声明 → 运行库与 `preprocess.json` 存在 → 清单中的文件哈希。全部通过后加载动态库、调用 ABI、创建上下文；任一失败把状态置为 `error` 并显示原因。

## 6. API 2、所有权与时效

1. 内置实时任务与外部分类发布者互斥：内置运行时 Socket 与同进程 v1 入口均返回 `publisher_busy`，旧分类注入不覆盖当前状态。
2. 同一 `run` 的 `seq` 严格递增；同窗口的分类、等级、窗口时间不可改变，改变返回 `window_conflict`；倒序窗口与不同 run 的晚到结果拒绝。
3. 确认不改变原始 argmax：异常分数至少 0.80 且相同类别与等级连续两窗确认，恢复正常连续三窗清除（REF）。低于 0.80 时显示低置信度候选，清除模型告警及累计确认，不生成工单，不转换为正常；逐窗日志和完整状态保留原始分类与分数。0.80 是待实采标定的试用门槛，可能漏掉低分真实故障，也不能排除高分误判；冻结数据集评估不应用该门槛。确认时冻结快照，类别或等级变化形成新事件。
4. 有效结果最大年龄 6000 ms，以窗口结束时间与本地单调时钟共同约束；超时、无效、停止立即撤销模型告警，界面显示 N/A 与原因码。
5. Socket 每行上限：api=2 为 4096 字节，api=1 与采集接口保持 1000 字节；响应 `{"ok":true,"error":"","acceptedSeq":N}`，拒绝码为 `unsupported_api`、`invalid_result`、`identity_mismatch`、`publisher_busy`、`stale_result`、`window_conflict`。

## 7. 工单与标签

| 字段 | 取值 |
|---|---|
| `schema` | `mlk.fault.order.v2` |
| `id` | 确认时生成的 UUID |
| `faultTimeUs` | 首次确认序列首窗 `endUs` |
| `class` | `grade=1` 为 1，`grade=2/3` 为 2，仅兼容旧端 |
| `grade` | 所选异常等级 1..3 |
| `message` | 具体类型与等级，UTF-8 ≤128 字节 |
| `diagnosis` | `classIndex`、`fault`、`model`、`preprocess`、`run`、`seq`、`startUs`、`endUs`、`confidence` |

整单 JSON ≤1000 字节；保存失败仍驱动物理告警，事件保留待重试。标签为 `<fault>_grade_<grade>`（如 `mount_tilt_grade_2`），`author` 为 `model:bench_fault_single_v1`，`note` 取 `message` 并截断到 512 字节；无 `diagnosis` 的 v1 工单仍生成 `class_<class>_grade_<grade>` 与 `author=model`。标签是预测，不表示窗口内所有时刻都存在该故障。

ps-local 每两秒请求一个后台重发批次；扫描和 PBKDF2 不在采集事件循环执行。工作线程持有同目录、同口令的 `WorkOrders` 实例，最多缓存 32 条认证结果；每次仍读取并比较完整密文，文件变化重新认证，口令或目录变化销毁旧缓存并拒绝旧批次返回。ACK 后不再进入待发清单，重复重试不重复派生相同文件的密钥。加密格式、100000 次 PBKDF2 和 GCM 校验保持。停止诊断和记录不会删除未确认工单。

逐窗日志剩余空间参数统一使用 MiB；仅在保留策略实现中换算成字节。原始低分预测仍按正常日志策略保留，不作为已确认故障标签。

## 8. 本地界面

「故障诊断」面板分为「实时诊断」与「数据集评估」两个页签，同一时间只运行一个。

实时诊断页包含包目录、后端选择、开始/停止、状态与原因、唯一具体故障、所选等级、分数、窗口时间、后端、预处理与推断耗时、结果年龄以及块数/有效比例等质量信息。开始诊断前停止 RUL 回放并等待引擎释放；标度或电流参数变化、电流归零时自动停止并撤销有效位。RUL 回放与故障诊断互斥，启动其中一类前必须先停止另一类。

数据集评估页包含运行包目录、评估集目录、开始/停止、进度、类别与联合准确率、逐类表格、类别与分级混淆矩阵以及报告导出；评估线程逐窗调用同一共享库，只读评估集，不产生告警、工单或网络包，实现见[故障模型接入与评估模式](故障模型接入与评估模式.md)。

## 9. 远端显示

完整故障状态使用 UDP v6/type8：28 字节头（`tsUs` 为最后窗口 `endUs`）+ `mlk.fault.status.v1` JSON，整帧 ≤1200 字节。remote-pc 按 `run` 与 `seq` 判定窗口身份，同窗口重发只续链路时间；5 秒未收到消息或结果年龄超过 6 秒显示 N/A，不显示为正常。BoardStatus v4/type7 的 `modelFault` 继续承载 v1 粗摘要，RUL v3 帧与粗摘要均不覆盖具体故障类型。
