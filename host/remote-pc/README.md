# remote-pc 远程采集与运维看板

本应用在 PC 上通过 UDP 接收板卡采集、模型状态及故障工单，使用与 [ps-local](../ps-local/README.md) 相同的深色主题、四传感器布局、模型面板、指标及核心板资源侧栏。PC 不加载板端 ARM 推理包。

具体故障类型与所选分级的新版状态/工单接口见[模型接口需求](../故障诊断模型接口需求.md)，解析器、显示与工程修改位置见[上位机改造清单](../故障诊断上位机改造清单.md)。这些均为待实施方案；当前粗分类和 RUL 消息不具备完整五类诊断语义。

首次配对、密钥生成 / 公钥交换、自动连接与 PC 自动启动步骤见 [连接与密钥配置](../../docs/上位机连接与密钥配置.md)。已配对设备默认自动发现同网段对端，应用启动后自动监听，无需重复填写 DHCP 地址。

## 界面与配置

| 入口 | 行为 |
|---|---|
| 左上「展开」 | 展开板端资源、监听地址 / 端口和监听开关；指标来自板卡，无回包时不可用 |
| 左上「展开」右侧 | 上行显示核心板网络（未连接 / WiFi / 4G / 有线），下行为应用连接状态：未连接、等待配对、等待板卡、正在握手、明文已连接、加密已连接、连接超时；5 秒未收到目标有效包即超时 |
| 指标「应用往返」 | 配置查询与匹配回复的单调时钟耗时，包含网络及两端处理 / 排队；不依赖跨设备校时 |
| 指标「数据时间差」 | 电脑 UTC 减波形时间戳，包含时钟差和采集 / 排队时间；v5 使用首样本 UTC，不能解释为网络耗时 |
| 「配置」 / F2 | 验证本机配置密码，初始 `root`，可独立修改 |
| 「记录」 | 按本机分段时长始终加密保存四传感器全部接收样本 |
| 配置 · 记录管理 | 「清理所有记录」确认后删除本机目录全部 MLKC / MLKF；「删除选定记录」在文件选择器中多选删除；保留寿命、工单与标签 |
| 「记录列表」 | 查看本机采集记录与故障工单，双击打开独立的波形 / 数据窗口 |
| 「回放」 | 独立二级窗口；异常 / 全部记录 / 故障清单，单击或选中后按回车加载；悬停、滚动和清单刷新保留当前波形；支持四传感器波形、播放定位、数据表、人工标注与 CSV 导出 |
| 模型面板 | 显示板端寿命结果，支持数据集回放；故障分级右侧显示故障时间 |

顶栏右侧按「未记录 / 记录中」「记录列表」「回放」「配置」排列。PC 使用物理键盘，不提供虚拟键盘、板端 WiFi 配置按钮和时间同步按钮（与核心板连通即具备网络）。配置密码、记录口令、保存目录、FFT 与刷新率独立于 ps-local；默认记录目录为 Qt 应用数据目录下 `records/`。共享的通道 `k/b`、告警上下限、使能与电流标定默认由 ps-local 决定；板端切换到 remote-pc 优先后，PC 保存的共享值在连接时提交并覆盖板端，离线修改在下次连接后生效。电流零点 / 增益由板端归零与传感器量程维护，PC 只读。共享参数与链路 / 密钥独立，修改本地设置不要求先配置 IP 或密钥。

系统占用侧栏的 NPU 与 CPU / 内存使用相同布局，包含状态、禁用的使用率条及硬核 / 软核活动历史曲线（次 / 秒）。NPU 与网络状态均来自板端 BoardStatus 的 v1 扩展；字段缺失或非法时显示不可用，5 秒状态超时后清除 NPU 曲线。顶栏两行字体与 CPU / 内存摘要一致；上行不反映 PC 本机网络。

连接状态和样式只在状态变化时更新，持续接收数据不触发每包重设样式。波形仍保存全部接收样本，绘图刷新按本机 UI 刷新率执行。时间指标的计算范围与有效期见 [接口契约 §7](../../docs/上位机-PS接口约定.md#7-时间与延迟)。

设置 `MLK_LINK_METRICS_LOG=1` 后，启动终端每 5 s 输出一次应用往返和数据时间差，便于结合 `ss -unmp` 的接收队列观察处理积压。

## 构建与连接

```sh
cd host
nix develop
mkdir -p remote-pc/build
cd remote-pc/build
qmake ../mlk_udp_host.pro
make -j4
./mlk_udp_host --listen 8000 --target 192.168.1.10:8000
```

构建后的日常启动可从仓库根执行 `host/remote-pc/run_host_app.sh`；上述显式 IP / 端口参数用于手动连接。Linux 桌面会话自动启动使用 `bash tools/install_remote_pc.sh install`。

启动脚本加载的 Nix 环境包含同版本 Qt 5 的 XCB 与 Wayland 平台插件及其搜索路径，可沿用桌面的 `QT_QPA_PLATFORM=wayland`。在已启动 XWayland 的桌面中，可用 `env QT_QPA_PLATFORM=xcb ./run_host_app.sh` 显式选择 XCB。无需在运行脚本前再次进入 `nix develop`。

两端上报目标需互相对应：PC 目标是板端 IP / 监听端口，板端目标是 PC IP / 监听端口。接收端校验源 IP / 端口。以太网、WiFi 使用同一协议。安全封装版本为 v2，两端需配套更新；PSK 为 32 字节、64 个十六进制字符，ECDH 需分别生成本机密钥并固定对端公钥。

采集使用 UDP v6（首样本 UTC），兼容接收 v5 / v4 / v2，振动包含三轴；电流为 signed32 mA，转速为 signed32、0.1 rpm/LSB，方向在 PS 统一修正。寿命结果与回放控制使用 UDP v3，两端后端默认选择 `CPU/NPU（FF6 六分支）`，对应板端校验后的后端 `2`；下拉框跟随实际后端，状态刷新保留未提交的手动选择。板端自动启动混合后端失败时回退融合 CPU；模型只输出寿命回归时分类 / 分级显示 N/A。模型不凭剩余寿命生成故障工单。

## 本地保存与工单

- 采集文件 `.mlkc`：按 10 / 30 / 60 / 300 s 分段，始终加密；保存温度、电流、转速、振动 XYZ 的原生样本、时间、速率与标定。PC 仅保存收到的样本，UDP 丢失的数据不能恢复。
- 寿命文件 `rul/*.mlkr`：有效 v3 结果自动保存。
- 工单文件 `orders/*.mlko`：独立事件 ID、故障 UTC 时间、分类 / 分级与说明，始终加密。只有工单和事件标签保存成功才向板端发送确认；重复 ID 同内容不重复写入，不同内容拒绝。

工单 API、WiFi / 无 SIM 联调、控制权和验证边界见 [无线联网与双端协同](../../docs/无线联网与双端协同.md)。模型部署见 [六分支运行包](../ps-local/inference/README.md)，协议见 [接口契约](../../docs/上位机-PS接口约定.md)。

## 开发联调

`--demo` 生成本机演示数据，不能作为真实采集或板端通信证据。「模拟注入」保留 v2 四值发送工具；当前板端寿命模型不使用该接口。加密测试与双端回环测试见 [测试规程](../tests/README.md)。

模型分类状态随 BoardStatus 同步并与 RUL 结果同时显示；通道告警勾选和上下限沿用双端共享配置权限。声音由板端 PL 输出，接口与验收见[声光告警与模型故障 API](../../docs/声光告警与模型故障API.md)。

故障清单按故障时间关联本机采集分段，打开后可查看四传感器波形和数据并导出 CSV；没有对应记录时显示缺失原因。工单本身不携带完整波形，PS 记录可复制后使用原口令读取。MLKC / MLKL 字节格式、标签 API、CSV 字段与解密命令见 [采集记录、回放与训练接口](../../docs/采集记录-回放与训练接口.md)。

电流零点与增益在双端配置中共用板端确认值，默认对应 ACS712-20A 的 100 mV/A。电机停转且无电流时在 ps-local 点击「归零」，重启后恢复实际零点。采集使用 UDP v6，记录载荷使用 mlk.capture.v2；两端应用与 mlk-capture 需配套更新，读取兼容原有 UDP 与采集记录。PL 码流无需更新。
