# host — 上位机需求与设计

> 面向竞赛选题四·领域 5（设备智能运维 / 故障诊断）。本文定义上位机要做什么、显示什么、怎么连、存什么、配什么，以及两部分（PC 端与 PS 端本地）的分工。
> 需求来源：[`../docs/竞赛题目及要求.pdf`](../docs/竞赛题目及要求.pdf)（选题四，评分 §（一）（二））；接口真值见 [`../docs/PL-PS接口约定.md`](../docs/PL-PS接口约定.md)、[`../docs/上位机-PS接口约定.md`](../docs/上位机-PS接口约定.md)、[`../docs/NPU-AI接口约定.md`](../docs/NPU-AI接口约定.md)。

当前单主故障模型的原生数据、独立引擎 ABI、五类诊断 API 2 和结构化工单需求见[模型接口需求](故障诊断模型接口需求.md)，待实施的文件/函数改动见[上位机改造清单](故障诊断上位机改造清单.md)。新增诊断显示具体故障类型与所选等级；本文“正常/轻微/重度”用于既有界面及兼容摘要，不作为具体故障类型枚举。

## 1. 需求来源

选题四评分项到上位机职责的对应：

| 来源 | 要求 | 上位机职责 |
|---|---|---|
| 基础必做 2 | Linux 系统 + 基础交互界面；HDMI 可视化曲线 / 参数配置界面 | PS 端本地 Qt（HDMI 看板 + 参数配置）；PC 端完整 UI |
| 基础必做 4 | NPU 单工况 / 缺陷分类；多类别 / 多任务 | 显示分类结果、分级、剩余寿命 |
| 基础必做 6 | 量化报告：采集延迟、AI 耗时、总线稳定性 | 显示采集延迟 / AI 推理耗时 / 丢包 |
| 拓展 1（高级） | 多通道并行、频谱分析 | 频谱（FFT）显示 |
| 拓展 4（高级） | 多故障分类、故障分级、剩余寿命预测、工单推送 | 分级 / 剩余寿命 / 工单显示与导出 |
| 拓展 5 | 本地 SD 存储、千兆网上传；4G 远程、OTA、数据加密 | 加密存储、网络 / 4G 接入、配置下发 |
| 拓展 6 | 连续稳定运行、宽温、低功耗 | 长时运行、资源受限下的一屏显示 |

领域 5 的传感器固定四类：**温度、电流、振动、转速**；被测电机独立运行，本系统只采集。

## 2. 分工

| | PC 端 [`remote-pc/`](remote-pc/README.md) | PS 端本地 [`ps-local/`](ps-local/README.md) |
|---|---|---|
| 运行位置 | 通信电脑（x86_64） | 板卡 PS（ARM Linux），HDMI 输出 |
| 输入 | 鼠标 + 键盘 | USB HOST 鼠标 / 触摸屏，或板载按键 |
| 职责 | 全量配置、四传感器看板、频谱、故障 / 分级 / 剩余寿命、故障波形存储与回放、报表导出、加密 | 单屏看板 + 告警 + 本地存储 + 基础参数配置 |

两端共用四传感器波形与诊断组件；ps-local 读取真实驱动数据，remote-pc 接收网络样本。温度、电流、振动、转速可用性由实际数据更新判定。

## 3. 显示（一屏）

以「一屏显示全部量」为约束，划分为状态栏、四个传感器小窗、诊断区、指标栏：

```
┌───────────────────────────────────────────────────────────┐
│ 链路: 以太网/4G/串口 · 延迟 · 丢包 · 采样率        (状态栏) │
├───────────────┬───────────────┬───────────────┬───────────┤
│ 温度 ℃        │ 电流 A        │ 振动 g        │ 转速 rpm  │
│ 数值 + 时域   │ 数值 + 时域   │ 数值 + 时域   │ 数值 + 脉冲│
│ [时域/频谱]   │ [时域/频谱]   │ [时域/频谱]   │           │
├───────────────┴───────────────┴───────────────┴───────────┤
│ 诊断: 正常/轻微/重度 · 分级 · 置信度 · 剩余寿命 · 告警     │
├───────────────────────────────────────────────────────────┤
│ 采集延迟 · AI 耗时 · 已存故障数 · SD 余量 · 运行时长       │
└───────────────────────────────────────────────────────────┘
```

- 每个小窗：名称、单位、当前值、均值 / 峰峰值、时域曲线；振动窗可切频谱。
- 转速经板载 RS485，由 PL 侧软 UART（+ DE 方向控制）接收，PS 读回，见 [`../docs/PL-PS接口约定.md`](../docs/PL-PS接口约定.md) §8 / §9。
- 颜色、单位、量程来自参数配置；告警时对应小窗与告警项同时变色。

## 4. 数据链路

| 链路 | 用途 | 说明 |
|---|---|---|
| 以太网（PS eth1） | 主链路：实时数据流 + 控制 | 首选 |
| 4G | 远程 / 冗余 | 断网时本地缓存，恢复后补传 |
| UART（UART&JTAG 二合一 Type-C） | 无网时串口接入 | CH342K，主机侧 `/dev/ttyACM*` |
| JTAG | PL 配置 / 调试，非数据面 | 不承载上位机数据 |

- 协议与帧格式见 [`../docs/上位机-PS接口约定.md`](../docs/上位机-PS接口约定.md)。
- 加密：传输与应用层加密、本地采集 / 标签存储使用 AES-256-GCM，记录口令通过 PBKDF2 派生密钥。
- 延迟：帧内时间戳 + 主机接收时间，计算并显示端到端延迟；丢包按序号统计。

### 4.1 模拟注入与双端交互

采集与训练分离：训练数据来自其他电机（让电机自然损坏需数年），线上 NPU 只做推理。为在比赛中稳定演示且避免损坏电机，PC 端提供「模拟注入」：

1. 点「模拟注入」，填温度 / 电流 / 振动 / 转速与时长，「上传」；
2. PC 以 `type=2` 帧发往 PS 目标地址；
3. PS 暂停采集、以注入值送 NPU 推理，结果以 `type=1` 回传；
4. PC 显示诊断工单；时长到点后 PS 恢复采集。

注入是临时路径切换，注入期间丢弃的采集数据不补传。协议见 [`../docs/上位机-PS接口约定.md`](../docs/上位机-PS接口约定.md) §3.2；NPU 输入见 [`../docs/NPU-AI接口约定.md`](../docs/NPU-AI接口约定.md) §3.2。

## 5. 存储与回放

两端「记录」按配置时长分段，保留温度、电流、转速、振动 XYZ 的全部接收样本与原生节奏，始终加密保存为 MLKC。「回放」打开独立二级窗口，支持异常 / 全部记录 / 故障清单、四类传感器共用时间轴、播放定位、数据表与 CSV 导出，不更改实时看板。

异常由模型事件或人工标签定义，MLKL 标签库加密保存区间、分类名称、来源与说明。工单按时间关联本机采集记录；无关联数据时明确显示不可用。命令行工具支持解密为 `[温度,电流,转速,振动X,振动Y,振动Z,振动合成]` 的等间隔 CSV，另含时间与有效位；原生 CSV 保留所有样本和原始码。格式、API、命令与验收步骤见 [采集记录、回放与训练接口](../docs/采集记录-回放与训练接口.md)。

## 6. 参数配置

PC 端全量；PS 端本地按键 / 触摸配置常用项。

| 组 | 参数 |
|---|---|
| 采集 | 通道使能、采样率、量程与标定 `k/b`、触发方式 |
| 告警 | 每传感器上下限、变化率阈值 |
| 诊断 | 故障分级阈值、置信度门限、剩余寿命参数 |
| 分析 | 时域 / 频域切换、FFT 点数与窗函数 |
| 存储 | 是否存故障波形、保留策略、SD 余量告警 |
| 网络 | IP / 端口 / 协议 / 4G APN / 上报目标 |
| NPU | 模型选择、批大小、推理频率 |
| 安全 | 加密开关、密钥 / 证书 |

PC 端已实现配置对话框（`remote-pc/src/settingsdialog.*`），QSettings 持久化：通道 k/b 与告警限、FFT 点数、监听地址 / 端口、故障波形目录、加密开关与口令。

## 7. 交互

- **PC 端**：鼠标 + 键盘，完整配置与操作。
- **PS 端本地（预选）**：HDMI 只有输出、无触摸。
  1. **2.5G USB 无线鼠标接收器（预选）**：2.4G USB HID 接收器，内核 `usbhid` 通用驱动即插即用；接 USB HOST 口，USB 跳线在 HOST 侧时同一分支仍提供 WiFi + 4G，鼠标与 4G 不冲突，见 [`../docs/接口冲突与可用性分析.md`](../docs/接口冲突与可用性分析.md) §1.2。Qt 以 `linuxfb` 运行，鼠标经 evdev 输入。
  2. **板载剩余按键 KEY1 / KEY2**：用于 HDMI 界面组件的选择与上下移动（翻页 / 确认 / 返回）；引脚在 PL 侧固定，与 PL eth0 的 MDIO/MDC 复用，本方案走 PS eth1 故不受影响，见同上 §2.1。
  - HDMI 触摸屏需带 USB 触摸控制器，走 USB HOST；鼠标不可用时以按键为后备。全量配置在 PC 端。
  - 详见 [`ps-local/README.md`](ps-local/README.md)「交互（预选方案）」。

## 8. 创新项落点

- 频谱分析：PL 硬件 FFT，上位机显示（拓展 1 高级）。
- 低延迟：环形缓冲、抽点显示、批量刷新；显示端到端延迟。
- 美观：深色主题、统一网格与配色、一屏自适应；触摸点按区域符合触摸尺寸。
- 双端交互：PC 模拟注入 → PS/NPU 推理 → 诊断工单回传（见 §4.1）。

## 无线接入与双端协同

remote-pc 使用与 ps-local 一致的主题、传感器、模型面板与系统资源侧栏；资源数据来自板端。ps-local 独有 WiFi 搜索 / 连接入口及虚拟键盘，PC 左上「展开」右侧显示由有效回包确认的连接状态。

共享标定 / 告警参数由板端统一保存，板端设置可选择 ps-local 或 remote-pc 优先，默认 ps-local。ps-local 优先时远端写入被拒绝；remote-pc 优先时板端本地修改可用，PC 连接后以其保存的共享快照覆盖板端。写入检查加密连接与控制权，不要求版本一致。共享参数与链路 / 密钥 / 本地存储独立。两端配置密码、记录口令、目录、显示和网络设置独立。故障时间以事件 API 的 UTC epoch 微秒为准，板端工单先保存再发送，PC 落盘后确认。完整字段、构建与验收见 [无线联网与双端协同](../docs/无线联网与双端协同.md)。
